# agent 专属可执行性判据正文（A/B/C 三组 15 项）

> **载体身份**：本文件是 A/B/C 三组 15 项 agent 判据的**唯一正文载体**（spec §7 交付物 2，依据 `docs/superpowers/specs/2026-10-20-execution-assurance-matrix-design.md` R5 逐字转写，名称/判定对象/判定方式不得另行改写）。
> **单源约束**：判据正文只在本文件定义一次；`skills/rule-inspector/references/criteria.md` 与 `rules/skill-authoring-convention.md` 只加归桶索引指针，不复制判据。模式表正反例（spec R6）属 `tools/execution-matrix/pattern-table.md`，**不写进本文件**。

## 0 适用范围与总则

### 0.1 检查范围（spec R2）

A/B/C 组判据**只查卡文本**（渲染后的 `agents/*.md`），**不查运行时产出**。运行时验证归属：议会评审产出 → parliament（侦探行为核对 + 审计证据核对）；改动验证 → review-loop（复查轮独立重审）。判据越界查运行时 = 与既有体系重复 = 不合格（对应 TC-028）。

### 0.2 模板形态适配（spec R5）

A 组判定词须兼容两种模板形态（parliament 模板与 senior-sdet handwritten 模板）：判定词按「存在性 + 语义」书写，**不按「逐字模板句」**。如 A3 判「有固定清单表格且每条有『必答/必问』列头」，A4 判「含『缺答/只答固定清单 = 不合格』任一字样」——不因第二模板无「回答」列或无特定字样而整卡误判红（对应 TC-050）。

**`explorePolicy: none` 形态适配（S1 新增）**：卡数据声明 `explorePolicy: none` 时，渲染出的「自由探索」节是「本节不适用…」句。此时 **B4（自由探索触发）按形态适配判 `pass`**，`C2`（自由探索逐条自证）同款——理由：该形态已显式声明不提问（只读取证角色不产出问题），要求它「必须有自由探索问题」等于逼卡自相矛盾。通用纪律里「只提问题不给解法 = 无效产出」同样按形态适配：该形态不产出问题，故不适用。**判 fail 的唯一情形是卡内仍出现「现场生成 3-5 个问题」类要求**（那说明槽位没接线，与 `explorePolicy: none` 声明冲突）。

### 0.3 AI 判的落位与三态（spec R8）

AI 判项（A 语义项 A1/A2 + B 组 4 项 + C 组全 4 项）判定结果写入 `rules/.inspector-annotations.json`（与 rule-inspector 共用同一文件），**键命名 = `agent 卡名:判定项名`**（如 `reviewer-audit:B2`、`reviewer-audit:C4`），值 = 三态：

| 值 | 语义 |
|---|---|
| `pass` | 判过且合格 |
| `fail: <理由>` | 判过且不合格（理由必填） |
| `pending` | 未判 |

**禁止压成布尔**：布尔会把「判 0 不合格」与「未判过」混为一个 `false`，脚本机械接收后静默放行、下轮不重判 = 自证偏差回绕。脚本只机械接收 annotations 值（透传，不重判语义）；`pending` 必须出现在「未判清单」而非「已判清单」，机械接收遇 `pending` 或 `fail:*` 即报红（对应 TC-022）。**非字符串值（布尔 / 数字 / null）= 无效判定 = 报红**（记 `InvalidAnnotation`，不许静默放行）；大小写不敏感（`FAIL: x` 同样判红）。B 组 4 项 + C 组 4 项与 A 语义项同样由脚本机械接收（键命名同为 `agent 卡名:判定项名`），十键一视同仁。

### 0.4 级联口径（对应 TC-049）

**A 组失败 → 卡不合格，C 组不空转打分**。A 组任一结构项（A3-A7）判红、或 A 语义项（A1/A2）判 `fail`，即整卡不合格、直接拦截；C 组不得对无自证对象的卡判「通过」（如 A3 失败导致无固定清单时，C1 若按「无对象 = 通过」即变相豁免，违规）。C 组只对 A 组通过的卡打分；缺此口径 = 判据不完整（打回补定义）。

### 0.5 A 组结构项的统一口径：节内优先、整卡兜底

A 组结构项（A3-A7）中**凡有「目标节」的按字样查的项（A4/A5）**，一律按「**节内优先、整卡兜底**」判定：先在**目标节内**匹配判定词，**未命中再退回全卡搜索**；命中位置（节内 / 节外兜底）记进检查 notes。判定语义与落位实现见 `tools/execution-matrix/check-agent.mjs` 的 `checkStruct`，两者必须一致。

**为什么不是严格限节内**：整卡兜底是**防误伤**的必要设计，不是精度妥协。两份模板的字样落位并不一致——`agents/senior-sdet.md` 的闭环字样「只答固定清单 = 不合格」写在 `## 自由探索（必做）` 节内（不在 `## 测试设计固定清单` 节内），若 A4 严格限节内会把这份合规卡判红 = **判据误伤**（误伤比漂移更严重：漂移只是口径说不清，误伤直接把正确卡拦下）。

**为什么不是直接查全卡**：节内优先收紧精度——字样出现在目标节内与节外兜底分别记不同 note，判定过程可追溯、不含糊。

**其余 A 组结构项的口径（不适用本条）**：

- **A3**：判定对象是「卡内任一表格的必答/必问列头」，**没有唯一目标节**（一份卡可能有多个清单表），故直接全卡扫表格，不存在节内/整卡之分。
- **A6/A7**：判的是节**存在性**（「有 `## 边界` 节」「有 `## 输出格式` 块」），不涉及字样落位，不适用本口径。

## 1 A 组：结构项（机器查，可 grep）——落位 `check-agent.mjs`

| 判定方式 | **机器查（可 grep）**：判定 = 卡内任一表格的表头行含「必答」或「必问」列头（兼容两种模板形态，按「存在性 + 语义」判，不按逐字模板句、不按节名匹配） |

## 2 A 组：语义项（AI 判 + annotations 三态）——落位 `rules/.inspector-annotations.json`

### A1 职责单一定位

| 要素 | 内容 |
|---|---|
| 名称 | A1 职责单一定位 |
| 判定对象 | identity（「你是谁」声明段） |
| 判定方式 | **AI 判（语义判断，机器无法兑现）**：判定 = 单一职责（非多主体）——「你是谁」只定位一个可执行主体；同时兼任两个互不相关职责（如「审计专员 + 前端开发」）→ `fail`。职责内容是否真实归 B1 |
| 落位 | annotations（键 `agent 卡名:A1`） |

### A2 触发信号可判

| 要素 | 内容 |
|---|---|
| 名称 | A2 触发信号可判 |
| 判定对象 | frontmatter description 的 when（触发信号） |
| 判定方式 | **AI 判（语义判断）**：判定 = 含具体触发条件枚举（非「需要时/酌情」类不可判信号）；description 只写触发条件、不写流程摘要（禁「本角色将先…再…」类流程描述）。触发信号不可判则卡「什么时候被调用」无法确定，等于无触发机制 |
| 落位 | annotations（键 `agent 卡名:A2`） |

## 3 B 组：内容 4 项（AI 判 + annotations 三态）——落位 `rules/.inspector-annotations.json`

### B1 identity 真实

| 要素 | 内容 |
|---|---|
| 名称 | B1 identity 真实 |
| 判定对象 | identity 段 vs frontmatter tools 与仓库实际角色 |
| 判定方式 | **AI 判**：判定 = 「你是谁」/能力段声明的能力有对应载体（tools/职责）；声明实际不具备的能力/权限（如声称可写任意文件而 tools 只有 Read/Glob/Grep）→ `fail` |
| 落位 | annotations（键 `agent 卡名:B1`） |

### B2 fixedList 判据可判

| 要素 | 内容 |
|---|---|
| 名称 | B2 fixedList 判据可判 |
| 判定对象 | 固定必问清单每条条目 |
| 判定方式 | **AI 判**：判定 = 每条有可判依据（机器可判命令 / 枚举值 / 可核对对象）；「你怎么看 / 觉得 / 合理吗 / 酌情」类开放问无判据 → `fail`（回答无法被判对错 = 把验收交给被验者自评，自证偏差源头） |
| 落位 | annotations（键 `agent 卡名:B2`） |

### B3 职责边界一致

| 要素 | 内容 |
|---|---|
| 名称 | B3 职责边界一致 |
| 判定对象 | 职责段 vs 边界段（跨段比对） |
| 判定方式 | **AI 判**：判定 = 任一职责动作被边界禁止、或边界允许了职责未授权动作 → `fail`（两段分开看都对、合起来冲突 = 卡自相矛盾） |
| 落位 | annotations（键 `agent 卡名:B3`） |

### B4 自由探索触发

| 要素 | 内容 |
|---|---|
| 名称 | B4 自由探索触发 |
| 判定对象 | 卡内「自由探索（必做）」段 |
| 判定方式 | **AI 判**：判定 = 卡含「自由探索 / 必做 / 额外问题」类段；无自由探索要求 → `fail`（只答固定清单 = 盲点扫描退化为填空） |
| 落位 | annotations（键 `agent 卡名:B4`） |

## 4 C 组：贯穿自证 4 项（AI 判 + annotations 三态）——落位 `rules/.inspector-annotations.json`

> 「自证」定义（对齐 TC-023/024/025/026）：给结论的环节都要有「独立回答 + 证据」，不是开头问一下。C 组判定基于卡文本结构（是否有逐条回答位与证据位），**不查运行时证据内容是否真实**（那归 parliament 侦探/审计核对）。

### C1 固定清单逐条自证

| 要素 | 内容 |
|---|---|
| 名称 | C1 固定清单逐条自证 |
| 判定对象 | 固定清单每条的回答（产出节） |
| 判定方式 | **AI 判**：判定 = 固定清单每条有「独立回答 + 证据」；任一清单条整体打包（「清单见上，均已核对」类）无逐条证据 → `fail` |
| 落位 | annotations（键 `agent 卡名:C1`） |

### C2 自由探索逐条自证

| 要素 | 内容 |
|---|---|
| 名称 | C2 自由探索逐条自证 |
| 判定对象 | 自由探索段的问题与回答 |
| 判定方式 | **AI 判**：判定 = 自由探索问题数 = 回答数且有证据；只列问题不逐条回答、或回答无证据 → `fail`（自由探索空转） |
| 落位 | annotations（键 `agent 卡名:C2`） |

### C3 结论可复算

| 要素 | 内容 |
|---|---|
| 名称 | C3 结论可复算 |
| 判定对象 | 卡内每个带数据/断言的结论 |
| 判定方式 | **AI 判**：判定 = 结论带取数命令或文件:行号（可复算来源）；「已确认 / 已核实」类措辞无来源 → `fail`（复核者无法重跑验证 = 等于没结论） |
| 落位 | annotations（键 `agent 卡名:C3`） |

### C4 自证贯穿不只在开头

| 要素 | 内容 |
|---|---|
| 名称 | C4 自证贯穿不只在开头 |
| 判定对象 | 全部产出节（核对项表 / 结论段等） |
| 判定方式 | **AI 判**：判定 = 产出节每行有证据位；仅开头总声明（如「本卡所有结论均附证据」）而产出节无任何证据 → `fail`（自证只在声明层 = spec R5 中心主旨落空） |
| 落位 | annotations（键 `agent 卡名:C4`） |

## 5 判据一览

- **A 组 7 项**：A3 必答清单存在（机器查）/ A4 必答闭环（机器查）/ A5 证据约束（机器查）/ A6 边界声明（机器查）/ A7 输出格式指定（机器查） + A1 职责单一定位（AI 判）/ A2 触发信号可判（AI 判）
- **B 组 4 项**（AI 判）：B1 identity 真实 / B2 fixedList 判据可判 / B3 职责边界一致 / B4 自由探索触发
- **C 组 4 项**（AI 判）：C1 固定清单逐条自证 / C2 自由探索逐条自证 / C3 结论可复算 / C4 自证贯穿不只在开头

> 落位汇总：A 结构项（A3-A7）→ `tools/execution-matrix/check-agent.mjs` 机器查；A 语义项（A1/A2）+ B 组 + C 组 → AI 判落 `rules/.inspector-annotations.json` 三态，脚本只机械接收。与 docgen `validateAgentData` 的判定对象（name/tools/when 格式/route/outputKind 等数据合法性）无交集（对应 TC-047）。
