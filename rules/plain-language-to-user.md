# 给用户看的解释一律用大白话，并把机理讲透

> 来源：用户当场指令（2026-09-28）｜证据：用户对「junction 方案评审」回复的原话——「你说的话，就像天书一样，说的简单易懂一点」「说话要用大白话说，不要简化，说清楚，不要说的我云里雾里」｜落地：2026-09-28

给用户（人）看的任何解释、评审结论、方案说明、报告，必须满足四条：

1. **不用行话、不用内部编号**：不出现 P0/P1、手法 N、Step 0–5、Ruling(P-x)、单源、幂等 这类只有长时间跟这个项目的人才懂的标记。确需引用时，先用一句人话说明它指的是什么。
2. **不省机理**：不能只给结论。要写清「为什么会这样」「它怎么运作」，让不懂背景的人也能自己判断对不对。
3. **必须落到例子**：抽象说法的后面跟一个具体场景——谁、在什么时候、做了什么、会发生什么。
4. **一句话一件事**：长句拆短，少用嵌套从句，少用破折号串三层。

**反例（本次真实触发）**：「盲点（P1）｜体检脚本缺触发点——违反我们自己的规矩：检查项必须有可观测触发信号」。读者看不懂 P1 是什么，也没说明为什么「没有触发点」就等于没用。
**正例**：「脚本得有人会想起来跑它。如果只能靠你记得，那它跟没有一样——这正是我们之前批评过的毛病。」
