# 在写前端代码 import 时，路径必须按归属使用相对路径或 @/ 别名

> 来源：项目约定（2026-10-10）｜落地：2026-10-15

## 核心判据

在配置了 `@/` 别名的前端项目里写 import 时，路径写法必须按目标资源与当前文件的归属关系选择：

- 同目录 / 邻近目录（相对路径 ≤2 层 `../`）→ 用相对路径，如 `./sc`、`../mock/...`
- 跨 3 层及以上的相对路径 → 一律用 `@/` 别名，如 `@/components/Card`
- 项目级公共资源（公共组件 / 工具 / 模型）→ 用 `@/`，如 `@/components/Card`、`@/utils/...`
- 业务模块内部资源（types、mock、邻近 components）→ 用相对路径，如 `../../types`、`../mock/...`

## 为什么

1-2 层相对路径能体现「这是当前业务模块内的资源」，可读性好；4 层以上长路径脆弱、易数错、文件移动即崩。

## 验证

编辑后调用 `GetDiagnostics` 自查，确认无 `Cannot find module` 错误。

## 触发时机

写 / 改前端业务代码里的 import 语句时。

## 例外

未配置 `@/` 别名的项目不适用本规则。
