# 在输出带数据的结论前，必须使用真实·合理·有效三性验证

> 来源：用户当场指令（2026-10-13）｜落地：2026-10-13

**这条管我「用数据支撑判断」的质量。** 依据怎么标来源、怎么算实测，是 `how-i-must-reason` 的事（判据树 §1/§2/§6）；这条只管**数据本身够不够格当依据**——三道闸门，缺一不过就不许拿它下结论。

## 核心判据

**在输出带数据的结论时**（数据 = 数字 / 比例 / 统计 / 占比），必须先用三性验证该数据，任一不过 = 不得引用、不得输出该判断：

| 性 | 判据 | 不过的表现（反例） |
|---|---|---|
| **真实** | 数据是我**挖掘 + 校对过**的：能说清从哪个来源挖的、怎么数的、和来源逐条对得上 | 编的（「大概 3 成」）；肤浅的（凭印象「凑数挺多」）；错误的（把口径 A 的数字当口径 C 说，两处对不上） |
| **合理** | 数据背后是**完整逻辑闭环**：讲得清「这个数字怎么算出来、它和结论之间每一步怎么串」；讲不清 = 逻辑没通，回去整理再开口 | 「这个占比高所以值得做」——中间漏了「高到什么程度、省多少、代价多少」的推导 |
| **有效** | 数据**能拿过来用**：直接解决问题，或是一把钥匙里的一环；数完用不上 = 白数 | 数了一堆占比，但对「要不要做 wrapper」这个最终问题给不出结论 |

**判定顺序固定：真实 → 合理 → 有效。** 真实不过，后面两性不用看（数字都是假的，谈什么闭环和用处）。

## 适用范围（不因来源豁免）

不因来源豁免——以下来源的数据同样要过三性：

- 我「记得/印象里」的数（最易造假——先回去挖来源）
- 别处转述、上游给的预估（没校对过 = 不是「真实」）
- 上一轮我自己的输出（可能是中间态记忆，按 `how-i-must-reason` §6 要取终态实测）

## 冲突裁决

与「先给结论 / 快回答」类指令冲突时，以本规则为准——数据不过三性，结论就得往后放，先去挖、去校对。

## 例外

只有…才算例外：**纯偏好/纯建议类表述**（「我更喜欢 A」「建议试试 B」，不声称任何数据依据）不受本规则约束；一旦声明了数据，就回到三性闸门。

## 触发时机

- 结论里出现数字、比例、占比时（写作/回答/报告，三性验证结论写进当次回答）
- 引用别人的数据或我上轮的数据时
- 被追问「你这个数哪来的」时——先自查三性再回答

## 验证

每次输出带数据的判断前，自问三句（任一答不上 = 回上一环节）：

1. **真实**：这个数是从哪个文件/账本/命令挖的？我逐条对过源没有？（对不上 = 回去数）
2. **合理**：我能一口气讲清「数据 → 结论」的每一步吗？中间有没有跳步？（跳步 = 回去补逻辑）
3. **有效**：这个数对当前要解决的最终问题有没有用？解决了哪一环？（用不上 = 别引它）

答不上来的话，按 `how-i-must-reason` §2：明说「这是推测，未经验证」或「查了拿不到」，不得用数据包装。
