# 可测 agent 建模方法论（草稿）

> 状态：草案。未来抽为 skill。
> 来源：`tmp/agent-criteria-demo` 讨论（2026-11-10）
> 适用：agent 角色卡的识别、创建、优化
> 不适用：代码实现、skill 内部流程设计

## 0 它解决什么

一句文案读得懂，但执行时还要再翻译一次——这是 agent 卡最大的隐性成本。本方法论把「读得懂」推到「不用翻译就能执行」。

**核心不变式**

> 一句话要进卡面，必须能落到「文件 + 行 + 字段 + 状态」；落不到的，补定义、标展示、或不许写。

**十一条从属原则**

1. 能推导的不存（`coverage` 由字段推导，不手写）
2. 能引用不复写（落点引 artifact ID，不写路径）
3. 能命令判的不靠人读（可机判的必须配 `machineCmd`）
4. **描述派生，不手写**（判据摘要、权限段、覆盖结论都由配置生成）
5. **自证不算判据**（由本席填的布尔 = 没判；必须换外部事实）
6. **权限只一处**（`action` / `write` / `command` 三维收敛，不再分散到 constraint、bans、groups）
7. **标题不得强于判据**（给人读的名称——`category` / `ok` / `bad` / `label`——其断言必须能在 `observable` 里找到对应 op；找不到就改标题、补 op、或标 residual）
8. **路径必须模板化**（占位符统一 `{name}` 并登记在 `placeholders`，不写裸 `<...>`；`source` 分「路径」与「描述」两类，不混）
9. **同一语义用同一结构**（"何时 / 谁 / 对什么 / 做什么"这组要素在触发、职责、判据里反复出现，就抽成共享字段 + 一个填充器；出现第二处相似句子不是写新模板的理由）
10. **字段按类型定校验**（字面量、定位、展示、断言、派生、命名六类各有各的判法；不按"看起来像什么"挑，按类型查表）
11. **术语不硬拆**（"交接取证""事实基线回核"是固定术语，拆开会改词义；但必须登记进词表，与要素型共用"已登记值"这条约束）
12. **状态词必须闭集且有定义，执行主体必须具名**（「半机判」没有判定条件，「机判」没有主语。判定方写 `本席` / 命令原文 / `抽检：{who}`，不写抽象类别；覆盖完整性由 `residual` 表达）

**字段类型与校验矩阵**

| 类型 | 典型字段 | 判据 | 失败码 |
|---|---|---|---|
| 枚举引用 | `perspective` / `action` / `objectKind` / `schedule` | 必须在共享词表 | `TriggerUnknown` |
| 字面量 | `forms[].text` | 有 `prefix` / `match` / `path` 之一 | — |
| 定位模板 | `forms[].path` | 占位符已登记、非绝对、无 `..` | `PathAbsolute` / `PathEscape` |
| 定位描述 | `records[].source.text` | 标 `kind: description`，不参与判定 | `SourceUnstructured` |
| 展示文本 | `escalation.steps[].text` | 由 `kind` 决定，不参与判定 | — |
| 断言 | `predicates.ok` / `category` / `permissionGroups.label` | 断言词必须有对应 op | `TitleDrift` |
| 派生文本 | `checkCriteria.summary` / `outputFormat.checks[].text` | 禁止手写 | `SummaryHandwritten` / `OutputTextHandwritten` |
| 命名 | `records[].label` / `templates[].label` | 唯一即可，不校验语义 | — |

判定顺序：① 会被 op 读吗？会 → 必须封闭取值；② 是断言还是命名？断言 → `TitleDrift`；③ 是字面量还是描述？描述 → 标 `kind`。

**检查清单应覆盖字段类型，不是靠肉眼挑**。本轮就漏过 `outputFormat.checks[].text`——它和已删的 `summary` 同类，只因为没在清单里，多活了一轮。

## 1 七阶流程

| 阶 | 做什么 | 输入 | 动作问句 | 输出 | 门 |
|---|---|---|---|---|---|
| P0 归位 | 判断这段属于哪个维 | 一句话 | 它属于身份/结构/时机/语义/判据/规则/命令/写入/产物/决策/异常/关系/输入哪一个？ | 维度标签 | 归不进任何维 → 它不属于 agent，下沉 skill |
| P1 拆解 | 递归找断点 | 一段文案 | 按句 → 子句 → 要素 → 叶子拆，拆不动即停 | 缺口四元组 | 无断点 |
| P2 定义 | 抽象谓词展开 | 敷衍/合理/充分… | 属加种差是什么？能否判断任意行为？ | 词义定义 + 属性 | 给不出定义 → 交人，不许自造 |
| P3 判据化 | 属性落成产物断言 | 属性 | 哪个文件、哪一栏、哪一行、什么状态？ | `observable[]` + `verify` | 落不到字段 → 回 P2 |
| P4 重写 | 用要素重述文案 | 判据 | 谁 / 何时 / 对什么 / 按什么判 / 写哪 | 新文案 | 新文案能反推回同一判据 |
| P5 验证 | 三条硬验 | 新文案 + 判据 | 负例必失败？渲染字节不变？命令可判出？ | 三项证据 | 任一不过 → 回 P3 |
| P6 收口 | 模型定稿，文案由引擎出 | 模型 | 卡面还有没有手写逻辑？ | 零翻译产物 | 有手写逻辑 → 未收口 |

## 2 P1：递归拆解

```
build(node, depth = 0):
  if isClosedLeaf(node):      return Closed        # 枚举 / 数字 / 已登记 ID / 正则
  if isDisplayLeaf(node):     return Display       # 不被任何 op 读取
  if depth > MAX_DEPTH:       return Fail TooDeep

  parts = split(node)
  if parts.length == 1:                            # 拆得动与否是可判的
      if isAbstractPredicate(node): return NeedDef
      return NeedTranslate

  return all(build(p, depth + 1))
```

**拆分算子**

| 层 | 按什么拆 | 拆不动的信号 |
|---|---|---|
| 段 | 句号、分号 | 整段一句，且含多个动词 |
| 句 | 并 / 且 / 同时 / 时 / 则 / 若 / 除非 | 有连词，拆完两边都不完整 |
| 子句 | 主谓宾抽取 | 找不到主语或谓语 |
| 要素 | 动词→`action`；名词→`record`；条件→`Expr`；数量→`value`；落点→`ref` | 动词无登记、名词无契约 |
| 叶子 | 枚举 / 数字 / ID / 正则 | 仍是自由字符串 |

**四态终止**

| 态 | 含义 | 处置 |
|---|---|---|
| `Closed` | 取值封闭 | 通过 |
| `Display` | 不被逻辑读取 | 允许，标 `display` |
| `NeedDef` | 抽象谓词 | 进 P2 |
| `NeedTranslate` | 拆不动、被读取、无定义可展开 | **文案本身不合格**，回 P4 重写 |

`NeedTranslate` 是重点：它不是模型不够，是句子没说清。

**断点分四型**

| 型 | 症状 | 处置 |
|---|---|---|
| A 复合句 | 一句两事，拆开两边都不完整 | 拆句 |
| B 指代不明 | 两个主语，不知说谁 | 先绑主语 |
| C 谓语缺定义 | 动词读得懂，写不出判法 | 去代码/文档找定义所在行 |
| D 真冲突 | 两句各自成立，放一起矛盾 | 不拆，交人 |

**输出格式（缺口四元组）**

```
{ path, code, missing, fixTarget }
```

`code` 闭集：`Expr` / `Ref` / `Enum` / `FieldId` / `Negation` / `Display` / `Migration`。详见 `result.md` §8.15。

## 3 P2：定义展开

抽象谓词（敷衍、合理、充分、及时、有效、清晰）不可直接建模，但**可以被定义**。

**定义式：属加种差**

```
term        = 敷衍
genus       = 形式上完成动作
differentia = 实质上未完成该动作要求的工作
```

**自检一问**

> 任给一个行为，我能不能只凭定义判断它是不是敷衍？

能 → 定义可用；不能 → 定义还缺东西，继续找，不要退回枚举。

**定义来源**

规范或说话人。AI 不得自造定义——自造会把猜测固化成判据。

**枚举与定义的分工**

- 定义是判据
- 枚举是测试用例，用来验证定义是否正确

新增行为不需要改模型，只要它落在定义内。

## 4 P3：判据化

**三层必须分开**

| 层 | 内容 | 能否判定 | 存哪 |
|---|---|---|---|
| 词义 | 表面完成、实质未完成 | 不能 | 文档 |
| 判据定义 | 满足什么 = 合格 | 能，逐条 | `checkCriteria` |
| 产物断言 | 哪个文件、哪一栏、哪一行、什么状态 | 能，跑命令 | `observable[]` + `verify` |

只在第一层给 `observable` 是假判据——它缺了产物与字段。

**标题与判据对齐（原则 7 的判定方法）**

给人读的名称只有三种合法关系：

| 关系 | 例子 | 合规 |
|---|---|---|
| 标题 = 判据的概括 | `ok="建议解法栏非空"` + `fieldEmpty(suggestion)` | 是 |
| 标题弱于判据 | `ok="证据栏完整"` + 三项都查 | 是 |
| 标题强于判据 | `ok="可复算"` + 只查 `fieldNonEmpty` | **否** |

判定：把标题里的断言词列出来，逐个问「`observable` 里有哪个 op 支撑它」。找不到就报 `TitleDrift`，三选一修——改标题、补 op、标 residual。

**必要条件与充要条件**

- 能机判的，写成判据
- 判不了的，写进 `residual{who, sample, fields, objective}`

把必要条件冒充充要条件，是比“不建”更坏的错——它会让读者以为已经管住了。

**自检一问**

> 给我一份产物，我能不能只跑命令判出这条？

能 → 是判据；不能 → 还在理解层。

## 5 P4：重写

**要素模板**

```
{编号}｜{时机}：对{对象}，要求{判据}——{可观测}，写回{落点}。
```

**必须删掉的三种修辞**

| 类型 | 例 | 为什么不能建 |
|---|---|---|
| 对仗 | 只提问题不给解法 | 用对偶替代规格，主谓宾不成立 |
| 口号 | 零容忍、一律、坚决 | 强度词，无观测面 |
| 俗语 | 拍脑袋、走过场 | 比喻，无对象 |

**一句话只装一件事**

一句话装两个要求、且两条可测性不同时，必须拆开——否则弱判据会掩护强要求。

## 6 P5：验证

| 验 | 方法 | 失败含义 |
|---|---|---|
| 负例必失败 | 给一条应违规的输入，判据必须判 fail | 判据没落地 |
| 渲染字节不变 | 改模型前后渲染产物 `deepStrictEqual` | 改的不是数据形态，是文案 |
| 命令可判 | `machineCmd` 命中白名单且能出结果 | 仍是人工判 |

三条全过才算改完。

## 7 P6：收口

**两个方向**

| 方向 | 顺序 | 适用 |
|---|---|---|
| 优化存量 | 文案 → 拆解 → 缺口 → 补模型 → 重写 | 现有卡 |
| 创建增量 | 先定 `records` + `checkCriteria` → 引擎渲染 | 新卡 |

创建时不写正文，只写数据——这是零翻译的落地形态。

**执行侧自检**

> 我是这个 agent，读到这里，下一步跑什么命令、看哪个文件哪一行、填哪一栏，能不能直接说出来？

说不出来 = P4 未过。这条比格式检查更准，因为它模拟真实执行者。

## 8 完整样例：敷衍

**原句**

> 不得只提问题不给解法——问题卡「建议解法」栏为空；出现即违反。

**P1 拆解**

| 片段 | 结果 |
|---|---|
| 不得只提问题不给解法 | 对仗修辞 → `NeedTranslate` |
| 建议解法栏为空 | `Closed`（`fieldNonEmpty`） |

断点：句子装了两个要求（存在性 A、有效性 B），且 B 无观测。

**P2 定义**

| 项 | 内容 |
|---|---|
| term | 敷衍 |
| genus | 形式上完成了回复 |
| differentia | 实质上没有完成该回复要求的工作 |
| 展开 | 输出了结论，但结论与其依据链断开 |

**P3 判据化（产物断言）**

产物：问题卡「建议解法」栏。不是敷衍，当且仅当每行满足：

| # | 断言 | 怎么测 |
|---|---|---|
| 1 | 行非空 | `fieldNonEmpty` |
| 2 | 行内含 `path:line` | 正则 `\S+:\d+` |
| 3 | 锚的文件存在 | 文件系统 `exists` |
| 4 | 行号在文件行数内 | `lineExists` |
| 5 | 摘句是该行子串 | `quoteInLine` |

任一不过 = 敷衍。

**边界**

五条只证明「依据链存在且可核」，不证明「依据链支持结论」。后者落 residual：

```json
"residual": {
  "who": "reviewer-audit", "sample": 3,
  "fields": ["round-check.md#建议解法"],
  "objective": { "target": "manual", "reason": "REQUIRES_HUMAN_JUDGMENT" }
}
```

**P4 重写**

```markdown
- 1｜不得留空建议解法栏——问题卡「建议解法」栏为空（针对问题卡）；出现即违反。
- 2｜不得给无依据建议——建议解法栏每行缺 `path:line`（针对问题卡）；出现即违反。
```

一句话一个要求，各自可测。

## 9 六道质量门

1. 每个名词 → 有 `record`
2. 每个动词 → 有 `observable`
3. 每个条件 → 是 `Expr`，不是字符串
4. 每个枚举 → 闭集，且每个值有 label
5. 每条判据 → 有可执行负例
6. 每条判断 → 有 `objective`（`full` / `partial` + `reason` / `manual`）

门不可跳。

## 10 边界

| 情况 | 处置 |
|---|---|
| 展示文本（禁令文案、标题） | 允许自由文本，标 `display`，禁任何 op 读取 |
| 抽象谓词无定义 | 交人，不许自造，不许枚举冒充定义 |
| 只能给必要条件 | 写判据 + `residual`，不宣称已闭环 |
| 定义与现役代码不符 | 先对齐现役，再改；现役没做的事先假设有理由 |
| 一句话属于两个维度 | 说明它该拆，不是该归位两次 |
