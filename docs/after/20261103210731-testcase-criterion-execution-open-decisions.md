## 1 这条在说什么

写 testcase 时，判据里的**命令可能根本跑不起来**，而现有工序发现不了——因为没人要求编写者跑一次。

本轮实例（可复现）：

```powershell
# 议会 Q-T-01 指出的原写法
Select-String -Path tools\docgen\policy\*.mjs -Recurse -Pattern 'pathGroups'
# 实跑输出：找不到与参数名称“Recurse”匹配的参数。（Select-String 无 -Recurse，那是 Get-ChildItem 的）
```

两处错叠在一起：

| 错 | 后果 |
|---|---|
| 用了不存在的参数 `-Recurse` | 命令直接抛参数绑定异常，判据一行都执行不了 |
| 路径写 `policy\*.mjs`（真实定义在 `policy\definitions\*.mjs`） | 就算删掉 `-Recurse`，也只扫到 `seat-policy.mjs`，命中 **0** —— 看着跑通、其实什么都没查 |

同族在本次议会里还有 3 处，说明不是偶发：

| 卡 | 形态 | 后果 |
|---|---|---|
| `A-05` | 判据写成 `node -e …` | 执行门账的审计席角色卡明文禁 `node -e`，按卡无法执行 |
| `AI Q-5` / `A-04` | 把 `Select-String` / `git diff` 的计数当判据 | 这两条命令不设退出码，计数为任何值都 exit 0（恒真） |
| `Q-T-24`（收窄前） | 判定范围写「整段边界段」 | 与保留段的合法路径冲突，金态恒红 |

## 2 根因（三句话）

1. **写的人只「写」不「跑」**：testcase 由独立子代理编写，它按目录印象写出了形态正确的命令，未执行；参数是否存在、文件在第几层，只有跑一次才知道。
2. **要求里没有执行证据**：`spec-testcase-gate` 的五条判据只要求「判据可执行」这一句，没要求「附一次实跑输出」；于是「像命令」= 过关。
3. **自查只数不跑**：编写者与主持人的自检都数条数、正负比、空代码块，**没有一项是「这些命令能跑吗」**——与本次被抓的「计数判据恒真」是同一个病：能数出来就算过。

## 3 该做（三档，按工程化优先）

| 优先级 | 做什么 | 落在哪 |
|---|---|---|
| ① 最硬 | 判据最终落成 `node --test` 用例，由 `npm run check` 真跑；不靠谁记得去跑 | 已在本轮 S-B spec §11.4 落地（十条硬约束各指一个用例 ID），可作后续 spec 的样板 |
| ② 补工序 | testcase 里每条**命令式**判据，必须由编写者实跑一次并把输出首行 / 退出码贴进用例；确实没跑的，显式标「**未施行**」+ 理由。缺此项 = 该条判据不成立 | 待定：`rules/` 的 `spec-testcase-gate` 判据 3（用例合格）或 `agents/senior-sdet.md` 的必问清单 |
| ③ 兜底 | ③ 段计划门 / ④ 段质量评估时，由验收方把 testcase 的判据命令全跑一遍 | `skills/dev-workflow/references/stage-2b-plan-gate.md` 或 `stage-4-quality.md` |
