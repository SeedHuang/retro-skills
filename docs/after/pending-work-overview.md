**检查范围边界（防与运行时流程重叠）**

> 来源：2026-10-20 用户确认「补边界」。本套判据（A/B/C 组）**只查卡文本本身**——即渲染后的 `agents/*.md` 有没有声明/具备这些可执行性要素。**不查 agent 实际执行时有没有带证据**（那是运行时验证）。运行时验证的归属：议会评审产出的收敛协议归 `parliament`（侦探行为核对 + 审计证据核对）；改动验证归 `review-loop`（复查轮独立重审）。C 组若越界去查运行时 = 与它们重复——本边界是防重复的硬线。

**「谁验证」：职责分离（防自证偏差 + 防证据造假）**

> 来源：2026-10-20 用户担心「AI 回答会造假、如何判断证据不造假；理解是否与要求一致；是否需新 agent 检查、让检查的人和写的人分开」。结论（用户已确认方向）：**职责分离 + 检查动作可复算，两者都要**——分离增加可信，可复算是根基；单靠换 agent 不够（同模型同盲区），单靠可复算命令但检查者=写者也弱。

| 原则 | 内容 | 已有先例 |
|---|---|---|
| ①证据必须可重跑 | 证据落在可复算事实（命令输出/文件:行号/git hash），复核 = 真重跑，不是相信证据文本；「我检查过了」类描述不算证据 | 审计「机械计数项必须写取数命令+输出」、review-loop A3 真实场景实测 |
| ②检查者 ≠ 写者 | 运行时产出的证据由独立方复核，不交给产出的 AI 自评（自证偏差） | 议会侦探、审计专员、senior-sdet 独立写 testcase、review-loop 复查轮 |
| ③理解前置显式化 | 动手前先声明「我理解的 X」给用户确认，理解对了才动手——事后「推脱理解错了」无空间（理解是用户点头过的） | rule-writer 硬闸门 1（措辞定稿前须用户确认）、X3 前置显式化 |
| ④判据化而非凭感觉 | 语义判断（B 组/C4）写成文字判据，检查者照判据判，不凭感觉 | rule-inspector 判据全集（可复算 grep） |

**执行力度置信度评级（省成本但不豁免高风险）**

> 来源：2026-10-20 用户「每种方案都做完整验收成本大，能否走完评级就自动知道执行度置信程度，省掉一笔成本」。**半认同半反驳后的结论**（用户已确认方向）：
> - **反驳**：「评级替代完整验收」= 自证偏差绕回——评级不能豁免验收，只能**决定验收强度**。
> - **认同**：「评级决定验收强度」省成本——成本省在「已证明可靠的模式不用每次重头验」，不省在「低置信度跳过验」。

| 置信度评级 | 依据（可复算） | 验收强度 |
|---|---|---|
| **高** | 该模式在同类场景被实测 ≥N 次、零回归 | 简化验收（抽查 + 自检命令） |
| **中** | 有实测但次数/场景不全 | 标准验收（走完整流程） |
| **低** | 新模式 / 新场景 / 无实测记录 | **必须完整验收，不可豁免** |

**三条硬约束（否则评级退化）：**
1. **评级必须可复算**——基于「模式 × 场景」的实测记录数打分，不是 AI 拍脑袋
2. **评级低 → 强制完整验收**——成本省在高置信度，不省在低置信度
3. **高风险永不免验**——不可逆操作 / 跨体系改动 / 用户明确要求全验的，评级再高也全验

> **与模式表的关系**：模式表 = 评级的依据（记录「某模式在某场景实测过几次/是否回归」），评级 = 模式表的自动推导。无库则评级空谈，无评级则库是档案。spec 时需把「实测记录如何落」（复用 lessons/retro 还是新建登记）一并设计。
