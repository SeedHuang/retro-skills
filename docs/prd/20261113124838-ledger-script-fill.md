# 账本产物「脚本填充 + 行定位 + AI 判值」（PRD）

> 状态：v3.1 定稿（2026-11-13；三方终审一致后，经独立 testcase 对账修正两处口径：行键基准改为 checklist `no`、待判「空」定义为无判定值）
> 来源：本次会话讨论；实证见 §1。评审记录：`tmp/prd-review/round1-consolidated.md`

## 0 谁、什么场景、什么价值

| 项 | 内容 |
|---|---|
| 谁 | 产物责任席本人实例（如审计席填 `round-check`）与其复核席；读侧为任何需要读长账本的席 |
| 场景 | 每轮结束后填账本（写侧）；评审中按行核对账本（读侧） |
| 价值 | ① 格式与计数不再由 AI 手抄，错填可归零；② 长产物只读命中行，降低读取量与漏行；③ 机算格带命令与首行，结论可复算 |

## 1 背景：四个病

| # | 病 | 实证 | 后果 |
|---|---|---|---|
| 1 | **产物格式靠 AI 手抄** | 卡面「输出格式」列 18 项（`agents/reviewer-audit.md:48-70`），模板实际 8 列（`tools/docgen/models/agents/jsons/reviewer-audit/index.json` 的 `templates.columns`）；两者无校验器对齐 | 格式漂移不报错，产物与卡面声明各说各话 |
| 2 | **机械项靠 AI 心算** | `skills/parliament-ledger/assets/round-check.md:4` 自述「心算必错，实测数错 3 次被拦」；取数命令已有，但仍由 AI 决定何时跑、抄哪段 | 慢、易错、不可复算 |
| 3 | **已有机械能力闲置在产物层** | 110 条判据全带 `observable`，但产物层没有填充器；模型 `outputs[].action = "fill"` 无任何消费者 | 判据能算，产物仍靠手填 |
| 4 | **读产物靠全文检索** | 100 行以上账本每次由 AI 全文读取；行键其实已由 `checklist.items[]` 枚举，却无按行定位的工具 | token 高、漏行不可发现 |

## 2 目标（功能点）

| # | 功能点 | 一句话判据 |
|---|---|---|
| F1 | **脚本生成产物骨架**：给定席位 + 阶段 + 评审目录，产出固定表头 / 行列 / 节的账本文件 | 骨架 100% 由脚本生成，AI 不写表头 |
| F2 | **可算项预填**：计数、求和、落点存在性、行号引用、枚举取值、轮次账由脚本算出并写入「结果 / 证据」；取数命令内置，AI 不需自行决定跑哪条 | 每个机算格带「命令 + 输出首行」 |
| F3 | **不可算项留待判**：语义判定格留空并标「待判」，AI 只填这些格 | 待判格未填即判红（空值合法清单见 §6.3） |
| F4 | **三态可辨 + 来源可查**：每格标「机算 / 待判 / 人工」，机算格写 provenance（命令与时刻） | 任取一机算格，可凭 provenance 复跑得同值 |
| F5 | **写后校验**：AI 填完后校验「待判已填、机算未被覆盖、格式未破」 | 任一不满足即判红 |
| F6 | **产物索引**：列出某产物全部行键 + 行号 + 空格 / 状态列 | 索引行键集合 = `checklist.items[].no` 全量 |
| F7 | **行定位**：按行键 / 列取值返回命中行 + 行号 + 上下文（N 行，默认 1）；多命中按行号升序；跨节时标明边界 | 0 命中与解析失败必须区分；行号可回读原文 |
| F8 | **重跑幂等**：同一产物重跑脚本，不覆盖已填的待判格、不改其他行 | 重跑前后已填格与其他行字节不变 |

## 3 非目标

- 不做语义判断自动化：87 条 `REQUIRES_HUMAN_JUDGMENT` 保持人 / AI 判，不进脚本。
- 不改 `agents/*.md` 卡面文本；卡面「输出格式」字段（18 项）与模板列（8 列）的同源属独立前置需求（见 §7 第 2 行），本 PRD 只声明依赖，不动卡面。
- 不改评审流程与轮次纪律（流程归 `parliament`）。
- 不新增产物类型与账本模板。
- 不做语义检索：定位器只按键 / 列取值取行，不回答「哪几条理由不成立」。
- PRD 不规定代码落点；落点在 spec 中定，且不得落 `.session`。

## 4 适用范围

| 适用度 | 产物 | 理由 |
|---|---|---|
| 高 | `round-check.md`、`delivery-audit.md`、`defense.md`、`detective.md`、`evidence.md`、`issue-card.md` | 行列由模型枚举，计数 / 存在性 / 行号可算 |
| 中 | `progress.md`、`problems.md` | 计数可算，叙述仍需 AI |
| 低 | 纯语义结论（「理由是否充分」「视角是否到位」） | 只能留待判 |
| 高（读侧） | 任意 100 行以上的长产物（delivery-audit、issue-card 汇总） | 按键定位后只读命中行 |

## 5 权责

| 角色 | 职责 | 禁止 |
|---|---|---|
| 运行席（产物责任席本人实例） | 运行脚本、填待判格、对格内错值负责 | 不得由他席代跑或代填（与 `round-check.md:3`「本人实例」一致） |
| 复核席（非本席） | 复跑取数命令比对、只判红；在证据栏署名「复核席 + 时刻」 | 不得代为改正错值 |
| 机算格 | 由脚本写入，带「命令 + 输出首行 + 取数时刻（含时区）」 | AI 不得改写；改写即判红 |

## 6 验收

### 6.1 通过项（全部满足才达线）

1. **试点与基线**：固定夹具 = 试点前 3 轮 `round-check` 副本（目录写死）；基线 = 每轮机械项错填数，按 §6.4 的坏行 / 重复键口径逐轮记录。
2. **错填归零**：试点后同夹具 3 轮，机械项错填数为 0，逐轮记录明细。
3. **防覆盖**：AI 手改任一「机算」格 → 由复核席复跑校验判红（不得由运行席自证）。
4. **防漏判**：待判格无「待判」标记或未填、且不属于 §6.3 空值合法清单 → 由复核席复跑校验判红（不得由运行席自证）。
5. **可复算**：机算格 provenance 中的命令可原样复跑并得到同值。
6. **定位准确**：固定 3 个行键（`第 1 项` / `第 4 项` / `第 6 项`，即 `checklist.items[].no` = 1/4/6），返回行号与原文行号逐行一致。
7. **零命中 ≠ 解析失败**：不存在的键返回 0 命中且 `skipped=0`；表格破损返回解析失败并判红。
8. **只读**：定位器运行前后产物文件字节不变（前后 sha256 相同）。
9. **键同源**：定位器与填充器使用的行键集合一致，均等于 `checklist.items[].no` 全量。

### 6.2 观测项（只出数，不设阈值）

1. **读取量**：100 行以上产物定位 3 行，记录 AI 读取字符数前后中位数，报告降幅。
2. **调用次数**：试点前后记录工具调用次数中位数，报告变化。

### 6.3 判红前置：三态与空值合法清单

| 列 | 三态 | 允许空 |
|---|---|---|
| 核对项 / 核对内容 | 骨架（人工预置） | 否 |
| 结果 | 机算（能算的）/ 待判 | 「允许空」= 允许无判定值；格内必须写 `[待判]` 标记，物理上非空 |
| 证据 | 机算（带命令与首行）/ 人工 | `hit` 行允许空；`miss` / `na` 必须写 reason / applicability |
| 结论 / 打回清单 | 人工 | 通过时打回清单允许写「无」 |

> 空值合法清单写死，避免「待判漏填」误红。另两条硬规则：① 待判格必须带「待判」标记，无标记的空格按漏填判红；② 机算格为空即判红（脚本失败只能写「待判」并注明原因）。

### 6.4 负例（输入 / 期望）

| 负例 | 期望 |
|---|---|
| 重复行键 | 判红 |
| 坏行（列数不符） | 计入 `skipped` 并判红 |
| 围栏内伪表格 | 不计行、不判红 |
| CRLF / BOM | 解析结果与 LF 相同 |
| 单元格转义竖线 | 不切列 |
| 重跑脚本 | 不覆盖已填的待判格（幂等） |

## 8 风险

| 风险 | 缓解 |
|---|---|
| 机算值被当权威但其实算错 | provenance 强制「命令 + 首行 + 时刻」，可复算；脚本失败不得填值，只能标待判 |
| AI 过度依赖预填、漏填待判格 | 待判格显式标记 + §6.3 空值清单 + 写后校验判红 |
| 定位器与填充器解析口径漂移 | 两器共用同一解析口径（实现细节见 spec）；上移公共 CLI 后删除本地实现 |
| 解析失败被当成 0 命中 | 输出必须带 `scanned` / `skipped`；`skipped > 0` 即判红 |
| 推广面过大 | 先 1 席 1 产物试点，按「高适用度」逐个铺开 |
