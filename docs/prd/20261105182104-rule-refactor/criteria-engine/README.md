# criteria-engine（判据引擎）

> 体系定名：2026-11-05（裁定日期）｜状态：方案定稿，三件套试点已实测全绿（`tmp/rule-dsl/`，18 样例 exit 0）
> 历史别名：rule DSL、data+script 模式、判据原子、原子登记处、三件套——均指本体系的不同侧面，已收编于本名。

## 一、它是什么

**rule / agent / skill 三载体共用的判据登记与执行体系。**

一句话：**所有载体的判据统一登记在判据引擎里，机器跑，测试保，投影出。**

- 「判据」= 一条能判真假的判定标准：什么时候管（when）、查什么（assert）、例外是什么（unless）、机器判不死的谁抽检（residual）、违规/合规记录落哪（landing）。
- 「引擎」= 登记判据、跑判据、出判定、渲染投影的那套固定程序。

## 二、它解决什么问题（四个病根，各有实证）

| 病根（改造前的真实形态） | 判据引擎的解法 |
|---|---|
| **判据不可测**：规则判据全写在散文里，改一个字没人知道改对还是改错 | 判据结构化为 json（when + assert），**每条配独立 testcase**（正例防误拦、反例防漏判）；改松判据时不能顺手改测试把红抹平——判据与测试分离 |
| **执行靠自觉**：AI 读了规则照不照做无人验证（实测 12 条验证节里 9 条是「自问三句」） | 机器验「痕」（锚在不在、清单命中没命中、材料齐不齐）；机器判不死的「心」（真伪、链闭合）登记 residual，收口抽检 + 用户终审 |
| **漂移**：同一约束多处手写，措辞各异，改一漏三（「不因来源豁免」曾在 9 条 rule 里各写一遍，实测 15 处，2026-11-05） | 单一真源：判据只活在 json 里，渲染产物手改无效；共享判据不复制，多载体引用同一登记 |
| **体积**：手册类内容塞进规则正文，每轮全量注入（改造前 23 条的字符数与 tok 见 [总纲 §1](./../prd/index.md)；本文件不复制数字） | 判据 json 由 script 消费不占注入；AI 只读 rule 投影（`rules/<id>.md`）；无消费者的 `inject` 压缩版已删除 |

## 三、它干什么（五个职能）

1. **登记**：每条判据一组文件——`<id>.json`（判据，字段白名单 10 项：9 必填 + `refs` 选填）+ `<id>.testcase.json`（独立测试）。
2. **校验**：白名单外字段判红（描述性散文不允许）、算子表封闭（未注册 op 判红）、缺 testcase 判红（未验证不得渲染）。
3. **判定**：唯一 `judge` 实现——when 不成立不触发；when 成立则 assert 全过才合规（unless 例外豁免）。
4. **测试**：testcase 逐条判定，正反例双向缺一判红。
5. **投影**：可插拔解释器注册表，同一份数据渲染不同产物——`md`（完整版，给人看）、`rule`（发布投影，进 AI 上下文）。

## 四、用在什么场景

| 载体 | 场景 | 实例 |
|---|---|---|
| **rule** | 保留集触发声明的判痕切面（锚存在 / target 在场 / 材料齐） | `no-unverified-number`（数字必须附取数命令）已作首个参考实现 |
| **agent** | 卡面可机判条目（「引用必须带 path:line」「送审缺件不得开评」） | `predicates.mjs` 的 manual 型谓词逐条迁入，判心型补 residual，逐条独立随时可停 |
| **skill** | 流程门禁的可机判条件（材料完备性、产物格式） | 按流程逐条登记 |
| **通用** | 任何能写成「出现 X 且缺 Y = 违规」的约束 | 封闭算子可枚举即可登记 |

**不进引擎的三类**（性质上不是判据，硬塞 = 当年「什么都写进 rule」的镜像错误）：
语义判据（讲透/合理——归 AI 判 + residual）、流程编排（时序依赖——归 skill 骨架）、模板/知识样例（无违规形态——归 references）。

## 五、目录形态（D-6 已裁）

```
criteria-engine/
  <id>.json            判据（唯一真源；rule 正文也由它渲染）
  <id>.testcase.json   独立测试（判据/测试分离）
  rules.json           投影注册：哪些判据 id 额外产出 rules/<id>.md
  schema.mjs           算子表 + judge 唯一实现 + 结构校验
  interpreters.mjs     投影注册表（md / rule；rule 投影 = rules/<id>.md）
  rules.mjs            rule 正文投影的取数/渲染/落盘（唯一入口）
  build.mjs            编排：加载 → 校验 → 判定 → 渲染
  README.md            本文件
```

> **2026-11-05 更正**：rule 正文不再有独立数据族（不再有 carriers / 散文数据）。
> 正文 = 判据 json 经 `rule` 解释器渲染出的投影；散文只是产物，不是数据。
> 手改 `rules/<id>.md` 即红（`RuleProjectionDrift` / gate `Mismatch`），改 json 后重跑 `build.mjs`。

## 六、七条硬设计裁定（改动需重裁）

| # | 裁定 | 理由 |
|---|---|---|
| **判据与测试分离** | cases 不在判据 json 里，独立 `<id>.testcase.json` | 同一实例写判据又写测试期望 = 自评同盲点；同文件时改松判据可顺手改测试抹红 |
| **判定语义唯一** | `judge` 只有 schema.mjs 一份实现；可插拔的只有投影 | 两个 judge 实现有出入 = 同一输入判出不同结果 = 判据漂移 |
| **判痕不判心** | 机器只判「痕」（存在性/命中/清单）；「心」（真伪/链闭合）登记 residual：AI 判 + 收口抽检 + 用户终审 + 客观化路径 | 判心不可机判；residual 是待客观化的 todo list，不是垃圾场 |
| **加判据零改脚本** | 新增一条判据 = 加两个数据文件，schema/解释器/编排零改动 | 扩展性已实测（`no-unverified-number` 试点验证） |
| **逻辑关系显式建模** | `anyOf` / `allOf` / `oneOf` / `not`；同级不混用，只能嵌套 | 隐式 AND / 优先级会让「或」「且」藏回散文，判定与渲染各说一套 |
| **label 只命名** | 名词短语；连接词由结构树产出，谓词由算子产出 | label 一旦承载逻辑或谓词，同一语义就有第二份表述，改一处必漂另一处 |
| **判定动作与记录落点分离** | `probe` 回答「怎么取」，`landing` 回答「记在哪」 | 把命令塞进 landing 会让读者知道结果、不知道取数动作，正文成半条规则 |

## 七、起点实证

- 三条试点判据（`no-git-write` / `import-guard` / `no-unverified-number`）共用同一引擎，**18 样例全绿 exit 0**，两解释器（md / rule）各渲染投影。
- 负向实测：旧格式（含描述性散文字段）喂入 → 8 条「未登记字段」RED exit 1；移走 testcase → 「判据无测试，未验证，不得渲染」RED；op 写散文 → 「算子表封闭」RED。
