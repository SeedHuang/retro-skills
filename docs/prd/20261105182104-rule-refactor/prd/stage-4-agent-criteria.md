# 阶段 4：agent 判据改造

> 所属项目：[rule 改造总纲](./index.md)｜前置：[阶段 2](./stage-2-new-mode-pilot.md) 完成（阶段 3 可并行，互不阻塞）
> 依据：统一模型 + agent 进化可行性（2026-11-05 裁定入文）；改造原则 = **语义与执行力净增不损**。

## 1 完成事项

1. **`predicates.mjs` 8 条谓词逐条分流**：`impl:'manual'` → `'script'`（配判据 json + 独立 testcase，迁入 `tools/quality/criteria-engine/`）或保留 `'manual'` + 补 `residual{who, sample, fields, 客观化路径}`。
2. **agent 卡面「一定会 / 禁止」条目逐条过判据分流**（三类，见 §2）。
3. 卡面渲染义务文本零变化（diff 证）——进化改的是**判定方式**，不改**义务内容**。

## 2 三类分流（逐条过，语义芯不动）

| 类 | 例子 | 去向 |
|---|---|---|
| **有信号的**（可机判） | 「引用必须带 path:line」「送审材料缺件不得开评」「产物按 X 格式」「gate 逐字节比对」 | → 判据引擎（script 型原子，配独立 testcase） |
| **语义芯**（职责义务表述） | 「只交原文、不越权下结论」「如实作答」 | → 留卡面正文——卡面是 docgen 渲染产物，义务文本不变 |
| **判心**（执行质量判定） | 「越权了没有」「回避了没有」 | → residual 登记（原 manual 型连这层都没有，逐条补齐） |

## 3 可行性依据（三证）

1. **管线同构已证**：agent 侧（card-model 单源 → validatePredicates 校验 → docgen 渲染卡面 + gate 逐字节）与判据引擎（判据/测试 json → schema.mjs 校验 → interpreters 渲染 + 手改无效）本是同一模式的两次独立演化——**缺的不是管线，是判据结构化**（when/assert + 独立 testcase）。
2. **执行力三层 > 一层**：进化前 = AI 读卡面 + 自觉（执行没执行无人验）；进化后 = AI 读卡面（不变）+ 机器验痕（净增）+ 判心抽检（净增）。
3. **rule 侧同构进化已有实测**：`no-git-write` 判据引擎化后义务零变化，新增机器与抽检两道闸，18 样例全绿。

## 4 迁移形态

**逐条独立、随时可停**：`impl` 逐条分流，每条迁移互不阻塞（与「加判据零改脚本」同构）；卡面渲染继续走 docgen 管线（数据 → 生成 → 确认 → 替换的既有纪律不变）。
