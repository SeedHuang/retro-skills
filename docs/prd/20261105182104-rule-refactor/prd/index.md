## 4 rule 写作规范（通用，与改哪条无关）

**四类该进 rule（缺一不可）**：① 义务句（做什么/禁止什么/必须什么）② 判定动作（可机判：命令+退出码/计数/集合比较/空非空/枚举）③ 边界与例外（`除非/只许/不再/不得`）④ 来源锚（一行：`来源：PRD §X / 用户裁定 YYYY-MM-DD`）。

**四类不该进**：① 为什么/病根/实测 → references ② 历史沿革 → git ③ 反例 → 测试断言（无测试才压一行）④ 操作步骤/模板/清单表 → skill 或脚本。

**判别法两条**：① 删掉这段，「判定动作」变不变？变 = 判据（提回正文压缩成句）；不变 = 说明（删，git 有）。② 已有脚本/技能持有？已持有 → 移，并查是否形成第二份真相。**唯一例外**：理由里携带边界条件（`除非/只许` 藏在解释句里）——提回判据行再删解释，不许整段删。

**正文四层**：判据层（义务+判定动作，必进上下文）/ 边界层（例外，紧邻判据）/ 溯源层（来源锚一行）/ 说明层（进 references，正文留一行指针——指针指向的文件必须真实存在；跨仓指针必须带仓前缀，写「（仓：retro-skills / evo-retro-skills-inspector）」，references 不复制判据正文）。

## 5.3 实测 token 账（T 系列：三个时点、两个口径）

> 账面口径 = 可复算（字符 × 0.5133 tok/字符折算系数）；**实付口径 = 黑盒每轮实际注入的份额**——2026-11-03 实测黑盒只注入 9 条（26,513 字符 ≈ 13,570 tok/轮）而非全量 23,340 tok，**实付才是真省的钱**。总 token = 固定前缀（系统提示 + 规则 + skill 名单 + 工具定义）+ 对话历史 + 输出——改造只影响规则份额，总量降幅 < 注入降幅；总量对比用同型任务代理（三个时点各问固定短问题，记首轮输入，平台 usage 可见则记实测值）。

| 时点 | 注入贡献（账面可复算） | 采集动作 |
|---|---|---|
| **T-0 基线（改造前）** | 源头账 **47,311 字符 ≈ 24,285 tok**（2026-11-05 18:26 取数）；**实付口径 9 条 / 26,513 字符 ≈ 13,570 tok/轮** | 2026-11-03 会话样本 + §5.3 复算命令（本节下方 `:101-104`） |
| **T-1 阶段 1 后** | 规则注入贡献 **0 tok/轮**（每轮实省 ≈ 13,570 tok） | 见 stage-1 验收（含运行时链接清退） |
| **T-2 阶段 2 后** | 触发声明（387 非空白字符）+ 3 个 skill 描述 ≈ **150–300 tok/轮**（对比 T-0 实付口径仍降约 98%） | 见 stage-2 验收（V-12 窗同窗采集） |

复算命令（任一时点可跑；口径 = 逐文件字符求和 × 0.5133）：

```powershell
(Get-ChildItem rules\*.md | ForEach-Object { (Get-Content $_.FullName -Raw).Length } |
  Measure-Object -Sum).Sum * 0.5133
```

> **⚠️ 旧命令作废**：`(Get-ChildItem rules\*.md | Get-Content -Raw).Length` 取的是数组元素数（= 文件条数），不是字符和（2026-11-05 实测返回 23）。
> T-2 时点另加触发声明字符 + 各新 skill SKILL.md 的 description 行字符（description 是进名单的部分；手册正文只在被触发加载时计入**按需成本** = 正文字符 × 0.5133，属账面估算，须用平台 usage 校准）。
