- **覆盖**：`R1 / §4 / §5 验收① / §7-1`
- **前置**：施工完成；归桶索引载体已落地（开放问题 1 未裁前的任一种形态：`tools/execution-matrix/` 或 docgen 组件或文档索引，以 plan 落点为准）
- **步骤**：① 定位归桶索引载体与三类文档（rule/skill/agent）checklist；② 断言三类 checklist 文件各存在一份；③ 跑仓库总检查
- **预期**：rule/skill/agent 三类各有一份 checklist；归桶索引能指到每份 checklist；总检查退出码 0
- **判据**：机器——文件存在断言（`Test-Path` 三类 checklist 全部为 true）+ `node scripts/check-all.mjs` 退出码 0；输出无 findings
- **红绿证据**：红 = 删掉 agent checklist，总检查退出码非 0 / 文件断言 false；绿 = 补齐后退出码 0
- **对应测试**：待 plan Task N
- **不覆盖**：不查共享项引用正确性（TC-003/005 管），不查清单完整性（TC-006 管）

### TC-003 共享项零重复定义（引用而非复制）

- **覆盖**：`R1 / §5 验收①`
- **前置**：三类 checklist 与归桶索引已落地
- **步骤**：① 取 allShared 与三个两两 shared 桶内全部检查项；② 逐个在 rule/skill/agent 三类 checklist 中检索该项出现方式；③ 断言：每类 checklist 中该项为**引用**（指针/槽位名/ID），非**内联复制**；④ 断言该项正文全文在仓库中**只出现一次**
- **预期**：共享项正文全库恰一处定义；三类 checklist 只出现引用；无同一检查项两处以上正文副本
- **判据**：机器——归桶零重复扫描：对每个共享项 ID 统计「定义处」计数，`定义处 === 1` 且「引用处 ≥ 引用它的 checklist 数」；任一共享项定义处 > 1 → 退出码非 0 并列出重复位置（文件:行号）
- **红绿证据**：红 = 某共享项正文被复制进两份 checklist，扫描报 2 处定义；绿 = 删副本改引用后通过
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖「改动一处自动同步」的运行时机制（本 spec 只要求静态归桶，联动改查 §1 联动四问与 TC-044）

- **判据**：机器——归桶扫描退出码非 0；输出含错误码（如 `BucketMismatch`）与文件:行号；「两两 shared 并入 allShared」必须为硬失败（非 warning）

- **前置**：职责分离声明与证据判定规则已落地
- **步骤**：① 构造证据样例：「我检查过了，没问题」（无命令、无文件、无行号）；② 评审者判定该描述是否算证据
- **预期**：判「不算证据」——R3 明文「『我检查过了』类描述不算证据」；证据 = 可重跑命令/可读文件，不是自我声称
- **判据**：人工/AI——评审者按证据判定规则：无「命令 + 输出」或「文件:行号 + 内容相符」→ 不算证据，缺证据 = 不通过（不是待补）
- **红绿证据**：红 = 「我检查过了」被记为证据栏内容；绿 = 证据栏空/不合格
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖「什么算可重跑命令」的细则（TC-043 管可重跑性）

### TC-043 证据可重跑验证（复核 = 真重跑命令/读文件）

- **覆盖**：`R3 / §5 验收⑤`
- **前置**：证据判定规则已落地；构造一条带证据的结论
- **步骤**：① 取证据文本（声称某命令输出 / 某文件某行）；② 复核者真重跑命令 / 真读文件；③ 断言结果与证据一致
- **预期**：重跑/读文件结果与证据一致 → 证据有效；不一致或跑不出 → 证据无效。复核动作必须是真执行，不是「相信证据文本」
- **判据**：机器——复核命令：对证据中「命令」重跑比对输出、对「文件:行号」读文件核对内容；任一不符 → 该证据判无效，退出码非 0
- **红绿证据**：红 = 复核只看证据文本不真重跑（自证偏差）；绿 = 真重跑且结果比对
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖证据所证明结论的对错（那是评审语义）

### TC-044 共享项变更硬闸门存在（两版对照 + 用户确认）

- **覆盖**：`R7 / §1 联动四问`
- **前置**：共享项变更流程说明已落地
- **步骤**：① 读共享项变更闸门说明；② 断言含「改前 vs 改后两版留齐 + 用户确认」强制步骤；③ 构造反例（只改新版不留旧版即落地）→ 判定
- **预期**：闸门声明两版对照 + 用户确认；「只改新版即落地」流程判不合格——共享项影响所有引用方（spec §1 联动四问），无对照无确认 = 引用方不可核对变更影响
- **判据**：机器——流程说明扫描：含「改前/改后」「用户确认」关键词，且为强制（非建议）；缺任一 → 退出码非 0
- **红绿证据**：红 = 闸门说明只写「共享项要谨慎改」；绿 = 明确两版对照 + 用户确认两步
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖闸门的执行记录（运行时责任）

### TC-045 共享项变更无两版对照 → 判失败

- **覆盖**：`R7`
- **前置**：共享项变更闸门已落地
- **步骤**：① 构造反例变更记录：共享项 X 直接改新版，无「改前 vs 改后」对照存档、无用户确认记录；② 审计判定该变更
- **预期**：判失败——R7 硬闸门未过，变更不成立；缺对照或缺确认任一即打回
- **判据**：机器——变更记录断言：共享项 X 的变更记录含「改前版 + 改后版 + 用户确认」三件套；缺任一 → 退出码非 0 并列出缺失项
- **红绿证据**：红 = 变更只留新版被放行；绿 = 缺对照/缺确认即拦
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖非共享项（独有项）变更——独有项只影响本类型，不强制走该闸门（spec R7 只约束共享项）

### TC-046 allShared 桶内项语义同构性核对（边界）

- **覆盖**：`§4 allShared 候选 / §1 同族`
- **前置**：归桶索引已产出
- **步骤**：① 取 allShared 桶内每项；② 评审者核对：该项在三类文档中的语义是否同构（rule「触发时机」/ skill「触发时机」/ agent「when 字段」是否真的是同一个可执行概念）；③ 断言语义不同构项不得入 allShared
- **预期**：触发机制⑦等 allShared 项在三类语义同构才可归入；若 agent 的 when（数据字段）与 rule/skill 的触发时机（语义段）不同构，则该检查项必须降为两两桶或拆分——allShared 前提是「三类都有同一概念」（spec §4 写「是最大公约数」是有条件的，需核对）
- **判据**：人工/AI——评审者逐项写「三类语义同构性」一行判断；任一项不同构仍留在 allShared → 判归桶错误，给出建议桶
- **红绿证据**：红 = 只看「三类都有触发相关文字」就归 allShared；绿 = 语义同构核对，不同构则分流
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖 allShared 之外桶的语义（两两桶同构性同理可查，非本用例范围）

### TC-047 A 组判据与 validateAgentData 既有断言无交集

### TC-048 模式表来源内容漂移 → 判失败

- **覆盖**：`R6 / §5 验收③`
- **前置**：模式表已产出；构造反例：某行来源 `agents/reviewer-audit.md:15` 指向的行内容已与行结论无关（文件被改，行号漂移）
- **步骤**：① 跑来源内容核对；② 断言指向内容存在且相符
- **预期**：来源指向行存在且内容支持该行结论 → 有效；指向行内容已漂移/不存在 → 判失败——来源可复算不仅是「有行号」，是「行号处内容与记录一致」
- **判据**：机器 + 人工/AI——机器：逐行读来源文件:行号，断言行存在且内容非空（漂移/不存在 → 退出码非 0 列出）；人工/AI：核对「行内容与模式表行结论同主题」（语义判断，机器只保证存在与非空，不判同主题）
- **红绿证据**：红 = 只查「文件存在」不查行内容，或把「同主题」塞给机器判（退化成关键词近似）；绿 = 机器查存在/非空 + 人工/AI 查同主题，漂移即拦
- **对应测试**：待 plan Task N
- **不覆盖**：不覆盖来源结论的对错（语义复核归模式表维护）

### TC-049 A3 失败时 C1 级联判定（边界）

| C 组 4 项（C1/C2 逐条自证 / C3 结论可复算 / C4 自证贯穿） | 需人通读卡全文判断「自证是否贯穿、逐条是否自证」 | reviewer-qa 逐产出节检查证据位；开头总声明不能替代产出节证据 |
| 越界判定（TC-028） | 「检查对象是卡文本还是运行时」需理解 A/B/C 组意图与 parliament/review-loop 职责 | 评审者核对检查对象归属，越界判不合格并指明归属方 |
| 语义同构性核对（TC-046） | 「三类语义是否同一概念」是语义判断 | 评审者逐项写同构性判断；不同构项不得留 allShared |
| 职责分离（TC-041/042） | 「独立方复核」「不算证据」是原则判定 | 评审者按 R3 判定声明完整性 + 证据判定样例 |

## 6 不测（带理由）

| 不测什么 | 为什么 |
|---|---|
| 运行时产出验证（议会产出、运行记录） | spec §5「不测」明示，归 parliament（侦探行为核对 + 审计证据核对）与 review-loop（复查轮独立重审）；A/B/C 组查运行时即越界（TC-028 反而是负例） |
| rule/skill 判据正文的改写内容 | spec §1 边界明示属 line B；本 spec 只建归桶索引不改写正文 |
| S3/S4 迁移（13 席迁移的 A/B/C 判定） | spec §1 边界明示；本 spec 只建检查体系，迁移是后续 spec 的验收 |
| 评级「N 次零回归」的 N 具体取值 | spec §4/§6 用 ≥N 占位，属待裁项；未裁前断言具体阈值会编造判据 |
| 模式表载体的最终落点（独立文件 vs 并入 lessons/retro） | spec §6-2 开放问题未裁；用例只断言「种子 ≥5 + 来源可复算」这两条与载体无关的硬性 |
| annotations 文件的 schema 细节 | 开放问题未裁；以既有 `rules/.inspector-annotations.json`（X1/X2/X3 先例）为基准，本 spec 验收只要求「判定落位 + 脚本机械接收」 |
| 新 agent 角色的 A/B/C 判定 | spec §1 边界「新 agent 角色（复用现有角色）」明确不做 |

## 7 缺口与判别力水位

| 缺口 | 漏检哪类反例 | 至少 1 个样例 | 语义由谁兜 |
|---|---|---|---|
| B 组「identity 真实」的判别力边界 | 卡声明了真实存在但**夸大程度**的能力（如「审计 13 席全部产出」但实际只审计提交物） | 卡写「核对全部交付物」而边界写「只核对清单内交付物」 | reviewer-qa 判定时核对 frontmatter tools + 实际职责枚举；议会评审（reviewer-audit 审计）兜底 |
| C 组「自证贯穿」对「产出节有证据栏但从不填」的漏检 | 卡结构上有证据栏，但结构检查（A 组）不查运行时是否真填 | 核对项表每行有证据栏，但某轮评审证据栏全空仍被放行 | 运行时由 parliament 侦探/审计核对证据栏非空；本 spec 只保证结构存在（TC-023 判「无证据位」而非「没填」） |
| 归桶语义同构性（TC-046）无法全自动 | 脚本只能查「桶名齐全 + 零重复」，查不了「这个检查项归类语义对不对」 | 把「冲突裁决⑤」从 skillAndRuleShared 误归 allShared（agent 无冲突裁决概念） | 评审者逐项核对；归桶索引首次落地送议会评审核对 |
| 评级「高」档的零回归是否真为零 | 评级依据是记录数，但记录可能不全（没记录 ≠ 零回归） | 某模式只跑了 2 次全过就评「高」；N=2 是否达阈值依赖待裁 N | N 值裁决后由取数命令口径保证；记录来源归 retro/lessons 流程 |
| 「你检查过了」类证据的机器识别 | 命令 + 输出形态可机器比，但「读文件核对内容」的语义核对比不了 | 证据写「`Select-String` 已确认无重复」但未附输出 | 复核者真重跑命令核输出（TC-043 机器兜底命令类；读文件语义归复核者） |
| 开放问题 3（reviewer-audit 存量 0 项是否立即修） | 本测试不判定「存量问题该不该修」，只保证「判得出来」 | C3 在 reviewer-audit 卡上若判 0（结论节证据要求可能缺失），修不修未裁 | spec §6-3 建议记入模式表留待 S3/S4；由议会评审裁决 |
