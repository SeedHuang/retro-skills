# 复盘飞轮战略图（大蓝图）

> 来源：2026-10-01 设计对话
> 定位：**战略图**——画出完整的飞轮和它的分阶段覆盖路线。它不规定具体改哪个文件；具体改动在局部战术 spec（`2026-10-01-retro-self-improvement-design.md`）。
> 关系：战略图与局部战术**不冲突**。战略图负责"往哪去、分几步到"；局部战术负责"这一步现在改什么"。每完成一个局部战术，就在战略图上点亮一块。

## 0 一句话

把"我在一次 session 里的不爽"，变成"下一次 agent 行为更好"——中间经过记录、沉淀、触发、复盘、落地五环，越转越顺；同时，这个飞轮每转一圈，我就多懂你一点。

## 1 飞轮全图

```
                    ┌──────────────────────────────────────────┐
                    │  Ring 0  原样发生                          │
                    │  session 进行 → agent 失误 → 你不爽（锚点） │
                    └───────────────────┬──────────────────────┘
                                        │
              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 1  记录（自动）                              │
              │  情绪锚点 + session 标识 + 上下文指针 → moments.md  │
              └─────────────────────────┬─────────────────────────┘
                                        │
              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 2  沉淀                                      │
              │  教训→ledger｜情绪→moments｜过程→摘要/事实包/复盘    │
              └─────────────────────────┬─────────────────────────┘
                                        │
              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 3  触发/通知（系统层）← 当前最空的一环         │
              │  编辑器内巡检（开工轻提醒）｜未来：IM/工作助手       │
              └─────────────────────────┬─────────────────────────┘

              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 4  复盘分析（用户发起）                       │
              │  事实包 → 复盘（说人话 + 危害/代价）                 │
              └─────────────────────────┬─────────────────────────┘
                                        │
              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 5  落地（lessons 裁决 → retro-skills 施工）   │
              │  更新 rule / skill / automation                     │
              └─────────────────────────┬─────────────────────────┘
                                        │
              ┌─────────────────────────▼─────────────────────────┐
              │  Ring 6  行为改善                                   │
              │  新 session 里 agent 做得更好 → 回到 Ring 0         │
              └────────────────────────────────────────────────────┘

   旁环（贯穿全程）：用户画像 ← 从每个情绪锚点累积
                    → 复制人（预沟通）→ 反哺 Ring 4/5 的方案质量
```

## 2 核心连接件：session-情绪锚点

**这是整张图的承重墙，之前的设计把它丢了。**

一次 session 里你不爽——这个情绪**不是一个孤立的抱怨，它是拿回整段 session 的把手**。顺着这个把手往回拉，能拉到：那次对话发生了什么、agent 做错了什么、复盘得出了什么、最后落成了没落。

所以每条情绪记录**必须锚定它的 session**（带 session 标识），从而：

```
一条情绪（锚点）→ 指向该 session 的全部上下文（摘要 / 事实包 / 复盘 / 账本条目）
```

**没有这个锚**：情绪是一堆没出处的标签，复盘找不到场景，画像追不回依据——飞轮各环之间是断的。
**有了这个锚**：情绪成为复盘和画像之间的桥，也是 Ring 3 触发时能"顺着锚把整段故事调出来"的前提。

## 3 六环逐环说明

| 环 | 名称 | 谁触发 | 输入 | 输出 | 现状 |
|---|---|---|---|---|---|
| 0 | 原样发生 | — | — | 一个失误 + 你的情绪 | 天然发生 |
| 1 | 记录 | **自动**（agent 察觉即记） | 情绪 + session 上下文 | moments.md 一条（含锚点） | Part 1 建 |
| 2 | 沉淀 | 自动 / 用户发复盘 | 过程与教训 | ledger 条目 / 事实包 / 复盘 | 已有 |
| 3 | 触发/通知 | **系统层**（编辑器巡检为主） | 已沉淀的未处理项 | 一句不打扰的提醒 | **最空，Part 1 起步** |
| 4 | 复盘分析 | **用户发起** | 事实包（+ 锚点） | 说人话的复盘 | 已有，Part 1 改进 |
| 5 | 落地 | 用户在 lessons 发起（一次一个） | 账本 + 历史复盘 + 锚点 + 画像 | rule / skill / automation | 已有，Part 1 归位 |
| 6 | 行为改善 | 自然发生 | 更新后的资产 | 更好的下一次 session | 目标态 |

**关键原则**：Ring 1 自动、Ring 3 系统保障、Ring 4/5 用户发起。**记录可以自动，决定永远归人。**

## 4 用户画像 → 复制人：演进阶梯

| 级 | 形态 | 说明 | 何时 |
|---|---|---|---|
| L0 | 标签 | 现在的用户档案：偏好清单（"要日志""说人话"） | 已有 |
| L1 | 场景锚定 | 每条认识能追回一个具体 session（靠情绪锚点） | Part 1–2 |
| L2 | 判断模型 | 面对某类问题，你大概会怎么判断（先问用途、再问代价） | Part 2+ |
| L3 | 复制人 | 能给方案"预沟通一轮"——先过一遍"他会怎么看" | 远期 |

**L3 的最小可用版本现在就能做**：我每次给方案前，先拿画像自检一遍（"这个人会在意什么？会反对什么？"），不对先改。这就是"预沟通一轮"的雏形，不必等大系统。

## 5 触发/通知层：编辑器为主，IM 为辅

| 渠道 | 覆盖场景 | 能接的下一步 | 分期 |
|---|---|---|---|
| **Trae / VSCode**（编辑器） | coding 全过程 | 直接改 skill/rule，最顺手 | **主线，现在做** |
| IM（钉钉/飞书/工作助手） | 非 coding 的日常 | 只能"提醒"，接不上改 skill | 远期，独立设计 |

**判断**：因为我们的产物（复盘、skill、rule）都是开发物件，**编辑器是天然主场**——记、看、改都在一处。IM 那层覆盖面更广，但它是"提醒的延伸"，不是"飞轮的主轴"，现阶段不并入。

**编辑器的触发形态**（不打扰原则）：沿用已有的"开工巡检"——会话开始时顺嘴报一句，不弹窗、不打断：

> 推迟项 6 条，均未命中信号；未结案情绪 3 条；画像 30 天未更新。

## 6 覆盖阶段（在大蓝图上一块块点亮）

| 阶段 | 覆盖的环 | 内容 | 状态 |
|---|---|---|---|
| Phase 0 | 2/4/5 | collect / analyze / institutionalize / ledger 四件套 | 已有 |
| **Phase 1** | 1/3/4/5 | 情绪锚点记录 + 巡检扩展 + 复盘说人话与危害账 + 落地归 lessons + 画像预自检 + **技能复盘链**（评审回流只记账、不追问改）+ **KB 体积治理**（热冷分层 / 归档 / 守卫 / show·find） | **局部战术 spec：`2026-10-01-retro-self-improvement-design.md`** |
| Phase 2 | 3/4 | 画像场景锚定；复盘结合锚点回溯 | 待规划 |
| Phase 3 | 旁环 | 复制人预沟通（方案先过画像） | 待规划 |
| Phase 4 | 3 | IM / 工作助手通知层（非 coding 场景） | 远期 |

**每阶段自洽可跑**：Phase 1 完成后，即便后面的没做，"记录→锚定→复盘→画像"这一段也能独立转起来。这是分阶段的意义——**不追求一次到位，追求每一块都能用**。

## 7 边界与不做

- **记录自动，决定归人**：飞轮再自动，Ring 4/5 的"要不要做、怎么做"永远由用户拍板——与"判断权在用户"原则一致。
- **不一次铺大**：战略图是愿景，落地按阶段，每阶段独立可验证。
- **不做**：IM 集成本期不碰；复制人不做模型训练（只做"规则化的预自检"）；趋势图/可视化为远期。
- **AI 可被动记录情绪，但不能自作主张下结论**——分析永远等用户发起。
- **技能复盘链**（2026-10-01 起）：技能自身的盲区由 `review-flywheel` 记账，**只告知、不追问改**；「改」由用户在 lessons 发起后走 `evolving-skills`。
- **体积治理**（2026-10-01 起）：KB 分热冷——`open` 留主账、`landed` 归档到 `ledger-archive-<年>.md`；主账超阈值提醒"尽早复盘收口"；**冷层永不读进上下文**，库再大也不拖累。
