## 4 机制

### 4.1 调用形态（门行证据的原文）

```
node scripts/check-plan.mjs coverage --plan <plan 文件> --prd <PRD 文件> --stage <S#>
node scripts/check-plan.mjs deps     --plan <plan 文件>
node scripts/check-plan.mjs map      --plan <plan 文件>
node scripts/check-plan.mjs size     --spec <spec 文件> --testcase <testcase 文件> --rounds <n>
```

- 路径解析统一 `resolve(process.cwd(), <arg>)`（与 `scripts/check-gate-record.mjs:80` 同口径）：相对路径以**调用时的 cwd** 为基准、绝对路径原样；门行证据一律在仓根下调用，故等价于「相对仓根」。文件不存在 / **路径是目录** → exit 2 并打印接到的是哪个参数（目录的报文见 Q25）。
- `--rounds` 对新块**必传**（R6）：缺 → exit 2。
- `--stage` 形态必须匹配 `^S\d+$`：`4` / `S4x` / `s4` → exit 2（不得静默走成「0 命中」的判据红）。
- `--rounds` 值必须是非负整数：`三` / `-1` / `1.5` → exit 2（`用法错：--rounds 必须是整数`）。
- 入参先 `statSync().isDirectory()` 判目录，再 `readFileSync`：**目录一律报「不是文件」**（否则 Windows 下会抛 `EISDIR` 落进「不可读」分支，报文与 Q25 不一致）；**`statSync` 抛 `ENOENT` → 走上一条的「文件不存在」分支**（报文须同时含参数名与文件名，见 P09），只有 `readFileSync` 的其余错误才进下一条的「不可读」。
- 读盘失败（`readFileSync` 抛错：权限 / 路径过长 / 编码）→ `try/catch` → exit 2，`用法错：<path> 不可读（<code>）`；**不得**让未捕获异常冒成 exit 1 的空首行（那会让门行证据拿到空串）。
- exit 0 / 1 时首行恒为 R7 的计数行；违规逐条 `console.error`（`[check-plan] <子命令>：<一条违规>`）。
- **exit 2 只打印一行用法/结构错，不打印任何计数行**（无数可计时不得出现 `gap 0` 形态，防误读成通过）。
- 不认识的子命令或多余参数 → exit 2。

## 7 测试节（测什么 / 为什么）

测试目标：四条子命令的**判据有判别力**——每一类违规都要能由一条可重跑的构造造出红，而不是只在正常路径断言。

测试用例文件：`docs/superpowers/specs/2026-10-28-s4-plan-gate-design-testcase.md`

| 测什么 | 为什么 |
|---|---|
| `coverage` 的差集语义（缺一个 F 必红、多一个 F 不红） | 宽松口径的方向必须被钉住，否则「宽松」会成为漏报的借口 |
| `coverage` 的 `--stage` 派生（区间 `～` 展开 / 顿号拆分 / 一行一个 F） | 两种存量表形态都要能读出正确集合 |
| `deps` 的三种标题形态、两种 `Consumes` 写法、环、`dangling` | 存量三份 plan 写法不同，收紧一种就有一份读不出来 |
| `map` 的两种用例 ID 载体、双向差集、testcase 路径缺失 | 只认一种载体 = 假绿（S1/S5 会被读成 0 条） |
| `size` 三项阈值 + `--rounds` 必传（缺 → exit 2）+ 存量超限样本 | 规模指标是本段新增判据，必须有红例；`--rounds` 可缺省会留一条永久假绿通道 |
| R7 的首行格式逐字 | 门行证据靠它比对，格式漂了判据就不可比 |
| exit 2 的用法错（清单见 Q23，不自列） | 「用法错」与「判据红」必须可区分，否则施工者会拿 exit 2 当通过 |
| 功能点→任务映射表的识别（按值 / 按表头）与「无表即红」 | 半条判据的唯一机械载体；判「不适用」会让 1 个 Task + 4 个 F 记号的 plan 三行全绿 |
| 附录 A 同一 ID 多行 → `mapped` 去重 | 计数口径漂了，门行数字就不可比 |
| `--spec` / `--testcase` 指向目录 → exit 2 | 目录不是可判对象，不得判成判据红 |
| `check-gate-record` 的 ISO 时间串用例 | P2 修法必须有判别力（修前必红、修后放行） |
| `TC-A09` / `TC-E26` 改义后的语义 | 判据级口径变更，须有正反两面 |
| `Consumes:` 后接「无」的行、区间四种破折号、单元格内多个 `Task`（「都」） | 这三类都是**真实 plan 里已存在**的写法：不钉住就会把 S3 plan 读成 16 条悬空 / 只认一种破折号 / 只看第一个任务 |
| 读盘失败、`--rounds` 非法值、`--stage` 形态错 → exit 2 | 「用法错」与「判据红」必须可区分；未捕获异常会让门行拿到空首行 |
| 旁路 plan 不跑 `coverage` / `map`（`stage-2b` 的旁路分支仍在位） | PRD §4.2 的逃生口；删掉它 = 单点小改无门可走 |
| 指纹复算（审计 ④ 段值现算） | 只核「有没有写」等于让指纹可以随便抄 |

## 8 不在这一轮 / 不测

- **不在这一轮**：`agent-card` PRD 的 S4 渲染层（F-09～F-12、F-23、全席重生成、`EXPIRY_LANDED` 置 true）；`commands.mjs` 的 `check.local` 补项（S6）；S2 测试夹具迁 `.session/tmp`（S2 已签测试，另走修订）。
- **不测**：PRD / plan 的**内容正确性**（脚本只判结构关系，判不出「这条需求写得对不对」）；议会轮数的真实性（由申报人抄入）；`npm run check` 的其它段。
