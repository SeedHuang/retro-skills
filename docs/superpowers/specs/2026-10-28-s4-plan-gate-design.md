## 4 机制

### 4.1 调用形态（门行证据的原文）

```
node scripts/check-plan.mjs coverage --plan <plan 文件> --prd <PRD 文件> --stage <S#>
node scripts/check-plan.mjs deps     --plan <plan 文件>
node scripts/check-plan.mjs map      --plan <plan 文件>
node scripts/check-plan.mjs size     --spec <spec 文件> --testcase <testcase 文件> --rounds <n>
```

- 路径解析统一 `resolve(process.cwd(), <arg>)`（与 `scripts/check-gate-record.mjs:80` 同口径）：相对路径以**调用时的 cwd** 为基准、绝对路径原样；门行证据一律在仓根下调用，故等价于「相对仓根」。文件不存在 / **路径是目录** → exit 2 并打印接到的是哪个参数（目录的报文见 Q25）。
- `--rounds` 对新块**必传**（R6）：缺 → exit 2。
- exit 0 / 1 时首行恒为 R7 的计数行；违规逐条 `console.error`（`[check-plan] <子命令>：<一条违规>`）。
- **exit 2 只打印一行用法/结构错，不打印任何计数行**（无数可计时不得出现 `gap 0` 形态，防误读成通过）。
- 不认识的子命令或多余参数 → exit 2。

### 4.2 解析口径的可判边界（防止「看起来核了」）

| 输入 | 取法 | 取不到时的处置 |
|---|---|---|
| PRD 的 F→S 表 | 逐行 `splitRow`（复用 `tools/execution-matrix/markdown-rows.mjs`）后按表头定位 | 找不到表 → exit 2，打印「未找到 F→S 覆盖表」 |
| `--stage` 命中行 | S 列切词后精确等于 `S#` | 命中 0 行 → exit 1 并报 `stage <S#> 在 F→S 表里 0 命中`（这是 PRD 漂移，不是用法错） |
| plan 侧功能点 | plan 全文 `F-\d{2}` 全取（宽松） | 一个都没有 → 覆盖差集 = PRD 全集（必红） |
| 任务节点 | 标题正则（R4） | 0 个节点 → `deps` exit 1；`coverage` 的「至少一条执行步骤」同时按下面一行判定 |
| 功能点→任务映射（覆盖第二半） | **按单元格值识别，不按表头**：某表内存在「首列含 `F-\d{2}`」的数据行，且该表任一单元格含 `Task\s*\d+` / `T\d+`（S3 plan `:92-98` 的表头是「PRD 功能点 / 一句话 / 本 plan 落点 / 覆盖用例（附录 A）」，按表头认会认不出）。每个被覆盖功能点该 `Task` 单元格非空、且其编号都指向存在节点 | **无此表 → exit 1**：`[check-plan] coverage：无「功能点→任务映射表」，第二半不成立`（**没有「不适用」这一档**——否则 1 个 Task + 4 个 F 记号的 plan 三行全绿）；某 F 缺行或该单元格为空 → exit 1：`[check-plan] coverage：<F> 无任务落点`；指向不存在的任务 → exit 1：`[check-plan] coverage：<F> 指向 <Task N> 不存在` |
| `Consumes:` | 任务块内该行，`Task\s*\d+` / `T\d+` 全部取值，**区间（`2–7` / `T1–T7`，破折号 `～ ~ – — -`）一律展开**（R4） | 无 `Consumes:` 行 → 该节点入度 0（合法；S3 plan 的 T1/T2 即如此） |
| 边集 | 去重后的**两端节点都存在**的边；指向不存在节点的引用计入 `dangling`，不计入 `edges`。**区间展开后每条引用各计 1**（`Task 8–9` 而节点只到 7 → `dangling 2`，不是 1） | —（`edges` / `dangling` 分别进首行） |
| testcase 路径 | plan 的 `**Testcase:**` 行首个反引号内路径 | 缺失或文件不存在 → exit 2 |
| 入参是目录 | 任一 `--plan/--prd/--spec/--testcase` 指向目录 | exit 2：`用法错：<path> 不是文件`（Q25），不判成判据红 |
| 附录 A | 标题含「附录 A」的小节内表格首列即 ID（三条件：`**Testcase:**` 行 + 附录 A 节 + 节内首列即 ID） | 缺任一 → exit 2（结构缺失，`missing/dangling` 无从计算） |
| 用例 ID | R5 并集去重 | 0 条 → exit 1 并报「testcase 未解析出任何用例 ID」（防恒绿）；**首行仍按 R7 输出 `cases 0`**（唯一计数行仍要在） |

**宽松口径的方向声明**：plan 侧功能点按出现即算（不要求出现在映射表里），误差方向是「多算覆盖」→ 只会漏报不会误报；故三条核对里只有它用宽松口径，`deps` / `map` 都是集合严格比对。

## 7 测试节（测什么 / 为什么）

测试目标：四条子命令的**判据有判别力**——每一类违规都要能由一条可重跑的构造造出红，而不是只在正常路径断言。

测试用例文件：`docs/superpowers/specs/2026-10-28-s4-plan-gate-design-testcase.md`

| 测什么 | 为什么 |
|---|---|
| `coverage` 的差集语义（缺一个 F 必红、多一个 F 不红） | 宽松口径的方向必须被钉住，否则「宽松」会成为漏报的借口 |
| `coverage` 的 `--stage` 派生（区间 `～` 展开 / 顿号拆分 / 一行一个 F） | 两种存量表形态都要能读出正确集合 |
| `deps` 的三种标题形态、两种 `Consumes` 写法、环、`dangling` | 存量三份 plan 写法不同，收紧一种就有一份读不出来 |
| `map` 的两种用例 ID 载体、双向差集、testcase 路径缺失 | 只认一种载体 = 假绿（S1/S5 会被读成 0 条） |
| `size` 三项阈值 + `--rounds` 必传（缺 → exit 2）+ 存量超限样本 | 规模指标是本段新增判据，必须有红例；`--rounds` 可缺省会留一条永久假绿通道 |
| R7 的首行格式逐字 | 门行证据靠它比对，格式漂了判据就不可比 |
| exit 2 的用法错（清单见 Q23，不自列） | 「用法错」与「判据红」必须可区分，否则施工者会拿 exit 2 当通过 |
| 功能点→任务映射表的识别（按值 / 按表头）与「无表即红」 | 半条判据的唯一机械载体；判「不适用」会让 1 个 Task + 4 个 F 记号的 plan 三行全绿 |
| 附录 A 同一 ID 多行 → `mapped` 去重 | 计数口径漂了，门行数字就不可比 |
| `--spec` / `--testcase` 指向目录 → exit 2 | 目录不是可判对象，不得判成判据红 |
| `check-gate-record` 的 ISO 时间串用例 | P2 修法必须有判别力（修前必红、修后放行） |
| `TC-A09` / `TC-E26` 改义后的语义 | 判据级口径变更，须有正反两面 |
