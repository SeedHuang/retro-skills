## 4 方案

### 4.1 `moments` 证据栏：**结构化参数**，不在文本里编码结构

**改 `buildMoment` + CLI + 模板**（**改代码**，不是零改动）。

**两处「防御性」设计（初稿没写，落地时加的）**：

| 位置 | 行为 | 为什么加 |
|---|---|---|
| `buildMoment` 收到**标量** `evidenceUp`（如直接调用时传了字符串） | 归一为单元素 + `warn` 告警 | **不静默丢数据**——初稿的 `Array.isArray(...) ? ... : []` 会把误用当成「没传」，输出退回单句形态且**一声不响** |
| `buildMoment` 与 `argAllOf` 都带**可注入 `warn`**（默认写 stderr） | 测试可捕获告警 | 否则单测会往 stderr 喷字，且**没法断言告警内容** |

**参数**：

| 参数 | 必填 | 语义 |
|---|---|---|
| `--evidence` | ✅ | **触发句**——**语义与现在完全一致**，13 条历史记录零改动 |
| `--evidence-up` | 选 | 上文一句，**可重复传任意次**，按传入顺序输出 |

**为什么「可重复」而不是 `--evidence-up2`**：单值取值 `argOneOf`（`lessons.mjs` 第 941 行）**只取第一个「有值的」同名参数**（漏值处跳过继续扫，与 `argAllOf` 同一语义，2026-10-08 OCR 指出后改）：

```js
export function argOneOf(argv, f, warn = (m) => process.stderr.write(m)) {
  for (let i = 0; i < argv.length; i++) {
    if (argv[i] !== f) continue
    const v = argv[i + 1]
    if (missingValue(v)) {
      warn(`[warn] ${f} 后面没有值，已忽略（读到：${v ?? 'EOF'}）\n`)
      continue
    }
    return v
  }
  return undefined
}
```

> **2026-10-08 补（第 11 轮 OCR）**：初版是 `argv.indexOf(f)` 只查首个 occurrence，`--evidence --evidence "原话"`（首个漏值、后一个有效）会丢掉有效值返回 `undefined`，与 `argAllOf` 的跳过语义分叉。已改为循环扫描第一个「有值」的 occurrence；对应断言见 `lessons.test.mjs` argOneOf 测试 ⑦。

若定义 `up` / `up2` / `up3`，**「有几句上文」就变成靠命名约定猜**——**跟被否的分隔符方案是同一个毛病：结构藏在约定里**。改成收集全部同名值后，**有几句 = 传了几次**。

> **2026-10-08 补充（review 第6 轮 OCR 指出，已实测复现）**：单值取值原先是 CLI 块内内联的 `argOf`，**漏值判定只有多值那边有**——于是 `moment add --evidence --project foo` 会把 `--project` 当成逐字原话写进证据栏（实测产物 `- 证据（原话）：\n  > --project`），且**零告警**，而那一栏的语义是「用户原话，一个字都不许被污染」。现已抽成导出的 `argOneOf`，与 `argAllOf` **共用 `missingValue` 同一个判定**——两边各写一份必然再次分叉。

**实现口径（必须保序，不许只取前 N 个）**：

> **⚠️ 落地时签名调整为 `argAllOf(argv, f, warn)`**（初稿写的是 `argAllOf(f)` 直接读 `process.argv`）——**改成 argv 入参是为了能单测**（`process.argv` 在测试里没法构造）。`isMain` 块内用 `const argAll = (f) => argAllOf(process.argv, f)` 包一层。**下面的代码是落地后的实际形态**（2026-10-08 按代码同步：初稿写的 `String(v).startsWith('--')` 已被实测推翻，见下面注）：

```js
/** 漏值判定：单值/多值两条解析器**共用**这一条 */
function missingValue(v) { return v === undefined || CLI_FLAGS.has(String(v)) }

// 收集 argv 里全部同名参数值，**按出现顺序**返回；下一个是已知 flag 时视为「漏值」并跳过
export function argAllOf(argv, f, warn = (m) => process.stderr.write(m)) {
  const out = []
  for (let i = 0; i < argv.length; i++) {
    if (argv[i] !== f) continue
    const v = argv[i + 1]
    if (missingValue(v)) {
      warn(`[warn] ${f} 后面没有值，已跳过（读到：${v ?? 'EOF'}）\n`)
      continue          // ← 不 push：漏值时宁可少一句，也不能把 flag 当正文
    }
    out.push(v)
  }
  return out
}
```

> **注意两点**：
> ① `missingValue(v)` 这条判断是**必须的**，省了就是本节末「不吞 flag」那条失效。**它判的不是 `--` 前缀而是「在 `CLI_FLAGS` 里」**——初稿写的是 `String(v).startsWith('--')`，实测后发现那样会**静默丢掉**以 `--` 开头的合法用户原话（这一栏是逐字抄录，贴个命令行片段太常见），故改为查表；`String()` 包装仍保留（`argv` 元素在 `process.argv` 里是字符串，但 `argAllOf` 是导出函数、测试会传真数组进来）。
> ② `warn` 是**可注入的**（默认写 stderr）——**测试传收集函数即可捕获告警，不必真的往 stderr 喷字**。

> **⚠️ 这段曾长期与代码不一致而守卫没报**（2026-10-08 段二发现）：本 spec 的行号守卫靠「引用后面**紧邻**的代码块取锚点」，而这里锚点被 `> **注意两点**` 隔开 → 只判了行号上界，**内容漂了照样全绿**。守卫的锚点提取当时只认「闭合围栏紧跟首行」，多行块直接跳过——两个缺陷叠在一起，让这段错误写法活了很久。两者都已修（锚点改为取围栏内首行、不要求闭合围栏紧跟）。

**四个必须做对的点**：

| 点 | 说明 |
|---|---|
| **扫描全数组** | 不能沿用 `argOf` 的「找到第一个就 `return`」——那样**第二次传的会被静默丢弃** |
| **保序** | `--evidence-up A --evidence-up B` 里 **A 是紧邻上文的上一句**；顺序错 = 上下文错乱，**且不会报错**（静默错） |
| **不吞下一个 flag** | 若 `--evidence-up` 后面紧跟另一个 `--xxx`（漏了值），**不能把 `--xxx` 当成上文收进去**。**⚠️ 落地口径与初稿不同（2026-10-07 实测后改）**：初稿写「判 `--` 前缀」，实际改成**只跳 `CLI_FLAGS` 里已登记的 flag**（`CLI_FLAGS.has(String(v))`）。原因：这一栏的语义是**用户原话逐字抄录**，合法原话完全可能以 `--` 开头（如用户贴了个命令行片段）——按前缀判会**静默丢掉**它。`String()` 包装仍保留（`argv` 元素在 `process.argv` 里是字符串，但 `argAllOf` 是导出函数、测试会传真数组进来） |
| **空串要留着** | `--evidence-up ""` 收集到的是空串，**`argAllOf` 不过滤**（过滤交给 `buildMoment`）——职责分层：`argAllOf` 只管收集与告警，不判断内容 |

**为什么这四点要写死**：前三类是**静默失败**——传两次只落一句、顺序颠倒、吞进 flag，**跑完不报错，事后才发现上下文是错的**。**上下文错乱比没有上下文更糟**（它会让人得出错误的因果判断）。第四点（空串留着）是**职责边界**：过滤发生在 `buildMoment`（那里才有「空句等于没传」的判断依据）。

**输出形态（示例，原文取自同 session `userwords.md` 第 85–89 条，**非编造**）：

```markdown

  > [上文] 除了完整性，我记得我还有两个问题
  > [触发] 说实话，我觉得你的如何正式有效实在说场面话，具体要怎么做，一个能执行的尺子都没有
```

| 原话以 `>` 开头 | ✅ 每句固定加 `  > ` 前缀后落盘（原话在引号内，不会破引用块） |
| 上文有几句 | ✅ **由传入参数个数决定**，不靠命名约定 |

**与 `userwords` 的分工**：userwords 记「用户说过什么」（**全量、逐字、106 条**）；moments 记「哪几句合起来引发了这个情绪」（**选摘、含上文**）。**moments 的每句原文必然能在 userwords 里找到——moments 是索引，userwords 是全量。**

### 4.2 `moment add` 的 `--message`：轮次 + 有 id 就附
