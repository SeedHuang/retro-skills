# 复盘飞轮局部战术（Phase 1）：说人话 + 危害账 + 情绪锚点 + 技能复盘链 + 落地归位

> 来源：2026-10-01 设计对话（brainstorming）+ 多透镜评审（3 矛盾 / 6 盲点 / 7 优化）+ 后续多轮细化
> 战略图：本文是 `2026-10-01-retro-flywheel-blueprint.md` 的 **Phase 1 局部战术**。
> 用户裁决（2026-10-01）：落地移到 lessons 发起、一次一个；情绪当场自动记、只收集不分析；收尾**由用户触发**；画像"能主动提醒、拍板归用户"；**系统只记账/提醒收集，"改"永远归用户**。

## 1 范围

**做**（以改现有资产为主；**唯一新建：`retro-verify`**）：

1. 复盘产物：说人话 + 危害/代价账 + 删"结尾追问落地"。
2. **数据维度与量化**：维度扩到 5 个；问题加量化字段（必答 + 选答）。
3. 情绪记录 `moment`：当场自动记、**正负双向**、带 session 锚点、只收集不分析。
4. `retro-collect` 梳理：接入 moment，扩展来源规则与模板。
5. 落地归位 lessons：一次一个；**急性/慢性**判定 + **痛感指数**排序。
6. **技能复盘链**改造：评审回流不问答改；技能账本分层。
7. **KB 体积治理**：主账/归档物理分离、体积守卫、超阈值提醒、查询命令、Obsidian 友好约定。
8. 用户画像：来源扩到"提问/回答"，补"问题的权重与类别"。
9. **验证环（§14，新建 `retro-verify`）**：验收 8 维度 + 验证方法路由 + 有效性评分 + 事前预期对账 + 无效回退。

**不做**（YAGNI）：**不新建 skill（除 `retro-verify`——飞轮缺的验证环，用决策树验过）**；不做自动分析；不新建记忆系统；不做 IM 通知层（Phase 4）；不做趋势图/可视化与复制人训练；**不物理删除历史**（除价值真过期，一律走归档）。

## 3 复盘产物改造（改 `retro-analyze` / `using-retrospective`）

### 3.1 说人话（硬规则）

复盘文件**写给用户看**，遵守全局规则"大白话、讲机理、落到例子"：内部标记（`P1`、`§3-1`）**首次出现先用一句人话说明**；表格保留（记账用），但**每个问题下必须跟一段人话说明**。

### 3.2 危害"疼在哪"并入现有"优先级"列（不新增列）

**评审 P0-3 修正**：不新增"严重程度"列（会与"优先级"变成两份"多严重"）。改为**只保留"优先级"一列**，判据含：**直接后果 / 时间代价 / token 代价（注明估算）/ 触发频率**。三档：`P1（重）`后果不可逆或单次代价 ≥1h｜`P2（中）`要返工或烧不少 token｜`P3（轻）`不影响交付。

### 3.3 删掉"结尾追问落地"

`retro-analyze` 结束动作改为：「本次复盘完成。教训已记入账本（open）。落地由你在 lessons 发起。」
`using-retrospective` 收口建议**保留"要不要复盘"**（收集侧），**去掉任何"要不要落地成 rule/skill"的推荐**。

### 3.4 数据维度与量化（本轮新增）

**维度集：3 → 5**（判定标准：**能否有效获取** × **对分析是否重要**）：

| 维度 | 变更理由 |
|---|---|
| 健壮度 | 保留 |
| 产品体验 | 由"用户体验"拆分而来（产品 UX 一类） |
| **协作体验** | **拆出新维度**——moment 记的是"协作摩擦"，与产品 UX 是两类，混在一起会互相淹没 |
| 性能 | 保留 |
| **安全** | **新增**——实证缺口：L-011 是 RCE 级安全教训，却被记成"健壮度" |

**问题量化字段**（原"是否普遍"列**删除**，由"影响范围"取代）：

| 字段 | 取值 | 档 |
|---|---|---|
| **影响范围** | 单点 / 本项目 / 跨项目 / 全局 | **必答**（判断，一轮内可得） |
| **可逆性** | 可逆 / 不可逆 | **必答**（看操作性质，二分） |
| **隐蔽度** | 显式 / 静默 | **必答**（看是否报错，二分） |
| **可复现性** | 稳定 / 偶发 / 不可 | **选答**（需多次观察，未知就留空） |

**事实量 vs 判断量分开标**：事实量（复发次数/耗时/token/讨论轮数）= 可测；判断量（严重度/影响范围/可逆性/隐蔽度）= 判断。

**问题必答清单**（防漏，缺一不合格）：① 谁受影响、什么场景触发（人话）② 后果 + 量化 ③ 根因（**标注事实 or 推断**）④ 怎么修（可执行一句）⑤ 怎么验证修好了。

**归属判据**：落**项目还是全局**看**通用性**（抽象掉项目外壳后仍成立 → 全局）。**影响范围是"信号"不是"判据"**（如"PowerShell 禁 UTF8"影响范围小但属通用 → 落全局）。

## 4 情绪记录（记录层，`moment`）

### 4.1 形态

- **存储**：`<KB>/projects/<项目标识>/<YYYY-MM-DD>-moments.md`（**按天分文件**，日期 = session 日期），当天文件一直追加，不改动前面行。
- **脚本命令**：

```
node scripts/lessons.mjs moment add --project <标识> --session <session_id> \
  --message <message_id> --date <YYYY-MM-DD> --polarity <负面|正面|认知> \
  --problem "..." --evidence "<原话，必填>" --reason "<判据：对象→意图→脏字→结论>" [--cause "..."] [--attitude "..."]

node scripts/lessons.mjs moment resolve --project <标识> --id <M-...> --solution "..." --cost "..."
```

### 4.2 极性三态（本轮新增）

| 极性 | 内容 | 去向 |
|---|---|---|
| **负面** | 用户不爽 | **规则管线**（可能立规矩）——有"解法/代价"，要结案 |
| **正面** | 用户认可 | **画像管线**——记"认可了什么 / 合什么偏好"，**不结案** |
| **认知** | 用户的提问/回答暴露的倾向 | **画像管线**——记"倾向 + 原话证据"，**不结案** |

**为什么记正面**：正面告诉你"什么管用"；**画像只有负面 = 投诉日志，不是人物画像**。
**为什么记认知**：提问/回答是**事实级**证据（比推断的"风格信号"强），暴露"关心什么、怎么决策"。

### 4.3 三钥匙（评审 P0-2 修正）

| 钥匙 | 角色 | 来源 |
|---|---|---|
| `session_id` | **主（必填）**——定位 session | 当场拿到 |
| `message_id` | **可选精定位**——能拿到就填，可定位到条 | 当场拿到 |
| `时间` | **辅（兜底）**——缩小范围 | 脚本给 |

**为什么 message / 时间是辅 / 可选**：memory 记的是"**摘要生成时间**"、会滞后、分钟级不唯一——单靠时间只能缩小范围、不能定位到条；`message_id` 能精确定位到条，但**当场未必拿得到**，故为**可选**（拿到就更好）。

### 4.4 自带快照 + 尽力指针（关键更正）

工具只存**摘要**（`~\.trae-cn\memory\...\session_memory_*.jsonl`），**不是原文**，且有 `.cleanup` 可能被清。因此：

- **自带快照（承重）**：**原话（引用）+ 一句话场景 + 我的失误** —— 独立可读，不依赖外部文件；
- **指针（尽力而为，非承重）**：`session_id` + `message_id`；
- **保留说明**：注明"外部指针可能被工具清理，**以快照为准**"。

### 4.5 硬护栏

1. 写库前查 `<KB>/.migrating`（存在即拒绝）；2. `--project` 沿用既有标识清洗（防路径穿越）；3. `resolve` 找不到 ID / 文件被改坏 → **报错、不改文件**；4. **原子写**（临时文件 + 改名）；5. 项目目录不存在 → 自动创建；6. **无 BOM**；7. 只追加、只改指定条目；8. `--polarity` 必填；负面必填 `--problem` 与 `--evidence`（原话，不猜原因），`--cause/--attitude` 可选且须标注推断；正面/认知必填 `--problem`（认可/倾向）与 `--evidence`（原话）；**所有极性必填 `--reason`（判据：对象→意图→脏字→结论 的推导）**。

### 4.6 格式（按极性分支）

```markdown
## M-2026-10-01-1
- 极性：负面｜项目：<标识>｜session：<id>｜message：<id 或 —>｜时间：…
- 状态：未解决
- 问题：<一句话>
- 判据（思考过程）：<对象→意图→脏字→结论 的推导，如「对象=人（主语你+否定理解）→ 无脏字 → 核心意图=贬 → 负面」>
- 证据（原话）：
  > <原话，必填>
- 原因（推断）：<可选，须标注推断>
- 态度（推断）：<可选，须标注推断>
- 解法：（结案补）｜代价：（结案补：讨论轮数 / 时间）

## M-2026-10-01-2
- 极性：正面｜项目｜session｜message｜时间
- 认可 / 倾向：<做法 / 倾向>
- 判据（思考过程）：<对象→意图→脏字→结论 的推导>
- 证据（原话）：
  > <原话>
```

> **2026-10-02 修订**：负面必填从「原因/态度（推断）」改为**必填原话（evidence）**——不猜原因/态度，猜的只作可选且须标注推断（判定公式见 `retro-collect/assets/userwords-template.md`，moments 与 userwords 共用一套）。正面 / 认知 **无状态行**（不结案）。此格式与 `buildMoment` 实现**逐字一致**。

### 4.7 边界（只收集，不分析）

- **我检测到（负面/正面/认知）→ 当场轻标，不问、不打断**；**克制**：只记"有信息量的"，不是每句都记。
- **分析/提炼不在收集时做**——并入 lessons 落地分析（§6）。
- **收尾由用户触发**；不自动。
- `retro-collect` 读 `<日期>-moments.md`，只把**计数**写进事实包（纯计数、不评价）。
- **情绪必须当场抓**（工具不记情绪）；**提问/回答**工具记了 `intent`，可事后回捞，但**当场轻标最稳**（防摘要被清）。

## 5 事实包梳理（改 `retro-collect`）

**边界**：仍然**只收集事实**，不因接入 moment 变成分析引擎。

| 动作 | 变化 |
|---|---|
| 多读一个文件 | `<日期>-moments.md`（筛本 session 条目） |
| 多读一个外部源（可选） | `memory\...\session_memory_*.jsonl`（拿 session_id/时间做锚点） |
| 多写一栏 | facts.md 的 **§4 情绪点**；§2 计数加"情绪点数 / 未结案数" |
| 多一条来源类型 | **对话原文**（原话）——情绪点没有命令输出 |
| **不写** | `<日期>-moments.md`（记录器的事）、retro.md、ledger.md |

**数据结构**：

```markdown
# 事实包：<session/阶段标识>
- 范围｜生成｜session：<id>｜message 范围：<首>..<尾>
## 1 时间线锚点   ## 2 计数（含情绪点数/未结案数）   ## 3 异常事件
## 4 情绪点（| # | moment ID | 极性 | 时间 | 触发原话 | 状态 | 来源 |）
## 5 证据清单   ## 6 未取得的数据   ## 7 声明（不含判断/方案/优先级）
```

**§4「状态」列**：负面填 `未解决` / `已解决`；**正面 / 认知填 `—`**（不结案）。

**文件结构**：

```
D:\Seed\lessons\projects\<项目>\
  ├─ <日期>-moments.md        ← 记录器写；collect 只读（按天，日期=session 日期）
  ├─ <日期>-userwords.md     ← 用户触发写（按天）
  ├─ <日期>-<sesshort>-facts.md   ← collect 产物（加 session 短码，防同日撞名）
  ├─ <日期>-retro.md         ← analyze 产物
  ├─ ledger.md               ← 主账（热）
  ├─ ledger-archive-<年>.md   ← 归档（冷，见 §8）
  └─ rules-history\
```

## 6 落地归位 lessons + 急性/慢性 + 痛感指数

```
你在 lessons 发起（一次一个 skill / 一类问题）
  → 读四样：账本 + 历史复盘 + moments（锚点） + 用户画像
  → 出分析 + 大白话方案（方案先过画像自检，§9）
  → 你判断 → 合理 → 到 retro-skills 改对应 skill → 完工 ledger：open → landed
```

**一次一个**。**触发（C 方案）**：平时绝不主动提；只有 ① 你主动发起，或 ② 开工巡检发现同类复发，才提。

### 6.1 急性 / 慢性（历史检索）

**分析前先在全历史检索"同族"**：**急性**（只此一次）= 孤例 → 记 `open` + 观察，**别急着立规矩**；**慢性**（历史 ≥2 次）= 复发 → 跨例找共性根因 → 系统性方案。
**诚实边界**：① "相同/近似"是**判断**，**归簇要用户过目**；② "只见过一次"≠"真孤例"，可能只是当时没记全。

### 6.2 痛感指数（自拟排序工具）

`痛感 = 事实量（复发次数 × 平均代价）× 判断权重`。**权重来自画像**（§9）。**明确标注为自拟指数、用于排序，非客观测量。**

## 7 技能复盘链的改造（本轮新增）

### 7.1 评审回流：删掉"问要不要改"（改 `review-flywheel.md`）

现状第 2 步「现在优化还是稍后批量？」会**把主线任务拉歪**。改为：① 先记录不阻塞（保持）→ 往 `skills/<技能名>/ledger.md` 记（open）；② 删掉那句 → 顶多"已记账（ID），落地留 lessons"；③ "改"完全交给 lessons。**记要快（自动、不打断），改要等（你在 lessons 发起）。**

### 7.2 技能复盘触发说明（改 `evolving-skills`）

- 技能复盘的"改"统一由 **lessons 落地分析**派工（§6）；`using-retrospective` 的 ③④（开工巡检、收口建议）**只提议收集/复盘**，**不得夹带"要不要落地成 rule/skill"**。
- 记：自动/当场；改：用户发起、一次一个。

## 8 KB 体积治理（本轮新增）

### 8.1 热冷分层

| 数据 | 热（默认读） | 冷（归档，默认不读） | 移动信号 |
|---|---|---|---|
| ledger 条目 | `open` | `landed`/`moved` | 状态改变时 |
| 候选与推迟项 | 未命中/未做 | 已升格/已关闭 | 处置完时 |
| moment | 未解决 / 未提炼 | 已解决 / 已提炼 | 结案/提炼后 |
| session 产物 | 最近 N 天 | 老的 | 阈值 |

**核心护栏：冷层永不读进上下文**——库再大，上下文成本不变。

### 8.2 主账 / 归档物理分离

```
ledger.md              ← 热：以 open 为主  小、常读
ledger-archive-<年>.md ← 冷：landed 历史   大、平时不读（仅慢性病分析时脚本查）
```

**只增不删**保留（历史留痕），但**主账要小**。

### 8.3 体积守卫 + 超阈值提醒

per-skill / per-project：主账超阈值（建议 >100 行 或 **open 条目 >20**）→ **主动提醒**「<目标> 主账已 N 行 / M 条 open，**建议尽早复盘收口**，否则每次读它都白烧 token」。**提醒而非自动删**。

### 8.4 候选与推迟表：处置完移归档

`index.md`「候选与推迟」是**待办清单**：活的留主表，升格/关闭的移到「已处置留档」。主表只显示"当前在观察什么"。

### 8.5 查询命令（补缺口）

```
node scripts/lessons.mjs show <ID>        # 查单条状态与落点
node scripts/lessons.mjs find <关键词>     # 按关键词列相关条目及状态
```

### 8.6 冗余列清理（本轮新增）

| 列 | 处置 | 理由 |
|---|---|---|
| **"对象"列** | **删除** | 与"载体"列**取值相同**（L-RS-1：对象=skill 载体=skill）——第二份真相 |
| **"是否普遍"列** | **删除** | 被 §3.4 的"影响范围"取代 |

### 8.7 Obsidian 友好约定（可选，本轮新增）

**把 `lessons` 开成 Obsidian vault（用法 A：当"看的窗口"，数据仍纯 markdown）**：

- 白拿**反向链接**（规则 `> 来源：L-019` ↔ 账本条目，自动互链，替代手动 grep）、图谱、搜索、tag；
- **约定**：引用统一写 `[[L-019]]` 或 `来源：L-019`（脚本兼容两种）；维度/状态可作 tag；
- **红线**：**不让 Obsidian 专有语法成为数据唯一载体**（防绑死 app、脚本难解析、迁移难）；**查询入口二选一**（脚本 or Dataview，不可两套）。

## 9 用户画像（本轮重写）

**来源三轴（客观度递增）**：

| 来源 | 内容 | 客观度 |
|---|---|---|
| 协作风格信号（我方推断） | "他在意什么" | 判断（低） |
| moment 情绪点 | 认可 / 不爽 | 事实 + 推断（中） |
| **提问 & 回答（新增）** | **用户原话** | **事实（高）** |

**画像的两种作用（本轮修正——不再说"不补问题"）**：

1. **补"问题的权重与类别"**：给 §3.4 量化字段**加权**（用户更在意可回滚 → "不可逆"权重更高）；"用户高频摩擦的类型"**本身是一类问题**。
2. **补"方案适配"**：方案先过画像自检（"他会在意什么？会反对什么？"），不对先改。

**落点**：写进 `%userprofile%\.trae-cn\memory\user_profile.md`；**每条结论必须引一句用户原话当证据**（可追溯）；**只提炼、不存全文**。**提炼在 lessons 落地分析时做**（用户发起），收集自动、不打扰。

## 14 验收与验证（新建技能 `retro-verify`）

> 飞轮缺的一环：**落地之后，怎么知道改对了、改管用了**。没有它，飞轮是开环。
> 新增技能 `retro-verify`（用 `retro-institutionalize` 决策树验过：多步技法 + 现有资产无此环节 → 该建）；`using-retrospective` **分发**到它。

### 14.1 验收维度：落地方案必带 8 项

| # | 维度 | 要回答 |
|---|---|---|
| 1 | **有效性判据** | 什么算成功——**必须是一条能跑 / 能查的检查**；给不出 → 写"无法验证"，**不许用"应该会好"占位** |
| 2 | 副作用面 | 会不会伤到别的场景 / 流程 |
| 3 | 成本 | 每次对话多花多少 token / 时间 |
| 4 | 作用域 | 全局 vs 项目；无条件 vs 按需 |
| 5 | 冲突 | 和既有 rule / skill 打不打架 |
| 6 | 可观测 | 怎么看到它生效 / 失效 |
| 7 | 代价 / 风险 | — |
| 8 | 可逆性 | 能退吗、怎么退 |

### 14.2 验证方法：按"能不能机械判定"选（= 按载体选）

| 档 | 问题特征 | 方法 | 强度 |
|---|---|---|---|
| **A 能跑** | 复现 = 跑命令 / 输入，得同样坏结果 | **写成测试 / lint**，跑它 | 最强（真"证实"） |
| **B 能查不能跑** | 复现 = 某类话 / 行为再现 | **复发信号（正则 / 关键词）+ 机会数** | 中（至多"未证伪"） |
| **C 都不能** | 无信号 | **人工观察**，标"无法自动验证" | 弱（不装） |

### 14.3 指标与读法（每个带方向）

| 指标 | 方向 | 读法 |
|---|---|---|
| 复发率 = B / A | **↓ 好** | 0% 最好 |
| 新问题率 = N / A | **↓ 好** | 越低越好 |
| 认可率 = P / A | **↑ 好** | 越高越好 |
| 机会数 A | **中性** | 只当样本门槛，**不代表好坏** |

**方向归一**：定档前统一成"改善量"（`+` 恒为变好）。**主判据 = 复发率**；新问题率 / 认可率是**警告灯**，与主判据方向冲突 → **结论降级 + 加注**（如"变好，但有代价"）。**只纵向比**（同一目标前后），**不横向比**。

**机会数 A 怎么来**（否则评分悬空）：按载体定取数口径——**自动化** = 该检查被执行的次数；**rule/skill** = 该目标触发面内、被记录到的相关场景数（从 moments / 对话里数）。**数不出来 → 标"无法评分"，不许估**。

### 14.4 5 档（由 Δ 改善量定，不由绝对值定）

| Δ 复发率 | 结论 |
|---|---|
| ≤ −30% | 明显变好 |
| −30% ~ −10% | 略微变好 |
| −10% ~ +10% | 看不出差别（噪声带） |
| +10% ~ +30% | 有劣化趋势 |
| ≥ +30% | 明显劣化趋势 |

### 14.5 事前预期 + 事后对账

- **改之前**：必须给**有依据的预期值（区间）+ 理由**——依据 = 基线 + 历史同类改动 + 本次覆盖面；无依据 → 只给方向性预期。
- **早期没有历史预期值** → **从本次起开始记**（本次期望值即往后基线）；**完全无依据 → 只给方向性预期，且不做"预期对账"**（只做趋势，别硬凑）。
- **没有预期值 = 事后怎么都能说好 = 没验。**
- **改之后**：实测 vs 预期对账 —— 达到 / 超出 = 有效；落区间下沿 = 部分有效；明显没达到 = 无效；反升 = 劣化。
- **没达到要分清**：① 改动不行 ② 预期虚高 —— **分开说**，防归因错误。

### 14.6 置信门槛（机会数 A）

| A | 能说明什么 |
|---|---|
| 0 – 1 | **不打分**（样本不足） |
| 2 – 4 | 只定性（有无复发），分值仅方向参考 |
| 5 – 9 | 复发率量级可参考 |
| ≥ 10 | 趋势可信，可对账预期 |

**"没看到复发" ≠ "没有复发"**（可能漏记）：**A ≥ 5 且 B = 0** 才敢说"有效"；A 小、B = 0 只能说"**暂未发现复发**"。

### 14.7 复发分型 + 回退（无效 / 更差）

复发 ≠ 直接判死，先分三类：**没生效 / 判据不对 / 归类错**——每类**要拿得出证据**；**"归类错"或拿不出证据 → 交用户**。
**无效 / 更差** → **回退载体**（技能 `git revert`；规则从 `rules-history` 恢复）+ **账目 `landed → regressed`（附现场）** + 回炉。**绝不留在 landed 假装成功。**
**回退也要走用户**（它本身就是"改载体"）——**先出回退方案 + 理由，用户确认后才退**；顺序固定为「**先退载体 → 后改账目**」，崩了可重跑（幂等；账目以载体实际状态为准）。
**停不停看"有没有新东西"**（不看试了几次）——原地打转才熔断。

### 14.8 触发与工具（分工）

- **触发**：`using-retrospective` **分发**到 `retro-verify`（用户说"过一遍 <目标> 的有效性 / 看分数趋势"）。
- **算数**：命令 `lessons verify record|score|trend|expect <目标>` 住 **`lessons.mjs`（KB 解析唯一处）**；`retro-verify` 的脚本**调它的 CLI 取数**，**不 import**（避跨技能"单装扑空"）。
  - **「目标」口径**：**技能名**（验 skill）或 **KB 条目 ID**（验某条 rule / automation），二选一。
- **台账**：每个目标一份 `effectiveness.md`，落**该目标在 KB 的归属目录**（技能 → `<KB>/skills/<技能名>/`；rule / automation 条目 → `<KB>/projects/<项目>/` 或 `<KB>/universal/`）——**不是** retro-skills 仓库的技能目录（那里要保持发布纯净、不放个人数据）；台账**纳入体积治理**（§8：超量归档）。表结构：

  | 期 | 日期 | 机会A | 复发B | 新问题N | 认可P | 事前预期（区间） | 复发信号 | 备注 |
  |---|---|---|---|---|---|---|---|---|
  | 改前 | YYYY-MM-DD | 6 | 4 | 1 | 0 | — | `<正则 / 命令>` | 基线 |

  计数（A/B/N/P）由验证时**从 moments / 账本数出**；**数不出 → 该期标「无法评分」（不填假数）**。
- **何时跑**：阶段收口 / 验证触发时。
