# 开发工作流主干：五段顺序、出口签字与长文取证

> 来源：PRD `docs/prd/20261024073606-dev-workflow-mainline/index.md` §4 / §6 / §3.3；S1 spec `docs/superpowers/specs/2026-10-24-dev-workflow-skeleton-design.md` §5｜落地：2026-10-24
> 判据锚在 PRD，本规则只写义务句与出处，不复制 PRD 正文。

## 核心判据（R1–R9）

**唯一证据载体**：`docs/devworkflows/<YYYYMMDDHHmmss>-<任务名>/gate-record.md`（一任务一份；进 ① 时建任务目录），固定表头 = `段 | 出口判据（逐条） | 核了什么（命令输出首行 或 path:line） | 申报人 | 签字人 | 结论`；格式唯一源 = `skills/dev-workflow/references/gate-record-template.md`。R1–R9 全部指它；本规则不自存任何名单或状态标记——段名单与各段签字人以 PRD §4 段表为唯一来源。

**规则的边界**：R1–R9 只管「主干怎么走」。不写「怎么评审」（调用 `parliament` 技能）、不写「怎么拆 spec」（调用 `prd-to-specs` 技能）、不写「怎么写 testcase」（判据以 `spec-testcase-gate` 规则为准）——重复即漂移。

**为什么每条都要可机械判**：判据停在「说明里点出」时，规则每轮加载却判不出来，等于没有约束。R1–R9 的右列各自给出唯一判定动作（数行数 / 比两个字段 / 判节存在性 / 比集合 / 跑命令看退出码），能机器判的部分一律机器判。

## 适用范围（不因来源豁免）

- 范围：`docs/prd/`、`docs/superpowers/specs/`、`docs/superpowers/plans/`、代码实现与交付审计这五类主线产物。
- 不因来源豁免——子代理、脚本、模板、AI 生成的产物同样要过；S1 之后新写的任务一律按五段顺序走。
- 只管主干顺序与签字归属，不改各段内部做法（拆 spec、评审、写用例的具体流程归各自技能）。

## 冲突裁决

与「这次先快速交付，回头补 spec」「先写代码再补 PRD」「签字人顺手代签」冲突时，以本规则为准。拿不准先停下说明，等用户确认再动。

## 例外

只有两类：

**① 存量 spec 不追溯**：**本规则生效（2026-10-24）前已定稿的存量 spec 不追溯**——按 `spec-testcase-gate` 规则的存量例外处理（用户 2026-10-18 裁定「存量不用管，逐个升级」，此处只承接该裁定，不另立口径）。

进 ③ 时必须在本段 plan 或交接材料里点名两件事：① 存量豁免的是哪几份 spec（写文件名）；② 升级时点 = 该 spec 下一次被修订并进入 plan 的那一刻（事件型，可核），或用户给出的具体日期。禁止把时点写成「看情况」这类不可核的表述。

**② 技改免议会（2026-11-05 用户裁定）**：功能点 ID 集合 diff 为空（无新增 / 删除 / 改判功能点）的技术改造，经用户在 ① 入口点名「本任务按技改走」，可免议会 #1 / #2。**同批允许新增交付物**（模板 / 目录档 / 校验脚本 / 测试）——「无新增交付物」不属本例外条件（若照抄 §4.2 的字面条件，本批自己就不合格；见 PRD `docs/prd/20261105160504-devworkflow-signoff-dir/index.md:21`）；只不准新增功能点。豁免只免议会、不免签字：① 行签字人仍按段表，② 行签字人 = 审计，并同批附 `senior-sdet` 与 `reviewer-audit` 两份审查结论（正文落 `docs/reports/<批次>/`，账内写 `path:line`）。① 入口未点名 → 不得事后追认；功能点集合 diff 非空 → 回 PRD 重签 §0（R5）。

## 触发时机

- 进入任一阶段（①、②、计划门、③、④、⑤）之前；
- 写或改本任务目录下 `gate-record.md` 的任一行时；
- 把 spec / plan 送议会、或在 plan 阶段想新增 spec 里没写的设计时；
- 引用对话记录、评审账、规范原文下结论时；
- **改任一判据级口径（验收判据 / 权限语义 / 错误码 / 计数口径 / 命名）时**（R8）；
- 交接、复盘或审计发现「出口未签就进下一段」时。

## 验证

两条自查命令，可在仓库根直接粘贴执行：

① 逐任务目录判：每份 `gate-record.md` 的签字人与申报人**无交集**的行数 = 总行数（表头与分隔行不计；两格按 `、 + ＋ ， , ／ / （） () 空白` 拆词后求交集）+ 签字人属段表「谁签」列（旁路 ①② 行 = 审计）+ 「拆 spec 中」数据行 ≤ 1 + 至少 1 条 ① + 计划门签字人含审计 + 段值白名单 + 四列上限 + R9——合并为一个脚本：

`node scripts/check-gate-record.mjs`

（**为什么不再用内联 `node -e`**：旧命令按「整行含『申报人』即当表头丢弃」过滤，正文里提到该词的数据行会被静默漏核 → 自检恒绿〔2026-10-28 代码审查 P1〕；脚本改为按**单元格**判表头，并复用 `markdown-rows.mjs` 的 `splitRow` 切分单元格、`fenceMask` 跳过围栏内的示例表。**解析 fail-closed（2026-11-05 sdet P0）**：表被非表格行截断后出现的六列签字行报「孤行」、围栏未闭合直接判红、占位行只看首格 `[[...]]`（不再整行含 `[[` 就丢）。**为什么改判目录**：签字账是项目文档，不是技能内容——`skills/` 只留模板，`tasks 0` 与任务目录缺 `gate-record.md` 都 fail-closed 判红。）

② 改判回扫（R8）——改过任一判据级口径后必须绿：

`node scripts/scope-sweep.mjs --check`

（**不要**写 `npm run doc:sweep -- --check`：PowerShell + npm 10.9 会吞掉 `--` 后参数，跑默认分支恒 exit 0，判据等于没有。）

判据：① `tasks N rows R bad 0` 且末行 `gate-record ok`；② exit 0（`sweep ok`）。任一不满足即本规则未过，不得进入下一段。
