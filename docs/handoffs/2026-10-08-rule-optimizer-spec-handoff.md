## spec 摘要（实现方必读）

### 要做什么

建一个新技能 `rule-optimizer`，用来**优化 `my-rules/rules/` 里的 13 条规则**：统一头部格式、精简冗余措辞、量化评分、防劣化。

### 关键设计决策（§0 已确认边界，实现时不得推翻）

| # | 边界 | 说明 |
|---|---|---|
| B1 | **删判据 = 绝对禁止** | 没有「问用户就能删」这一档。用户明确纠正过我这一点 |
| B2 | **体积是防废话的秤，不是限高栏杆** | 规则随场景长大是正常的；超预算只触发废话审查，不强制砍 |
| B3 | 规则格式统一**不是官方要求** | 官方只管 SKILL.md 管不到 rules；依据是自定义规则「同含义同标记」 |
| B4 | 来源行留「类型+日期」，砍历史叙述 | 保留权限标记，砍合并记录/用户原话 |
| B5 | skill 是**改稿器**不是报告生成器 | 每类违规要配可复制的改法（处方） |
| B6 | 语义判断**不自动化** | 脚本只查形式；判据糊没糊由 AI 按三检验判断并写进报告 |
| B7 | **不引入外部打分器** | Schliff(4 stars)/PromptQC(0.2.0)/instruction-lint(Alpha) 权威性不足 |

### 核心判据：三检验（§4）

一条文字「可删」当且仅当删掉后：①判据不变 ②边界例子不变 ③跨规则引用不断。三条全过才可删；任一不过则禁止删。检验 #3 可脚本化，#1 #2 需 AI 逐条判断。

### 评分体系（§6）

五个维度各 0–20 分：头部规范 / 层级规范 / 来源精简 / 体积健康 / 引用完整。分级 90+ 健康 / 70–89 预警 / <70 超标。**但分级只作提示，不构成「必须优化到某分」的目标。**

### 硬闸门（§5.3，写进 SKILL.md 顶部）

禁止删判据 / 改判据措辞须报告改前改后等确认 / 禁止为凑分数改规则 / 禁止把语义判断交给脚本 / 删冗余必须写出三检验过程。
