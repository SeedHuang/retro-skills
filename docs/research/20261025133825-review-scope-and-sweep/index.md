## 1 用户原话与本意（逐条）

| # | 用户说的 | 本意（我的理解） |
|---|---|---|
| 1 | 「改标题，肯定是要连内容和相关关联的地方都要看一下，以防漏改」 | 改一条口径不是改一处字面，而是改「这句话在全文（含关联文档）的所有表达」。这要有**影响面清单**，不能靠记性 |
| 2 | 「改完后文字不能变这个问题是不是老问题，我之前都说了，重要的表达的意思不变，不要求文字和改之前一致」 | 这是**已定裁定的复发**：裁定时只落到一处，旧说法没清掉 | 
| 3 | 「所以这个问题在哪里呢？不是简单的你不会算数吧？」 | 数字对不上不是算错，是**同一事实有三层数法**（数组几项 / 摊开几项 / 卡上几项）却没写清哪层用哪个数 |
| 4 | 「你这个问题不是因为规则没改导致的吗？」 | 文档互相打架的根因是**上游签字件与规则没有同批改**，不是下游没写对 |
| 5 | 「他们不能只负责看他们需要负责的地方吗？全局不是你和审计要做的事情吗？他们只是负责协助你」「token 要花好几倍」 | 后端/测试/安全**只按处协助**；全局一致性 = 主 agent + 审计；禁止把全文通读摊给所有席位 |
| 6 | 「改之前是不是列出要改的内容，让审计同学一起帮你找？或者有其他方案吗？」 | 改前冻结清单 + 审计机械核；并要工程化，不只靠人工 |
| 7 | 「后面我们需要把这些全都工程化而不是我和你说一次做一次」 | 上述全部要变成**可重复运行的工具/规则/流程**，不是一次性动作 |

## 2 结论（已定，作为后续实现依据）

### 2.1 职责分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 主 agent | 全局一致性（同一事实只留一处 + 其余引用）、列影响清单、跨文件对账 | 自己判自己写的东西「改对了」 |
| 审计 | **机械核「找全没有」**：跑关键词扫描、比对命中处与派活清单、核计数 | 判技术对错、判「该改还是该留」 |
| 后端 | 按处判：契约 / 数据流 / 错误码 / 依赖方向 | 通读全文；判用例判别力 |
| 测试 | 按处判：判据能不能跑、会不会恒绿/恒红、覆盖够不够 | 通读全文；判权限等价 |
| 安全 | 按处判：权限等价 / 注入面 / 最小权限 | 通读全文 |
| 红线 | **禁止自写自判**；每一处处置必须落到具体席位的名下；P0 级口径（验收判据、权限语义）**双签**（一人判对、一人判全） | —— |

### 2.2 复核范围采「混合」（方案 C）

- **首轮**：相关席各通读一次全文（已发生，32 族由此而来）。
- **后续轮**：只读**增量 + 派给自己的切片**，不再全文通读。
- **全局**：主 agent 列清单 + 审计机械核。
- **否掉 B（只按处派活）**：省 9 成，但「找全」押在清单完整性上，而这三轮最大病根正是「清单只列被点名处」。
- **否掉 A（全席全文 × 2 遍）**：首轮已兑现覆盖，重复通读边际收益近零。

### 2.3 成本实测（精算席，全部带取数命令）

| 项 | 实测 |
|---|---|
| spec | 308 行 / 22,282 字符 |
| testcase | 3,209 行 / 247,065 字符 / 77 条（每条 ≈ 41.7 行 ≈ 1.07k token） |
| 全文一次 | 3,517 行 / 269,347 字符 ≈ **90k token**（上界 115k；口径 = 字符 ÷ 3） |
| A 全席全文（评审 + 复核） | ≈ **720k / 轮** |
| B 按处派活（+兜底） | ≈ 76k（+22k = 98k）/ 轮；拦截 19/32（含兜底 28/32） |
| C 混合 | 首轮 ≈ 440k；后续 ≈ **80k / 轮** |

## 3 工程化清单（这是本文件的主产物）

> 原则：能机器判的不靠人；每条给出「落点 / 输入 / 输出 / 判据 / 优先级」。

| # | 要工程化的东西 | 落点 | 输入 | 输出 / 判据 | 优先级 |
|---|---|---|---|---|---|
| E1 | **口径扫描器** `sweep.mjs` | `scripts/`（`npm run doc:sweep -- "<词1,词2>"`） | 关键词表 + 扫描范围（spec / testcase / PRD / S5 / rules） | 每个命中处的 `file:line` + 上下文；改前改后各跑一次 → 命中只减不增；每处必须有处置标注（改 / 引用 / 历史保留） | P0 |
| E2 | **影响清单模板**（impact sheet） | `skills/parliament/assets/impact-sheet.md` | 要改的口径 | 六列：口径 / 搜索词 / 命中处 / 处置 / 判的人 / 核的人；改前冻结、改后附复扫结果 | P0 |
| E3 | **审计机械核** `facts-scan` | `scripts/`（`npm run doc:facts-scan`），并入 `check-all` 可选段 | 族关键词表（可维护的 JSON） | 输出命中处清单；与影响清单 diff：清单缺处 = 审计不通过 | P0 |
| E4 | **口径登记表** | spec 模板 / `skills/dev-workflow` 资产 | 已定裁定 | 每条裁定只在「已定口径」节写一次，正文只引用；机器判：同一裁定关键词在正文出现 >1 次且未带引用标记 → 报警 | P1 |
| E5 | **三层计数命名** | spec 模板 | 路径清单 | `arrayCount` / `itemCount` / `cardCount` 三个名字，禁止写算式；机器判：文档内出现 `21`/`22`/`23` 必须能对上名字 | P1 |
| E6 | **改判回扫上游**（规则化） | `rules/dev-workflow-mainline.md` 新增一条 | 一次改判 | 同批 diff 必须包含上游文件（PRD / 已签 spec / 规则）里所有相关命中的处置；缺 = 违规 | P0（需用户批） |
| E7 | **议会复核派活**（流程化） | `skills/parliament/SKILL.md` + `assets/` | 影响清单 | 复核轮只派「处」，不派「全文」；审计机械核；P0 双签；禁止单席连审 | P0 |
| E8 | **卡数对账** | `check-all.mjs` 的 `.session` 段或议会账本检查 | `cards.md` + `problems.md` | 卡片数 = 卡文本数（每个 `Q-x-` 编号在 `cards.md` 有正文）；台账声明的不计入项必须显式写在文件里 | P2 |
| E9 | **引用一律用稳定锚点**（本轮新增，实测代价最大） | spec / testcase 模板 + `sweep.mjs` | 文档间引用 | 文档互引只许用「§节号 / V-x / 不变量 N / 错误码」；**禁止 `文件:行号`**（本轮 4 次改 spec 共导致 testcase 里 150+ 处行号漂移，每次都要整轮校准）。行号只用于**一次性取证**（gate-record / 审计证据），且必须与内容摘要同写 | P0 |
