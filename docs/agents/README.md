# 角色席索引

| 席名 | 职责一句 | 维度 | 输出类型 | 链接 |
|---|---|---|---|---|
| reviewer-audit | 当议会评审需要过程标准核对、轮际对账或交付审计 | 独立（标准核对） | audit | `docs/agents/reviewer-audit.md` |
| reviewer-product | 当议长调度对 PRD、spec、plan 做产品视角评审 | 产品设计 | issue-card | `docs/agents/reviewer-product.md` |
| reviewer-interaction | 当议长调度对 PRD、spec、plan 做交互视角评审 | 产品设计 | issue-card | `docs/agents/reviewer-interaction.md` |
| reviewer-ui | 当议长调度对 PRD、spec、plan 做 UI 视角评审 | 产品设计 | issue-card | `docs/agents/reviewer-ui.md` |
| reviewer-frontend | 当议长调度对 spec、plan、技术方案做前端实现视角评审 | 技术实现 | issue-card | `docs/agents/reviewer-frontend.md` |
| reviewer-backend | 当议长调度对 spec、plan、技术方案做后端视角评审 | 技术实现 | issue-card | `docs/agents/reviewer-backend.md` |
| reviewer-ops | 当议长调度对 spec、plan、技术方案做交付运维视角评审 | 技术实现 | issue-card | `docs/agents/reviewer-ops.md` |
| reviewer-qa | 当议长调度对 spec、plan、技术方案做测试视角评审 | 技术实现 | issue-card | `docs/agents/reviewer-qa.md` |
| reviewer-ai | 当议长调度对 rule、skill、agents、含 AI 指令的文档做 AI 工程视角评审 | 技术实现 | issue-card | `docs/agents/reviewer-ai.md` |
| reviewer-security | 当议长调度对任意文档做安全风险视角评审 | 安全风险 | issue-card | `docs/agents/reviewer-security.md` |
| reviewer-actuary | 当议长调度对任意文档做成本与收益视角评审 | 成本考量 | issue-card | `docs/agents/reviewer-actuary.md` |
| reviewer-reader | 当议长调度对描述性、记录型、任意文档做读者视角评审 | 产品设计 | issue-card | `docs/agents/reviewer-reader.md` |
| detective-observer | 每轮答辩结束后由议长调度做行为核实 | 独立观察 | observation | `docs/agents/detective-observer.md` |
| evidence-reader | 当需要通读长文并交出可核对的原文与行号（交接取证、事实基线回核） | 取证 | evidence | `docs/agents/evidence-reader.md` |
| senior-sdet | 当需要为 PRD、spec 设计并编写测试用例（testcase.md），或专门找出被忽视的边界与失败场景；不用于：修改业务代码、写实现方案、或只读的议会评审（那走 reviewer-qa） | 测试设计 | testcase | `docs/agents/senior-sdet.md` |
| speaker | 当议会评审轮需要按程序点名、收卡与判定本轮结束 | 程序 | proceeding | `docs/agents/speaker.md` |
| respondent-architect | 当答辩需要按项目技术栈核实问题卡并汇总统一口径 | 架构 | defense | `docs/agents/respondent-architect.md` |
| respondent-dev | 当答辩需要用命令复现问题卡所述行为并给出核实结论 | 研发 | defense | `docs/agents/respondent-dev.md` |
