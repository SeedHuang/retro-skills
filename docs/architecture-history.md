### 9.1 V2 实测结果（2026-09-28）

**结论：`ais` 在本机不可用，根因是 Windows「开发者模式」从未开启。**

- **取数命令**：`ais use D:\Seed\my-rules`
- **原始错误**：`EPERM: operation not permitted, symlink 'D:\Seed\my-rules' -> 'C:\Users\HuangChunhua\.config\ai-rules-sync\repos\my-rules'`
- **环境实测**：Windows 11 专业版；`HKLM:\...\AppModelUnlock\AllowDevelopmentWithoutDevLicense` **不存在（从未开启）**；当前进程**非管理员**
- `ais` 本身装成功了（`0.10.0`，npm 全局前缀在 D 盘，装它不需要管理员），但**一跑就失败**——它在"配置仓库"这一步就要建 symlink

**这个根因同时解释了之前所有 symlink 相关的怪事**：`npx skills add` 的 symlink 模式退化成 copy，是同一个原因。

**两条路**：

| 路 | 做法 | 代价 / 收益 |
|---|---|---|
| **A. 开开发者模式**（推荐） | Windows 设置 → 系统 → 面向开发人员 → 开发人员模式，打开 | 一次性设置。之后 `ais` 与 `npx skills add` 的 symlink 都能用。**需重启终端/IDE 才生效**（权限在登录时授予） |
| **B. 自写 junction 脚本** | PowerShell `New-Item -ItemType Junction`（已实测：**junction 不需要管理员**、**可跨盘**） | 不用改系统设置；但只有"同步"这一件事，没有 ais 的 `status` / `check` / `update` / `import` 那一套 |

**后续（2026-09-28 已定）**：开发者模式**已开启**（符号链接随后实测可用）；但 ais 即使能用也**装不到 Trae CN 的目录**（它认的是 `~\.trae\`，见 §9 表格 V2），所以**已卸载**，最后一公里由 `sync.mjs` 自建（见 §8.1）。
