> 本文件是 rule-inspector 的判据全集，内容照抄 spec `2026-10-09-rule-suite-design.md` §2（单源一致，逐字落地）；`scripts/score.mjs`（Task 3）按此实现，rule-writer（Task 5）亦引用本文件。

## 2. 判据全集（评分维度）

### 2.1 来源类型（权限标记，管「谁定的」）
| 类型 | 现有规则 |
|---|---|
| `用户当场指令` | `global-ask-before-acting`、`plain-language-to-user`、`docs-convention`、`how-i-must-reason` |
| `评审第 N 轮` | `landing-sweep` |
| `实测/踩坑` | `powershell-file-encoding`、`import-guard`、`skill-assets-convention`、`ts-expect-error`、`vitest-queued-alternative` |
| `项目约定` | `poll-deferred-at-start`、`no-git-write`、`code-style`、`rules-single-source` |

> 来源类型 = 权限标记（谁定的、可审计），**不决定约束力**——极性（做/不做）由措辞判定（grep 正文极性词，可复算）。

### 2.2 层级规范（既有，判据：同一含义用同一标记）
`#` 规则名=一句话判据（恰一个）；`##` 大节（核心判据由 H2 或列表承载）；`###` 小节（不用 emoji）；`**加粗**` 是句内强调，不参与扣分（`#` 管分节、`**` 管强调，不冲突）。

### 2.3 三检验（既有，定义「可删」）
一条文字可删，当且仅当删掉后：①判据本身不变 ②边界例子不变 ③引用关系不断。#1#2 需 AI 逐条判断，#3 可脚本查。

### 2.4 评分维度

**废弃「强度档位」**：原「绝对禁止/禁止/必须按来源分档」是伪区别（都是 must 级）且来源类型不决定约束力，移除。改为**极性**（做/不做，grep 正文措辞判定，可复算）。

#### 硬性维度（D1/D2/D3/D5，拆成检查点，每项 1 分）
| 组 | 检查点 | 判定（可复算） | 得分 |
|---|---|---|---|
| 头部规范 | 来源行三字段（类型/日期/落地） | 来源行含「来源：类型（日期）」+「落地」；无来源行 = 0 | 有 1 / 无 0 |
| | 来源类型在枚举内 | 来源行类型 ∈（用户当场指令/评审第 N 轮/实测踩坑/项目约定） | 有 1 / 无 0 |
| | 来源行不错位 | 来源行在头部（前 10 行内），不在文末 | 是 1 / 否 0 |
| 层级规范 | H1 唯一 | 全文恰一个 `# 标题` | 是 1 / 否 0 |
| | H3 无 emoji | `###` 标题不含 emoji/装饰符号 | 是 1 / 否 0 |

#### 新增维度
**执行力度（含极性，各检查点有/无，每项 1 分）**

| # | 检查点 | 判定（可复算 grep） | 得分 |
|---|---|---|---|
| ① | **极性明确** | 正文有「禁止/不得/不要/必须/应/要」+ 动作；无极性 = 不知道做什么 = 不可执行 | 有 1 / 无 0 |
| ② | **动作内容具体** | 动作的对象是可枚举项（如 `git commit`）或具体描述，非空泛（「合理处理」「适当」类） | 有 1 / 无 0 |
| ③ | **适用条件精细** | 明确到「具体类型+条件」（如「在 typescript 场景」）；只写「全部情况下」或没写 = 0 | 有 1 / 无 0 |
| ④ | **来源覆盖** | 禁令类声明「不因来源豁免」（含计划/子代理/脚本/工具模板） | 有 1 / 无 0 |
| ⑤ | **冲突裁决** | 声明「与具体指令/模板冲突时以本规则为准」 | 有 1 / 无 0 |
| ⑥ | **例外从严** | 例外条件明确（「只有…才算」），无宽松词（「一般」「通常」「可能允许」） | 有 1 / 无 0 |
| ⑦ | **触发机制** | 有可观测触发信号/时机（「落地后」「开工时」「编辑后」） | 有 1 / 无 0 |
| ⑧ | **验证闭环** | 定义「怎么确认遵守了」（自检命令/检查点/报告要求） | 有 1 / 无 0 |

> ①②③ 语义完整（A 类）、④⑤⑥ 抗绕过（B 类）、⑦⑧ 闭环（C 类）。**每检查点 1 分（有=1/无=0）**；**不适用项不计入满分**，执行力度组满分 = 适用检查点数（禁令类 8 项，非禁令类省略④⑤⑥ = 5 项）。**禁令类判定**：正文有「禁止/不得/不要/严禁」类极性词 = 禁令类（④⑤⑥ 适用）；纯「必须/应」正向义务或流程类 = 非禁令类（④⑤⑥ 不适用）。出处方：补对应小节（`no-git-write` 的「防掠过」是 ④⑤⑥ 样板）。

**冗余度（每项 1 分）**
| 层 | 检查项 | 判定（可复算） | 得分 |
|---|---|---|---|
| 形式（脚本） | 无完全重复句 | 正文去重后相同非空句子 ≥2 次 → 不得分 | 无 1 / 有 0 |
| | 无空泛引导段 | 段落以「总之/综上/需要注意的是/换句话说/由此可见」开头 → 不得分 | 无 1 / 有 0 |
| | 无来源行历史叙述 | 来源行含「合并/补于/补记」等历史词 → 不得分 | 无 1 / 有 0 |
| 语义（AI） | 三检验报告 | AI 逐段三检验，报告「可删 N 段 + 理由」。**报告必须做**；可删段数不计分，未优化可删段标注「待删 N 段」 | 做了 1 / 没做 0 |

> 设计原则：脚本只查可判定冗余（重复句/空泛段/历史词），语义冗余由 AI 三检验判断并写报告。体积（D4）保持参考不计总分；冗余度独立成维度（用户裁决：不把体积直接打分，把冗余话术作为打分项）。

**标题（每项 1 分）**
| 检查点 | 判定 | 得分 |
|---|---|---|
| 判据式非主题名 | 标题是一句话可执行判据，不是主题名 | 是 1 / 否 0 |
| 含极性 + 动作 + 对象 | 标题有「禁止/必须/不得」+ 动作 + 对象 | 有 1 / 无 0 |
| 反映关键前提 | 内容有明确适用范围/前提时标题必须体现（如「沟通中」）——漏前提 = 误匹配风险 | 有 1 / 漏 0 |
| 标题 ↔ 内容一致性 | 收尾对照三句：①范围 ②极性 ③对象 与正文一致 | 一致 1 / 不一致 0 |

**计分方式（可扩展）**：**每检查点 1 分，满分 = 当前检查点总数**（现有 24 项：头部 3 + 层级 2 + 来源 2 + 引用 1 + 冗余 4 + 执行力度 8 + 标题 4）。报告用「得分 / 满分」表示（如 20/24）。**以后加新维度/检查点只增满分，不重算任何比例**。**级别按得分率**（得分 ÷ 满分）：健康 ≥90% / 预警 70–89% / 不及格 <70%。不适用项不计入满分（如非禁令类省略④⑤⑥，执行力度组满分 5/5）。

## 3. 类型感知扩展（双轴模型 + 类型专属检查点 + 单判据）

> **本扩展取代原 §2.4 的 24 检查点单一口径计分方式；满分按类型（通用 17 + 执行力度适用项），不适用项不计入满分，原 24 检查点正文保留为基底判据。**
> 类型判定是 AI 的职责（语义归类），作为输入传给 `score.mjs`（`opts.type`，同 `triCheckDone` 模式）；脚本不做类型归类，只按收到的 type 选检查点、机械算分。判出的类型写进体检报告（可复算证据）。

### 3.1 双轴模型（规则类型 = 适用方式 × 极性）

**两个正交轴，一条规则各取一个值。**

**适用方式轴（3 值）——规则怎么被触发/适用**

| 值 | 定义 | 特征 |
|---|---|---|
| **持续适用** | 无条件、无触发时机，任何时候都适用 | 无「在…时/开工时/落地后」类条件与时机词；通用型禁令或纪律 |
| **条件触发** | 由特定条件/事件/时机触发，触发一次执行一次 | 有明确触发条件（编辑时/开工时/落地后/测试 stuck 时） |
| **模式门控** | 有一个**持久的模式状态变量**，规则一直在线，按当前模式裁决同一动作；状态切换是独立的转移逻辑 | 含「模式/适用/退出/回到/重新适用」等状态转移描述 |

> 模式门控与条件触发的本质区别：条件触发 = `if(事件E) => 动作A`（一次性，事件不发生则规则不存在）；模式门控 = 持久 `state`（跨时刻延续）+ 按当前 state 裁决同一动作 + 独立的 state 转移逻辑。

**极性轴（2 值）——规则要求做还是不做 + 判定词封闭词表**

| 值 | 定义 | 判定词（封闭词表） |
|---|---|---|
| **禁令** | 要求**不做** | 禁止/不得/不要/严禁 |
| **义务** | 要求**做** | 必须/应/要/一律 |

> **判定词是封闭词表**：规则正文极性一律用表内词，不引入表外词（不允许/不可/切勿等 → 读懂语义后归一成表内词）。rule-writer 写/改规则时强制归一；inspector 体检发现表外词 → 给处方（换表内词）= **归一缺口**。
> **极性必须单一**：一个文件一个核心判据、一个极性。混合极性（同一文件既有禁令句又有义务句且无单一核心判据）= 结构缺陷，由「单判据」检查点判 0（见 §3.3）。
> 「规范」不是极性，是体裁——以「约定/标准长什么样」形式写的规则；写成「必须做 Y」= 义务，写成「禁止做 Z」= 禁令。

### 3.2 类型判定流程（AI 判，脚本只接收）

**适用方式判定顺序：模式门控 → 条件触发 → 持续适用**

| 判定为 | 线索（正文/标题出现即优先） |
|---|---|
| 模式门控 | 含「模式 / 适用 / 退出 / 回到 / 重新适用」等状态转移描述，或明显按「某条消息/某状态」裁决同一动作 |
| 条件触发 | 含「开工时 / 落地后 / 编辑时 / …时 / …后 / …前」的时机或条件标记 |
| 持续适用 | 以上皆无，规则无条件持续适用 |

**极性判定**

| 判定为 | 线索 |
|---|---|
| 禁令 | 正文含「禁止 / 不得 / 不要 / 严禁」 |
| 义务 | 正文含「必须 / 应 / 要 / 一律」且无禁令词 |
| 混合（缺陷） | 既含禁令词又含义务词，且无单一核心判据 → 由「单判据」检查点判 0（该拆） |

### 3.3 通用 17 项（所有类型共用）

头部规范 3 + 层级规范 2 + 来源精简 2 + 引用完整 1 + 冗余度 4 + 标题 4 + **单判据 1** = **17**。

**单判据（通用结构检查点，AI 判，每项 1 分）**

| 检查点 | 判定（查什么） |
|---|---|
| 单判据 | 一个文件只承载**一个核心判据**（一个极性 + 一个主题）；多个互不相关的 H2 主题 / 极性混合且无单一核心判据 = **合集 = 该拆**（判 0 + 处方「拆成 N 条独立规则」） |

> 评分单元保持按文件，不按节评分（合集 = 单判据 0 分，不被按节累加变相豁免）。「一个判据的部件」（如 no-git-write 的禁止写/允许读/遇到不确定暂停）不算多判据——它们是同一核心判据的组成部分。

### 3.4 执行力度适用项表（类型 × 极性 → 适用检查点）

| 类型 | 极性 | 执行力度适用项 | ③⑦ 口径 | 执行力度组 max |
|---|---|---|---|---|
| 持续适用 | 禁令 | ①②④⑤⑥⑧（③⑦ 不适用） | — | 6 |
| 持续适用 | 义务 | ①②⑧（③④⑤⑥⑦ 不适用） | — | 3 |
| 条件触发 | 禁令 | ①②③④⑤⑥⑦⑧ | ③=触发条件明确；⑦=有可观测时机词 | 8 |
| 条件触发 | 义务 | ①②③⑦⑧（④⑤⑥ 不适用） | 同上 | 5 |
| 模式门控 | 禁令 | ①②③④⑤⑥⑦⑧ + 模式专属 6 | ③=模式归属可判定；⑦=切换信号可观测 | 14 |
| 模式门控 | 义务 | ①②③⑦⑧ + 模式专属 6 | 同上 | 11 |

> ④⑤⑥ 仅禁令类适用（沿用 §2.4 禁令类判定：正文含禁止/不得/不要/严禁）。不适用项**不计入满分**。

### 3.5 满分口径（满分 = 通用 17 + 执行力度组 max，组 max 已含类型专属）

| 类型 × 极性 | 满分 |
|---|---|
| 持续适用 · 禁令 | 23 |
| 持续适用 · 义务 | 20 |
| 条件触发 · 禁令 | 25 |
| 条件触发 · 义务 | 22 |
| 模式门控 · 禁令 | 31 |
| 模式门控 · 义务 | 28 |

**合集（待拆未定）评分口径**：类型待拆未定时，**只报通用组**（满分 17，单判据=0）+ 处方「该拆」；执行力度与类型专属不评。**报告形态**：报通用组得分率，**不报整体级别**（满分未定，拆后按各新文件分别判类型、重评）。

### 3.6 模式门控 6 个专属检查点（每项 1 分，AI 判）

| # | 检查点 | 判定（查什么） |
|---|---|---|
| M1 | **状态集合完整** | 定义了规则管辖的全部模式（≥2 态）；漏一态 = 该态下规则没交代 |
| M2 | **每状态行为明确** | 每个状态都规定了动作裁决（该态做/不做）；空态 = 0 |
| M3 | **切换判据明确** | 状态转移由可观测信号驱动，无「感觉/大概/酌情」 |
| M4 | **回到逻辑完整** | 有「退出 → 重新适用」回转路径；单向退出 = 规则形同失效 |
| M5 | **模式边界封闭** | 每态覆盖情形可判定、不用执行者做语义归类（防掠过） |
| M6 | **退出后由谁接管** | 规则让位时指明动作按什么管；退出不留空档 |

> 判定方式：这 6 项查「状态机完整性」，靠 **AI 判**（同三检验报告），每项 0 分进 findings 并给处方。类型本身是 AI 标注，检查点同源。

### 3.7 计分与级别（类型感知）

- 每检查点 1 分；满分 = 该类型适用检查点数（§3.5）；得分率 = 得分 ÷ 满分。（合集/待拆未定文件例外：只报通用组得分率、不报整体级别，见 §3.5）
- 级别：健康 ≥90% / 预警 70–89% / 不及格 <70%。
- **只同类型比较**，跨类型不比（不同类型满分不同是设计使然）。
- 分数 = 缺口指示器：告诉「这种类型还差哪几个检查点」，全满足 = 合格。
