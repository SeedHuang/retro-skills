# 判据全集（24 检查点 1 分制）——Spec A §2 落地

> 本文件是 rule-inspector 的判据全集，内容照抄 spec `2026-10-09-rule-suite-design.md` §2（单源一致，逐字落地）；`scripts/score.mjs`（Task 3）按此实现，rule-writer（Task 5）亦引用本文件。

## 2. 判据全集（评分维度）

### 2.1 来源类型（权限标记，管「谁定的」）
| 类型 | 现有规则 |
|---|---|
| `用户当场指令` | `global-ask-before-acting`、`plain-language-to-user`、`docs-convention`、`how-i-must-reason` |
| `评审第 N 轮` | `landing-sweep` |
| `实测/踩坑` | `powershell-file-encoding`、`import-guard`、`skill-assets-convention`、`ts-expect-error`、`vitest-queued-alternative` |
| `项目约定` | `poll-deferred-at-start`、`no-git-write`、`code-style`、`rules-single-source` |

> 来源类型 = 权限标记（谁定的、可审计），**不决定约束力**——极性（做/不做）由措辞判定（grep 正文极性词，可复算）。

### 2.2 层级规范（既有，判据：同一含义用同一标记）
`#` 规则名=一句话判据（恰一个）；`##` 大节（核心判据由 H2 或列表承载）；`###` 小节（不用 emoji）；`**加粗**` 是句内强调，不参与扣分（`#` 管分节、`**` 管强调，不冲突）。

### 2.3 三检验（既有，定义「可删」）
一条文字可删，当且仅当删掉后：①判据本身不变 ②边界例子不变 ③引用关系不断。#1#2 需 AI 逐条判断，#3 可脚本查。

### 2.4 评分维度

**废弃「强度档位」**：原「绝对禁止/禁止/必须按来源分档」是伪区别（都是 must 级）且来源类型不决定约束力，移除。改为**极性**（做/不做，grep 正文措辞判定，可复算）。

#### 硬性维度（D1/D2/D3/D5，拆成检查点，每项 1 分）
| 组 | 检查点 | 判定（可复算） | 得分 |
|---|---|---|---|
| 头部规范 | 来源行三字段（类型/日期/落地） | 来源行含「来源：类型（日期）」+「落地」；无来源行 = 0 | 有 1 / 无 0 |
| | 来源类型在枚举内 | 来源行类型 ∈（用户当场指令/评审第 N 轮/实测踩坑/项目约定） | 有 1 / 无 0 |
| | 来源行不错位 | 来源行在头部（前 10 行内），不在文末 | 是 1 / 否 0 |
| 层级规范 | H1 唯一 | 全文恰一个 `# 标题` | 是 1 / 否 0 |
| | H3 无 emoji | `###` 标题不含 emoji/装饰符号 | 是 1 / 否 0 |
| 来源精简 | 来源行 ≤2 渲染行 | >200 字符即视为超 2 行 | 是 1 / 否 0 |
| | 无原话引用 | 来源行不含「」/引号内的用户原话 | 是 1 / 否 0 |
| 引用完整 | 跨规则指针有效 | 引用的规则文件都存在 | 是 1 / 否 0 |

> **无来源行** → 头部规范组 3 项（三字段/类型枚举/不错位）全 0。

#### 参考维度（D4，不计入总分）
| 检查项 | 判定 |
|---|---|
| H1 是判据（非目录式标题） | 是 ✓（参考）/ 目录式 ✗ |
| 超单条基线 ×1.5 | 生成「需冗余审查」提示（参考，人工流程检查点） |

#### 新增维度
**执行力度（含极性，各检查点有/无，每项 1 分）**

| # | 检查点 | 判定（可复算 grep） | 得分 |
|---|---|---|---|
| ① | **极性明确** | 正文有「禁止/不得/不要/必须/应/要」+ 动作；无极性 = 不知道做什么 = 不可执行 | 有 1 / 无 0 |
| ② | **动作内容具体** | 动作的对象是可枚举项（如 `git commit`）或具体描述，非空泛（「合理处理」「适当」类） | 有 1 / 无 0 |
| ③ | **适用条件精细** | 明确到「具体类型+条件」（如「在 typescript 场景」）；只写「全部情况下」或没写 = 0 | 有 1 / 无 0 |
| ④ | **来源覆盖** | 禁令类声明「不因来源豁免」（含计划/子代理/脚本/工具模板） | 有 1 / 无 0 |
| ⑤ | **冲突裁决** | 声明「与具体指令/模板冲突时以本规则为准」 | 有 1 / 无 0 |
| ⑥ | **例外从严** | 例外条件明确（「只有…才算」），无宽松词（「一般」「通常」「可能允许」） | 有 1 / 无 0 |
| ⑦ | **触发机制** | 有可观测触发信号/时机（「落地后」「开工时」「编辑后」） | 有 1 / 无 0 |
| ⑧ | **验证闭环** | 定义「怎么确认遵守了」（自检命令/检查点/报告要求） | 有 1 / 无 0 |

> ①②③ 语义完整（A 类）、④⑤⑥ 抗绕过（B 类）、⑦⑧ 闭环（C 类）。**每检查点 1 分（有=1/无=0）**；**不适用项不计入满分**，执行力度组满分 = 适用检查点数（禁令类 8 项，非禁令类省略④⑤⑥ = 5 项）。**禁令类判定**：正文有「禁止/不得/不要/严禁」类极性词 = 禁令类（④⑤⑥ 适用）；纯「必须/应」正向义务或流程类 = 非禁令类（④⑤⑥ 不适用）。出处方：补对应小节（`no-git-write` 的「防掠过」是 ④⑤⑥ 样板）。

**冗余度（每项 1 分）**
| 层 | 检查项 | 判定（可复算） | 得分 |
|---|---|---|---|
| 形式（脚本） | 无完全重复句 | 正文去重后相同非空句子 ≥2 次 → 不得分 | 无 1 / 有 0 |
| | 无空泛引导段 | 段落以「总之/综上/需要注意的是/换句话说/由此可见」开头 → 不得分 | 无 1 / 有 0 |
| | 无来源行历史叙述 | 来源行含「合并/补于/补记」等历史词 → 不得分 | 无 1 / 有 0 |
| 语义（AI） | 三检验报告 | AI 逐段三检验，报告「可删 N 段 + 理由」。**报告必须做**；可删段数不计分，未优化可删段标注「待删 N 段」 | 做了 1 / 没做 0 |

> 设计原则：脚本只查可判定冗余（重复句/空泛段/历史词），语义冗余由 AI 三检验判断并写报告。体积（D4）保持参考不计总分；冗余度独立成维度（用户裁决：不把体积直接打分，把冗余话术作为打分项）。

**标题（每项 1 分）**
| 检查点 | 判定 | 得分 |
|---|---|---|
| 判据式非主题名 | 标题是一句话可执行判据，不是主题名 | 是 1 / 否 0 |
| 含极性 + 动作 + 对象 | 标题有「禁止/必须/不得」+ 动作 + 对象 | 有 1 / 无 0 |
| 反映关键前提 | 内容有明确适用范围/前提时标题必须体现（如「沟通中」）——漏前提 = 误匹配风险 | 有 1 / 漏 0 |
| 标题 ↔ 内容一致性 | 收尾对照三句：①范围 ②极性 ③对象 与正文一致 | 一致 1 / 不一致 0 |

**计分方式（可扩展）**：**每检查点 1 分，满分 = 当前检查点总数**（现有 24 项：头部 3 + 层级 2 + 来源 2 + 引用 1 + 冗余 4 + 执行力度 8 + 标题 4）。报告用「得分 / 满分」表示（如 20/24）。**以后加新维度/检查点只增满分，不重算任何比例**。**级别按得分率**（得分 ÷ 满分）：健康 ≥90% / 预警 70–89% / 不及格 <70%。不适用项不计入满分（如非禁令类省略④⑤⑥，执行力度组满分 5/5）。
