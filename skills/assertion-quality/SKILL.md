# assertion-quality：断言质检（三轴手册）

## 一句话

一条断言要过三道关：**来路清楚（真实）→ 路经站得住（合理）→ 去处有着落（有效）**。顺序固定，任一轴零分，另两轴满分也救不回来。

## 什么时候用

| 场景 | 用不用 |
|---|---|
| 结论会影响他人决策 / 会被签字 / 会送审 / 会对外交付 | 用，走完整四步 |
| 日常一句话结论（含一句出处 + 一句对照 + 一句 target） | 用轻量版：材料即正文，不立档 |
| 高复用关键结论 | 升格成长档案 + `hash + path + line + 行摘录` 四件套 |
| 纯偏好表达（不声称任何事实依据） | 不用 |

## 四步程序（审查别人 / 自查同一套）

1. **分解**断言序列；分解不出 = 不受理。
2. 逐环查**封闭失败模式清单**：越界 / 语义偷换 / 量级失真 / 遗漏前提 / 极性反转 / 合取偷换。
3. **反例搜索**：构造满足全部前提但结论为反的实例。
4. **强度标注**。

审查性质 = 证伪式：能判死「不合理」，不能证明「绝对合理」；「通过」只等于「未发现跳步 + 暂未被证伪」。

## 材料 schema（六字段）

`claim / source{type, anchor, output} / chain[]{step, next, warrant} / mapping / boundary{semantics, invalidWhen} / target`

固定格式的价值：失败模式有固定栖息地；`warrant`（每环凭什么）写不出来的环，就是藏着前提的环。

## 分层记账（证书模式）

| 层 | 谁做 | 成本 |
|---|---|---|
| 过程层：材料 + 四步审查 | AI / 议会，一次性 | 高 |
| 凭证层：判证书存在与有效 | 脚本 `nonEmpty` + `containsAny`，使用时 | 零 |
| 追溯层：后续发现不合理 → 三态定责 | 程序漏模式 → 补清单；材料造假 → 收紧抽检；条件失效 → 按 `invalidWhen` 作废重审 | 低频 |

## 判心（residual）：机器判不死的部分

两类：**利益冲突型**（信息在场但判者 = 行为者 → 判定权分离）与**无信号语义型**（判定对象是概念 / 逻辑关系，不发射可读信号）。

每条 residual 登记必须带四件：`{who, sample, fields, 客观化路径}`。缺任一件 = `npm run check:criteria` exit 1 并点名 id。

| 闸门 | 内容 |
|---|---|
| ① 用户终审 | 判定结果落记录，用户签字才生效 |
| ② 永久可翻案 | 只盖「截至 X 日未发现跳步」章；翻案条件显式登记 |
| ③ 客观化路线图 | 每条注明客观化路径（补失败模式 / 判例成熟 / 出现可形式化结构）；判心场景变多 = 设计失败信号。机判：`objectivePath` 非空，校验 `npm run check:criteria` exit 0 |

触发时机 = **收口**（gate 出口 / 议会 / review 门禁），且只寄生在「缺席有红灯」的收口上；高频说话不触发人工成本。

## 交付前自查（可粘贴）

1. `npm run check:criteria` → 首行 `判据 N 条 / 绿 M / 红 K`，末行 `criteria-engine ok` 且 exit 0；
2. 材料里每个锚 `Test-Path` 或 `Grep` 能命中（`path:line` 写法）；
3. 数字类结论附取数命令，复算结果一致。

手册全文见 `references/manual.md`；判例库见 `references/cases.md`（按「先看反例，再看正例」读）。

建模场景另有一条标题约束：给判据 / 清单条目 / 禁令 / 字段起名时，按 `references/title-criterion.md` 执行，读完产出「标题断言词 → 可观测算子」对照（无算子则改标题 / 补算子 / 标 residual，三选一）；缺对照 = 未执行。仅适用于模型与卡面标题，不适用于 skill / PRD 等非判据标题（避免误杀）。
