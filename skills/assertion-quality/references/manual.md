# 断言质检手册（三轴框架全文）

> 来源：rule 改造 PRD `docs/prd/20261105182104-rule-refactor/prd/stage-2-new-mode-pilot.md` §4（2026-11-05 D-10/D-13 终裁）
> 定位：`assertion-quality` 的按需正文；SKILL.md 是入口与边界，本文件是细则。

## 4.1 三轴定义

| 轴 | 定义 | 机判部分 | 残余（residual） | schema 字段 |
|---|---|---|---|---|
| **真实 = 出处轴** | 断言有出处且逐条对得上（口径一致）；出处指向但口径不同 = 不真实；两个出处 = 交叉验证 | 出处锚存在 + 取数命令复算一致 | 是否真挖过 | `source` |
| **合理 = 范围轴 + 链轴** | 范围被显式声明；链在声明范围内每步成立 | 材料存在性 + 显式失败模式检测 | warrant 真伪 / 链闭合 / 隐藏前提 | `chain` `mapping` `boundary` |
| **有效 = 问题轴** | 锚定显式 target 的解决（直接有效 = 数字即答案；环节有效 = 一把钥匙里的一环） | target 声明 + 回指在场 | 推进真实性 / 环节贡献 | `target` |

三性**正交**（任一轴满分救不了另一轴零分）；**链式依赖**（顺序固定 真实→合理→有效）；**材料不倒序**（无出处先谈 target = 先射箭后画靶 = 编造信号）。

**两层有效**：微观有效 = target 达成（客观可判，数据侧责任；判据 = `target` 字段非空且回指在场）；宏观有效 = target 该不该问（规划侧责任）。两种死法分开定责：target 未达成 → 重做数据；target 不在必要路径 → 改问题分解，不动数据。

## 4.2 材料 schema（固定格式）

```
claim / source{type, anchor, output} / chain[]{step, next, warrant} / mapping / boundary{semantics 封闭枚举, invalidWhen} / target
```

固定格式的价值 = **失败模式有固定栖息地**（散文里跳步藏在字缝，schema 里查固定字段）；`warrant`（每环凭什么）是隐藏前提的强光灯——写不出的环就是藏前提的环。

## 4.3 四步审查程序

① 分解断言序列（分解不出 = 不受理）→ ② 逐环查**封闭失败模式清单**：**越界 / 语义偷换 / 量级失真 / 遗漏前提 / 极性反转 / 合取偷换** → ③ 反例搜索（构造满足全部前提但结论为反的实例）→ ④ 强度标注。

审查性质 = **证伪式**：能判死不合理，不能证明绝对合理；「通过」= 未发现跳步 + 暂未被证伪。

## 4.4 证书模式（script 盯证书，不盯过程）

| 层 | 职责 | 实现 |
|---|---|---|
| 过程层 | 材料 + 四步程序审查（复杂性全在这） | AI / 议会，一次性成本 |
| 凭证层 | 判证书存在与有效 | script：`nonEmpty` + `containsAny`，使用时零成本 |
| 追溯层 | 后续发现不合理 → 查档三态定责 | 程序漏模式→补清单；材料造假→收紧抽检；条件失效→按 `invalidWhen` 作废重审 |

**成本分层**：日常断言材料即正文（一句出处 + 一句对照 + 一句 target，不立档案）；**高复用关键结论**才升格成长档案 + hash 强锚。

## 4.5 阶段闸门（真实=前提、合理=过程、有效=结果）

材料按阶段填充，**不要求一次交齐**。数据状态嵌套（有效 ⊃ 合理 ⊃ 真实）；每站只查**新增材料 + 前站绿章**；抽检按状态分层（真实站抽真伪、合理站抽链、有效站抽去向）。与 gate-record 段表 / dev-workflow 五段同构：分段校验 + 单向推进 + 前站绿章。

## 4.6 出处锚强度分级 + 时序纪律

位置锚（`path:line`）三种漂移：行号漂、路径漂、**语义漂**（锚看似有效、内容已被改写）。分界判据 = **引用要活多久**：即时引用用弱锚；存证引用必须 **`hash + path + line + 行摘录`** 四件套。

**hash 锚时序纪律三条**：

1. **先提交，后写锚**（改 → commit → 用那个 commit 的 hash；不随手拿 HEAD 填）；
2. 未提交内容 hash 栏标「待提交」，提交后回填；
3. 行摘录防行号抄错，不防内容未进历史——不豁免第 1、2 条。

## 4.7 判心两闸门与客观化路线图

判心两类：**利益冲突型**（信息在场、当场可判，但判定者与行为者同一 → 判定权分离）与**无信号语义型**（判定对象是概念 / 逻辑关系，不发射可读取信号；引用事实的环有信号、一律压回机判）。

| 闸门 | 内容 | 依据 |
|---|---|---|
| ① 用户终审 | 判定结果落 gate-record 式记录，**用户签字才生效** | dev-workflow「中断权与终裁权只在用户」 |
| ② 永久可翻案 | 结论只盖「截至 X 日未发现跳步」章；翻案条件显式登记（新失败模式 / 新判例 / 前提崩塌） | 证伪式延伸；与 `invalidWhen` 同构 |
| ③ 客观化路线图 | 每条 residual 登记时必须注明客观化路径（失败模式清单补条 / 判例成熟 / 可形式化结构出现）——residual 是待客观化 todo list，不是垃圾场；**判心场景变多 = 设计失败信号**。机判：`objectivePath` 非空 | 「证据就是可以客观表达的」——北极星 |

**residual 触发时机**：不在过程触发，在**收口**触发（产物产生时只登记，收口时才抽检）——且**只寄生在「缺席有红灯」的收口上**（gate 出口 / 议会 / review 门禁：抽检记录缺席 = 下一步红灯）；session 收尾无门禁，只是捡漏窗口。判心只钩低频存证点（立档 / 送审 / 收口），高频的说话不触发人工成本。

## 4.8 script 边界

封闭算子表达不了「合理」的**总判定**，表达得了它的**骨架**（材料 schema）与**显式失败模式**（有限清单逐个做检测器）。语义判据的工程化 = 把 AI 判断逼进轨道、压缩到最小可审区域，不是消灭语义判断。

## 4.10 角色映射（席位义务生成逻辑）

| 阶段 | 第一责任席 | 本仓对应物 |
|---|---|---|
| 真实级 | 数据采集席 | `evidence-reader`（只交原文 + 行号） |
| 合理级 | 推导执行席 | 议会逻辑评委 |
| 有效级 | 决策落点席 | PRD 汇报数据 |

每席位只对本站轴负全责（采集席不对有效负责——硬要它管 target 只会逼它编）；下游材料自动含上游绿章——交接点即闸门。
