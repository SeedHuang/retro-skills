# 角色面板（分场景必问清单）

使用方式：评审时逐角色过清单，每条必答（显式记录"问过，无问题"）。角色面板的价值在**领域地雷库**，不在角色扮演——无固定清单的角色评审，同一角色不同次评审的覆盖面会漂移。

## 场景 A：PRD / 产品需求文档

角色：产品经理、交互设计师、资深开发、资深测试。裁决角色：项目 Owner（对发现做采纳/拒绝裁决并给理由）。

### 产品经理必问

1. 目标用户完整旅程有断点吗？重点扫"第一次使用"与"被拒绝时"——每个不支持的场景，用户当下的替代路径是什么、体验如何？
2. 每个边界/异常场景，文档说了"怎么办"吗？
3. 交付节奏：有中间可用节点吗？最小可用集是什么？
4. 工具失效时用户怎么逃生（不依赖本工具的手工路径）？
5. 有没有隐含前置条件没写出来（目标项目已有某配置/某状态）？

### 交互设计师必问

1. 所有打断用户的时机，能前置的都前置了吗？（执行中途弹选择 = 大忌）
2. 列表/选项里有无效选项吗（选了也白选）？
3. 每条错误信息带可执行的下一步吗？
4. 加法/减法混在同一界面时，模式区分了吗？
5. 有没有静默发生的状态变化（用户不可见）？
6. 输出可被脚本/自动化消费吗（--json 等）？

### 资深开发必问

1. 每个技术机制断言在目标平台验证过吗？列出全部"用 X 实现 Y"断言，逐一查 X 的平台真伪（symlink/junction、路径分隔符、CRLF/BOM、编码、大小写）
2. 接管时刻：工具接管前用户可能手动制造过任意脏状态——接管逻辑校验前提了吗？
3. 并发/重入：两实例同跑、同命令重跑（幂等）会怎样？
4. 中断恢复：任意步骤崩溃后重跑收敛吗？
5. 读取点合法性：每个持久化字段读取时校验来源合法吗（防污染持久化）？
6. 选型库的已知坑查过吗（CJK 渲染、Windows 兼容、版本断代）？原生模块/二进制产物被方案内多个运行时（Node/Electron/浏览器）加载时，逐一列出"运行时 × 产物"矩阵验证互不破坏；发现互斥时决策点前移到最早任务

### 资深测试必问

1. 每条验收标准标注自动可验证 / 人工验证了吗？
2. 关键路径的回归防护是什么（golden file / 快照 / 状态构造）？
3. 不可重复场景（kill 进程、时序竞争）换成确定性状态构造了吗？
4. fixture 覆盖真实世界多样性吗（CRLF/BOM/缩进/编码/平台）？
5. 实验性/降级功能的验证方式定义了吗（smoke 手测清单 vs 自动化）？

## 场景 B：技术方案 / spec

角色：架构师、资深开发（复用场景 A 开发必问）、资深测试（复用其 1/2/4）、交付/运维。

### 架构师必问

1. 每个单元职责能一句话说清吗？改内部不破外部吗？
2. 边界处的数据流与错误传播定义了吗？
3. 每个外部交互（IO/进程/网络）失败时的行为定义了吗？
4. 有没有第二份真相（两处维护同一信息）？

### 交付/运维必问

1. 安装/部署的前置条件清单？
2. 出问题的诊断入口（日志/状态导出）？
3. 回滚方案？

## 场景 C：通用文档

六手法 + 资深开发必问（1/2/3/4）+ 目标读者代表必问：

1. 不看文档开头，能从任意章节进入不迷路吗？
2. 术语首次出现有定义吗？
