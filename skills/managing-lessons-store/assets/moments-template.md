# 情绪点模板（moments，逐字使用）

> 本文件是**情绪点（moments）结构的权威定义方**。`managing-lessons-store/SKILL.md` 只指向这里，不复制。
> **必须逐字使用**。
> 情绪判定公式与 userwords 共用一套（见 `retro-collect/assets/userwords-template.md`）——**对象主判据，情绪由对象+核心意图推出**，不自创第二套。

## 落点

`<KB>/projects/<项目标识>/<日期>-<sid>-<摘要>/moments.md`（**一 session 一份**——文件即本 session；日期 / `sid` / 摘要的定法以 `retro-collect/SKILL.md`「第 0 步：定 session」为权威定义方）

与同目录 `facts.md` / `userwords.md` 并列。

## 触发（谁有权写）

两条写路径：

1. **agent 主动**——察觉用户情绪时**当场记**，不用问用户（主路径，平时就在记）。
2. **`retro-collect` 重扫**——跑到 collect 时按当前公式重扫本 session 全对话，覆盖本 session 那批（补漏，见下节）。

与 userwords 的区别：userwords 只在跑 collect 时才产；moments 平时就在记，collect 只负责重扫补漏。

## 重扫与覆盖（`retro-collect` 跑时）

collect 时按**当前**判定公式**重扫本 session 全对话** → `moment drop`（清本 session 的条目区）→ `moment add` 逐条重写。**直接覆盖，不留旧版**——但"随时可再生成"只对**情绪**成立：**已结案条目的解法 / 代价是人写的判断，会一并被清掉**（drop 会回报条数），重扫完须重新结案。

**前提：本 session 对话仍完整可见。** 若已被压缩 / 截断（扫不全）→ **不要 drop**：残缺的新数据盖掉完整的旧数据 = 静默丢数据。此时只补新发现的，或先告诉用户「对话已不全，不覆盖」。

**文件即本 session**：drop 只清这个目录里的条目，天然不涉及别的 session。

**条目区边界**（必须按这个来，否则会误删）：

- 清的是 **`^##\s+M-` 块**；**文件头**（第一个 `^##\s+M-` 之前的内容）原样保留；
- **非 moment 标题**（手加的 `## 备注` 等）**保留**；
- 全文件无 `## M-` 头 → 不动（返回 0）。

## 记什么（三类极性，全收）

| 极性 | 收什么 | 去向 |
|---|---|---|
| **负面** | 用户不满意（对事纠正的轻负面 / 对人的重负面） | 规则管线（可能立规矩），要结案 |
| **正面** | 用户认可（「你这个想法好」= 对人正面） | 画像管线，不结案 |
| **认知** | 提问/回答暴露的判断倾向 | 画像管线，不结案 |

**好的也留**——画像只有负面 = 投诉日志，不是人物画像。正面/认知是画像的主要原料。

## 情绪判定公式（与 userwords 共用，不在此重写）

按 `retro-collect/assets/userwords-template.md` 的公式：
1. 有脏字 → 情绪波动标记，剥掉看核心
2. 核心意图：夸→正面 / 贬→负面 / 中性→中性
3. **对象（人/事）决定强度**：对人→情绪重；对事→情绪轻（对事的纠正是中性）
4. 「负面」≠ 骂得脏；「好的」≈ok 无评价词=中性

## 模板

```markdown
# 情绪记录（moments）

> 格式权威定义见 `managing-lessons-store/assets/moments-template.md`（本文件只放数据）。
> 触发：agent 察觉情绪当场记（不问）；collect 时重扫覆盖本 session。极性：负面 / 正面 / 认知，全收。
> 判定公式与 userwords 共用（对象主判据，情绪由对象+意图推出）。
> 触发句（原话）**三种极性都必填**（不猜原因/态度）；原因/态度为可选，写则标「（推断）」。

---

## M-<sid>-<N>

- 极性：<负面|正面|认知>｜项目：<标识>｜session：<sid>｜message：<轮次 N；memory id 拿得到则写成「轮次 N｜id <hex>」>｜时间：<YYYY-MM-DD>
- 状态：<未解决|已解决>（仅负面；正面/认知写「—」）
- 问题 / 认可 / 倾向：<一句话>
- 判据（思考过程）：<对象→意图→脏字→结论 的推导，如「对象=人（主语你+否定理解）→ 无脏字 → 核心意图=贬 → 负面」>
- 证据（原话）：
  > <用户原话，逐字>
- 原因（推断，可选）：<若有，须标推断>
- 态度（可选）：<若有，须标推断>
- 解法：（结案时补）｜代价：（结案时补：讨论轮数 / 时间）
```

### 证据栏的两种形态（2026-10-07 起）

> **上面 `## 模板` 代码块才是「逐字使用」的对象**（生成物的文件头 + 条目骨架照它抄）。本节是**说明与规则**，**不逐字抄进 KB**——它解释那个骨架里的「证据（原话）」一行在**两种情况**下会落成什么样。

**默认（不传 `--evidence-up`）——单句，与旧记录完全一致**：

```markdown
- 证据（原话）：
  > <用户原话，逐字>
```

**传了 `--evidence-up`（上文）——多行，末行=触发句**：

```markdown
- 证据（对话原文，紧邻上文→触发句）：
  > [上文] <紧邻的上一句，逐字>
  > [上文] <更早的一句，逐字>
  > [触发] <让情绪起来的那句，逐字>
```

**为什么用「独立参数」而不是在文本里用分隔符**（2026-10-07 用户裁决）：原话是**逐字抄录**的，若用 `｜` / `【触发】` 之类符号表达结构，**原话里出现这些符号就会解析错乱**。所以结构由**参数有几个**表达，不由文本里有什么符号表达——**原话含任何符号都不影响**。

**规则**：

| 规则 | 内容 |
|---|---|
| 上文**可重复传任意次** | `--evidence-up "句1" --evidence-up "句2"`，**按传入顺序输出**；**紧邻的上一句在前** |
| 末行固定是触发句 | 由 `--evidence` 提供，**三种极性都必填**（`validateMoment` 一律拒空） |
| **有上文但漏了触发句** | 证据栏**整块不输出**（末行约定靠触发句成立，半截的块没有意义），并打一条 `[warn]` 说出丢了多少句。走 CLI 时 `validateMoment` 会先拒空、根本走不到这里；这条只管**直接调用导出的 `buildMoment`** 的路径 |
| 原话里含换行 | 折成空格（`one()` 防护**不拆**），块结构不会被伪造 |
| 原话里含 `｜` `>` 等符号 | **原样保留**，不被解析 |
| 每句各自 `one()` 折行 | 所以「有多少句」= 传了几次 `--evidence-up` |
| `--evidence-up` **只收字符串** | 非字符串元素（对象 / 数组 / 数字）**跳过 + 告警**，不写进 KB——`String()` 会把对象变成 `[object Object]`，而这一栏的语义是逐字原话。空串 / 纯空白直接剔除 |
| **漏值**：参数后面跟了别的 flag | 视为「没给值」，**忽略 + 告警**。单值参数（`--evidence` 等）和 `--evidence-up` **同一套判定**。所以 `--evidence --project foo` 里的 `--project` **不会被当成原话写进证据栏**（实测过；旧版本只有多值有这层防护，单值那侧会把 flag 写进 KB） |
| **⚠️ 已知的取舍：单字母 flag 也会被当成 flag** | 判定用的是**全局** flag 表，而表里有 `verify record` 的单字母选项 `--a` / `--b` / `--n` / `--p`。所以用户原话**恰好等于** `--p` 时会被判成漏值 → **告警 + 拒记账**（实测：`--evidence "--p"` → `[warn] --evidence 后面没有值` + `记账失败：负面必须提供 --evidence`）。⚠️ **是显式拒绝，不是静默丢字**。**为什么不改**：把这些单字母从判定里排除，会让 `verify record --period P1 --a --b 3` 这种**真漏值**变成静默通过（`--a` 收不到值、台账记错），那比「原话被拒一次、用户重打一遍」坏得多。原话**含** `--p` 但不等于它（如 `--p 是原话`）不受影响，实测正常落盘 |
| 三种极性都支持多行 | 负面 / 正面 / 认知传了 `--evidence-up` 都出多行证据栏（不传则都是单句） |

**与 `userwords` 的分工**：userwords 记「用户说过什么」（**全量、逐字**）；moments 记「**哪几句合起来引发了这个情绪**」（选摘、含上文）。**moments 的每句原文必然能在 userwords 里找到——moments 是索引，userwords 是全量。**

**`--message` 填法**：`轮次 <N>`；memory 的 `message_id` 拿得到就附上写成 `轮次 N｜id <hex>`，**拿不到只写轮次即可**（memory 实测滞后，不能强依赖）。

> **⚠️ `--message` 是「强烈建议」不是「硬必填」**：不传**不会被拒绝**，`momentAdd` 只打一条 `[warn]` 告警（`lessons.mjs`：`if (!opts.message) process.stderr.write('[warn] ...')`）。但**不传就只剩 session 级可查**，定位不到具体哪一轮——所以实质上等同必填。**别把文档里的「必填」当成脚本会替你把关。**

## 硬约束

1. **触发句（原话）三种极性都必填**——`validateMoment` 一律拒空（负面原话不猜原因/态度；猜的部分须显式标「（推断）」）
2. **判据（思考过程）必填**——已有定性（极性）就必须写下推导（对象→意图→脏字→结论），否则无法复核
3. **只记情绪点**，不做价值判断——「这句话说明了什么」归分析阶段
4. **好的也留**（正面/认知）——不因为「不是负面」而漏记
5. 写库前查 `<KB>/.migrating`：存在 → 拒绝写入
6. **原子写**（临时文件 + 改名）+ **无 BOM**

## 常见错误

| 错误 | 纠正 |
|---|---|
| 负面只填 `--cause` 没有原话 | 原话（evidence）**三种极性都必填**（`validateMoment` 拒空）；原因只是可选推断 |
| 正面/认知**压根没记** | 它们是画像主原料——**注意不是「漏了证据栏」，是「没建这条 moment」**（`moment add` 一律要求 `--evidence`，三种极性都会出证据栏） |
| `--message` 当成脚本会把关 | **不传只告警不拒绝**——必须自己记得带，否则只剩 session 级可查 |
| 把「对事的纠正」当情绪爆发 | 对象=事 → 中性/轻负面，不是重情绪 |
| 自创格式 | 模板必须逐字使用 |
