# 出口签字账模板（`gate-record.md`）

> 本文件是**格式唯一源**：技能侧只留这一份模板，实例落在 `docs/devworkflows/<YYYYMMDDHHmmss>-<任务名>/gate-record.md`。
> 本文件不含真实签字行。整份复制到任务目录后，把 `[[...]]` 占位行换成本段的真实行。

## 六列口径

| 列 | 写什么 | 上限 |
|---|---|---|
| `段` | 六种之一：`①` `②` `②→③` `③` `④` `⑤`；同任务多次交付加 `@批次` | 无 |
| `出口判据（逐条）` | 本段出口判据的逐条结论（有 / 无 / 相等 / 不相等） | ≤300 字符 |
| `核了什么（命令输出首行 或 path:line）` | 一个可复算锚点 + 证据正文位置 | ≤250 字符 |
| `申报人` | 产物作者，按段定 | 无 |
| `签字人` | 该段的定性人；与申报人交集为空 | 无 |
| `结论` | `过` / `不过` / `不适用` + 一句理由 | ≤120 字符 |

> 上限数值的唯一实现是 `scripts/check-gate-record.mjs` 的 `LIMITS`（整份 ≤40KB）；本表是它的可读副本，冲突以脚本为准。

## 判据映射（R1–R9）

| 判据 | 账本里怎么体现 |
|---|---|
| R1 | 每行六列齐；`核了什么` 含反引号包裹的**命令或路径**、或 `#L7` / `path:line`；空 / 只写「已核」/ 只有反引号包的空话（`` `已核对` ``）→ 红 |
| R2 | `签字人` 与 `申报人` 按 `、+＋，,／/（）()空白` 拆词后交集为空（通用限定语「主 / agent / 代拟」不参与交集）；签字人须属段表「谁签」列（①/⑤ 用户、②/②→③/③ 审计、④ sdet）；`结论`列写「旁路」的 ①② 行签字人 = 审计 |
| R3 | 有数据行就必须有 `①` 行；出现 `②→③` 及之后的行时，`①`、`②` 两行必须在位且 `结论` 非空；计划门行签字人须含「审计」 |
| R4 | plan 出现 `## 新增设计决策` 节 → 违规（判在 plan 文件，不在账本） |
| R5 | 功能点 ID 集合 diff 非空且 PRD §0 无重签 → 违规 |
| R6 | 本任务目录内「拆 spec 中」的数据行 ≤ 1（只数 `出口判据` 与 `结论` 两列） |
| R7 | 引用长文结论必须带 `path:line` 且能追到 `evidence` 产出 |
| R8 | 改判后 `node scripts/scope-sweep.mjs --check` 必须 exit 0 |
| R9 | `skills/**/references/*.md` 不得出现真实六列签字行；本模板与 `[[...]]` 行豁免 |

## 出口签字表

| 段 | 出口判据（逐条） | 核了什么（命令输出首行 或 path:line） | 申报人 | 签字人 | 结论 |
|---|---|---|---|---|---|
| [[段]] | [[本段出口判据逐条结论]] | [[命令输出首行 或 path:line]] | [[申报人]] | [[签字人]] | [[结论]] |

## 填法

| 步骤 | 动作 |
|---|---|
| 1 | 进 ① 时建任务目录 `docs/devworkflows/<YYYYMMDDHHmmss>-<任务名>/`，把本文件复制为 `gate-record.md` |
| 2 | 每段收口后把 `[[...]]` 行替换为真实行；同任务增量追加新行，不改原行 `结论` |
| 3 | 单份超 40 KB 时把长证据外迁到 `docs/reports/<批次>-evidence/`，格内只留短锚 |
| 4 | 落行后跑 `node scripts/check-gate-record.mjs`，末行 `gate-record ok` 且 exit 0 |
