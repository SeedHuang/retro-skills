# 段②：技术设计（spec + testcase）

## 入口条件

- ① 的 `gate-record.md` 行已齐六列，且议会 #1 已通过（P0 = 0）。
- 本段要写 spec 的范围已划清（功能块粒度，未定稿的功能块不提前拆）。

> **旁路（PRD §4.2）**：单点小改（功能点集合 diff 为空 + 无新增交付物）跳过议会 #1 / #2。本文凡写「议会已通过」，旁路时改为「`gate-record.md` 注明「旁路」+ 审计的集合 diff 结论」；出口判据按 PRD §4.2 的替换表执行（② 改为「无 spec / testcase 增量 + 变更落在既有 F 覆盖范围**或** F 之外的既有文件（README / 配置 / 依赖清单 / 纯文档）」），其余签字按 PRD §4 段表。

## 出口判据

1. spec 与 testcase 作为**一件**交付物同时存在：testcase 由独立子代理在全新上下文编写（**编写者 ≠ spec 作者 ≠ 施工者**），spec 内用外链指向它，不内联用例。
2. 每份 spec 的验收项都能指到一条 testcase；testcase 覆盖总表每行能指回 spec 的节号或 R 编号。
3. 负例 + 边界条数 ≥ 正例条数（计数可复算）。
4. 差异清单留痕：与上一版相比改了什么、为什么改，每条有位置（`path:line`）。
5. 内部对齐零未决：spec 里不出现「待确认」字样；必须用户拍板的项已单独列成清单并在本段关闭。
6. 议会 #2 通过（P0 = 0、必修项清零）。

## 谁签

- **申报人**：主 agent（spec 作者）+ sdet（testcase 作者）。
- **签字人**：**审计**（核议会 #2 放行 + 两条计数；申报人不得自签）。
- 签字必须附：议会 #2 的放行记录位置、testcase 覆盖总表（按 `### TC-*` 或 `#### <ID>` **任一**形态落盘，审计用 Grep 自数 `^### TC-` 与 `| 正 |` / `| 负 |` / `| 边界 |` 标签，不要求申报人跑命令）。

## 功能块滚动拆（阈值与超限处置）

一个**功能块** = 交付单位（PRD §4.1）：一块产一份 spec + 一份 testcase，**做完一块再拆下一块**——**不提前批量拆**（提前拆 = 用还没定的结论去划后面几块的边界，拆完必返工）。

| 指标 | 阈值 | 超限怎么办 |
|---|---|---|
| spec 行数 | **≤ 350** | 在 **plan 阶段**拆成两块（不在 spec 里硬塞） |
| testcase 条数 | **≤ 80** | 同上 |
| 议会评审轮 | **≤ 3** | 同上 |

超限时必须在 plan 里写清两件事：**为什么拆**（哪几节自成一件事、边界在哪）、**拆完怎么合起来验收**（两块各自的 ③ 出口 + 合并后的 ④ 验收）；只写「拆成两块」= 没写。

**出口可预跑**：`size` 子命令（S4 起）可提前量三项指标，避免到计划门才发现超限——
`node scripts/check-plan.mjs size --spec <spec 文件> --testcase <testcase 文件> --rounds <n>`（首行给出 `spec n/350 tc n/80 rounds n/3`）。

## 拆块后的回流

- 新块（拆出来的第二块）的 spec / testcase 须**再送议会 #2**，不得沿用第一块的放行记录；
- `gate-record.md` 的 `②` 行按「**增量子集**」追加一节（复用 `②@S2` 的增量登记先例：只追加、不改原签结论）；
- 本段的六条出口判据对**每一块**分别成立，不是两块合并着算。

## 三权归属

| 权 | 谁 | 判据 |
|---|---|---|
| 申报 | 主 agent + sdet | 申报六条出口已齐，附议会放行记录与两条计数输出 |
| 定性 | sdet（testcase 质量）+ 议会 #2（整体） | sdet 不得同时是 spec 作者；议会 #2 未通过不得签字 |
| 核对 | 审计 | 核「spec ↔ testcase」外链是否双向可达、覆盖总表是否有不可回溯行 |

## 常见漏项

- spec 写完直接进 plan，testcase 以后补 → 验收项等于没有执行体。
- spec 作者顺手写用例 → 自写自判，独立编写的要求落空。
- 「待确认」留在 spec 正文里 → 内部对齐未零未决，实际把决策推给施工者。
- 差异清单只写「按评审意见修改」→ 无位置、无理由，等于没留痕。
- 负例条数凑不够，用「同一场景换措辞」充数 → 覆盖总表会暴露重复。

## 收口后

产出 `gate-record.md` 里 ② 的那一行：六列齐，「核了什么」写议会 #2 放行记录的位置或计数命令输出首行。缺行不得进入计划门。
