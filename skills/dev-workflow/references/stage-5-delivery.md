# 段⑤：产品交付

## 入口条件

- ④ 的 `gate-record.md` 行已齐六列，sdet 已签字。
- 交付物与验收结论一一对应（哪个产物由哪条验收结论支撑）。

## 出口判据

1. 交付审计完成：逐交付物核完成判据，每条有结论与证据位（`path:line` 或命令输出首行）。
2. 数字签字项齐：每条带数字的结论都有取数命令，且审计逐条复算过（不是只看结论）。
3. 未完成项 / 已知限制有明确落点（写进待办文档或明说不在本期），不含「以后再看」这类无落点项。
4. 运行时生效性可核：凡「新增规则 / 新增技能」类交付，已执行 `aas sync` 且体检为 0 待建链接（本机验）。

## 谁签

- **申报人**：主 agent（交付整理者）。
- **签字人**：**用户**（交付终验）；审计是审计表作者，不签验收。
- 签字必须附：交付审计表的结论行、每个数字项的复算命令与输出、运行时体检那一行的原文。

## 三权归属

| 权 | 谁 | 判据 |
|---|---|---|
| 申报 | 主 agent | 申报四条出口已齐，附审计表与复算输出 |
| 定性 | 用户（终验） | 逐交付物判过 / 不过；审计出具审计表，但定性人是用户 |
| 核对 | 审计 | 核数字项回原始命令；只核结论不核命令 = 证据栏空 |

## 常见漏项

- 数字只写结论不给取数命令 → 无法复算，审计只能信。
- 新增规则 / 技能没做运行时就位 → 仓内全绿但下一轮零加载。
- 已知限制写成「后续优化」→ 无落点、无负责人，等于消失。
- 交付审计表引用别的文档却没有那一行的证据位 → 证据栏空 = 不通过。
- 多个交付物共用一条结论 → 完成判据被稀释，逐交付物核对失效。

## 收口后

产出 `gate-record.md` 里 ⑤ 的那一行：六列齐，「核了什么」写审计结论行或复算命令输出首行。缺行 = 交付未收口。
