# 段①：PRD（需求产生 + 产品设计）

## 入口条件

- 用户给出想法、或给出市场 / 用户研究结论；或已有 PRD 被判定需要重开本段。
- 上游无前置段（本段是主干起点）。S2 之前「市场调研结论」入口由用户提供或省略，不阻塞。

## 出口判据

每条都必须能答「有 / 无 / 相等 / 不相等」，不写形容词：

1. §0 四栏（问题 / 用户 / 依据 / 边界）**每栏都有内容**，且依据栏每条都可追到来源（`path:line` 或外部链接 + 日期）。
2. 功能点清单与流程图**双向**一一对应：清单里每个 `F-xx` 在流程图出现，流程图每个节点在清单有编号；两向差集均为空。
3. 每个功能点都写了验收判据（可观测的行为或结果），没有「提升体验」这类无法判定的目标。
4. 非目标（明确不做的事）列出来了，每条写了背后的假设。

## 谁签

- **申报人**：产品经理（S2 前由主 agent 代拟，头部注明「代拟：主 agent」）。
- **签字人**：产品经理 + 用户；审计核 §0。
- 签字必须附证据：读了哪几节、跑过哪条命令（双向差集命令或人工核对表）、§0 四栏各自的来源。

## 三权归属

| 权 | 谁 | 判据 |
|---|---|---|
| 申报 | 产品经理（代拟期为主 agent） | 申报出口四条已齐，附 §0 四栏来源与双相差集结果 |
| 定性 | 产品经理 + 用户 | 用户签字前必须逐条看过功能点清单与验收判据；代拟者不签字 |
| 核对 | 审计 | 核 §0 四栏是否真有依据（不是「写了依据」四个字），核双相差集命令的输出 |

## 常见漏项

- 只写功能点、不画流程图 → 双向核对无法执行，第二条判据落空。
- 依据栏写「用户反馈」而无出处 → 不可核，等于没有依据。
- 验收判据写成「体验流畅」这类形容词 → 第四段无法验。
- 非目标不写 → 后面每一段都要重新讨论「这个做不做」。
- PRD 定稿后有人直接改功能点集合而不重签 §0 → 属「功能增删」类漂移（见强制约束 R5）。

## 收口后

产出 `references/gate-record.md` 里 ① 的那一行：六列齐，「核了什么」写命令输出首行或 `path:line`。缺行不得进入 ②。
