> 用法：逐字复制本骨架，按小节填。**每一项都要填满**——缺项 = 这一轮不算数。
> 判断标准见 `SKILL.md`「必须逐项填满的」。

## 范围（一旦定下，后续轮次只在其上做增量）

- **范围**：<工作区未提交 / 最近 N 次 commit / 那一个 commit（hash）>
- **审查启动**：<HH:MM>（= 开始全部 review 的时刻，取数：`node skills/review-log/scripts/time.mjs`；总耗时计时的起点。⚠️ 这条命令**必须带完整路径**、从仓库根跑——`scripts/time.mjs` 不存在，去掉 `skills/review-log/` 前缀会报 `Cannot find module`。命令要能跑通，优先于「本技能内引用用相对路径」那条规矩）
- **母分支 / 分支名**：<母分支 = 触发时的当前分支> / <新建的分支名（分支前置第 5 步必写，漏了中断恢复/收尾找不到母分支）>
- **起始 diff**：**<N> 文件 +<A> / -<B>**（取数命令：`git diff --stat`）
- **未跟踪新增**（取数命令：`git status --porcelain`）：<逐条列；这是本次审查的一部分，别漏>
- **⚠️ 本轮新增改动 = 上一轮修完后的 diff 增量** —— 这是「不重复审」的关键

## 轮次账

**轮次编号从这张表数，不许口头数。**

| 轮 | 起止（HH:MM） | 耗时 | OCR session id | FILES/COMMENTS | 逐条处置完 | 段二 | 段三 | 本轮核销 |
|---|---|---|---|---|---|---|---|---|
| 1 | <HH:MM>~<HH:MM> | <Nm> | `<uuid>` | <N> / <M> | ⬜ | ⬜ | ⬜ | ⬜ |

- 取数命令：`ocr session list`
- **耗时口径（用户裁定 2026-10-14，勿用「建分支→commit」代替）**：
  - **每轮耗时** = 从「开始那一轮 review」到「那一轮 review 结束」——起 = 该轮动手时刻（跑 `node skills/review-log/scripts/time.mjs` 记下），止 = 该轮三段处置完成、核销判定落账时（再跑一次 time.mjs）；差值分钟向上取整。
  - **总耗时** = 从「开始全部 review」到「全部 review 修复结束」——起 = 范围节「审查启动」，止 = 复查轮核销干净时；= 各轮耗时之和（核对一致）。
  - **不是「建分支 → commit」**：建分支是分支前置，commit 是收尾动作，都不计入 review 耗时。
- **取数动作强制**：起/止各跑一次 `node skills/review-log/scripts/time.mjs`，把两次输出直接抄进账本——**没有跑脚本取数就填的耗时 = 无效**（agent 无内置时钟，2026-10-14 实测教训）。
- **OCR `session id` 必须记** —— 它是唯一能回溯「当时报了哪些」的凭据。
- **⚠️ 如果相邻两轮报的是同一批**：说明范围没有做增量，两轮都在审全量 diff。记下来，并在「重复劳动」小节说明。

### 评论关联分析（修复前填，A4）

**本轮有要修的评论（≥1 条）时，动手修前先填这张表**（把本轮要修的评论当一个整体；判据按 review-loop 技能的修复纪律 A4 执行，填完核对三条，缺一条 = 本轮修复不算数）：① 本轮小节里有这张「评论关联分析」表；② 同文件 / 相邻代码的多条评论已合并成一次修；③ 动过签名 / 返回 / CLI / 共享常量的评论，契约链已按依赖排序（先契约后消费）。**本轮无要修的评论（0 条，如纯处置轮：不改 / 误报 / 候选，未修任何文件）时，本节写「无」即合规。**

| # | 评论 | 同文件/相邻代码 | 先后依赖 | 契约影响（签名/返回/CLI/常量 + 调用方数） | 预期返回变不变 | 处置（合并/排序/独立） |
|---|---|---|---|---|---|---|
| 1 | <OCR 第 N 条（段一·代码） / 段二 P0/P1/P2（文档扫描出的） / 段三对账或修复中自己发现的> | <改哪个文件> | <依赖谁 / 被谁依赖> | <影响面> | <是/否 + 说明> | <合并修 / 先修 / 独立修> |

**分级**（判哪档看「解法是否已判明」+「影响面多大」，三档动作按 review-loop 技能的修复纪律 A4）：

- **第一档 · 解法被 OCR 判明（带建议 / diff）+ 单文件** → 关联分析写一行，直接修。
- **第二档 · 解法未判明 + 有设计决策（签名 / 契约变更）** → 写修复 plan，plan 里要有**关联表 + 解法 + 调用方影响面**三项，并对 plan 做 md-review；三项缺一 = plan 不合格，md-review 无从审起。
- **第三档 · 解法未判明 + 跨文件 + 高影响** → 写 plan + 明确预期返回 / 调用方清单，**plan 同样要做 md-review**，修复后再用真实场景实测；这一档影响面最大、plan 写错代价最高，不得因为「已经写了 plan」就跳过 md-review。

### 本轮复盘（沉淀「暴露了什么机制缺陷」，不是「改了什么」）

> **每轮都要有，不许跳**（本轮无新暴露也要写一行「本轮无新机制缺陷」——留空分不清是「确实没有」还是「忘了写」）。
> **为什么不并进上面的「本轮改了什么」**：那节记「这轮改了什么」（一次性信息），本节记「**这轮暴露了什么会重复发生的机制缺陷**」——后者跨轮累积，**是下一轮唯一真正能省时间的输入**。只在复盘里写「改了什么」，下一轮还会踩同一个坑。

| 维度 | 填什么 |
|---|---|
| **一句话结论** | <若下轮换个 agent 也能听懂，**只写这一句**；长内容写独立文件（见下）> |
| **现象** | <哪条判据 / 哪步流程本轮才被发现有问题——**写具体位置或具体行为，不写「有问题」这种空话**> |
| **卡点** | <为什么前几轮没发现 / 为什么判据没拦住——若根因是「判据是散文形式」就直说> |
| **沉淀** | <改了什么载体：判据表 / 新检查 / 单一真相源 / 文档措辞。**只写已落地的**，没落地的写进下方「待办」并指向 `docs/after/`> |
| **验证过没有** | <✅ 已实测 / 🔶 部分（缺什么证据）/ ❌ 未验证。**写「已沉淀」但没实测要标 🔶 或 ❌**——不然下轮会当成已验证的结论直接引用> |
| **完整复盘** | <复盘短（表格装得下）→ 就地内联，上面**五条**填完即完成。复盘长（要展开证据链 / 多轮对比 / 表格）→ **另立 `retro-<轮次>-<主题>.md`，与本文件同级**，本行写文件名 + 一句话摘要> |

**「独立复盘文件」的两种形态**（本目录内，与本文件同级，不另开目录）：

| 形态 | 何时用 | 命名 |
|---|---|---|
| 就地内联（**默认**） | 复盘能压进上面那张表 | 不另立文件 |
| 独立文件 | 要展开证据链 / 多轮对比 / 有表格，且超过 5 分钟才能读完 | `retro-<轮次>-<主题>.md`，文件首行写 `# <一句话结论>` |

> ⚠️ **别默认立文件**：独立文件有「建了没人读」的风险（判据见全局规则 `reference-read-output-loop`——被动资源不取决于「它在」，取决于「执行路径是否强制经过它」）。**复盘文件的价值全靠下一轮真的去读**，所以见下面的读取硬约束。

**🔒 独立复盘文件的读取硬约束（不许当成「建议读」）**：

写下轮或收尾时**要按本轮结论做动作之前**，**必须**先读该轮指向的 `retro-*.md`，读完把它的「可操作结论」逐条抄进当轮待办；**跳过这一步 = 那一轮复盘不算数，等于没写**（判据同 `reference-read-output-loop`：停在「去读」的指针会被跳读）。

**一条判据**：如果下一轮换个 agent 来做同样的事，这条复盘能不能让他**少踩一次坑**？不能 → 这不是复盘，是流水账，重写。
