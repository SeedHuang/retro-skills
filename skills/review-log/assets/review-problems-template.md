# 逐条问题清单：<中文标题>

> 用法：**发现即记**；**已修的立刻从这里移走**。
> 修好的 bug 已经变成测试断言或代码注释 —— 那才是它的长期形态，
> 留在这里只会和代码说法漂移。
> **「不改」和「误报」必须留下**：测试记不住取舍的理由，
> 下一轮遇到同一个取舍会重新纠结一遍。

## 状态图例

| 状态 | 含义 | 必填 |
|---|---|---|
| `待处置` | 已确认是真问题，还没动手 | 问题出处 |
| `已修` | 改完了 | 细节看代码/测试，本表**留一行就删** |
| `不改` | 判定不改 | **锚点**（文件+行号+关键词）+ **理由**（判据在哪、为什么不改） |
| `误报` | 报了但实际不成立 | **锚点**（文件+行号+关键词）+ **证据**（实测命令 + 结果） |
| `候选` | 暂不处置，等触发信号 | **锚点**（文件+行号+关键词）+ **触发信号**（什么出现再评估） |

> **锚点是给「重复判定过滤」用的**（review-loop 每轮处置前先对照本清单过滤）：三要素齐了才能被规则匹配到、自动吞掉重复报，不再花一整轮重新纠结。锚点不全 = 下轮可能原样再报一遍。
