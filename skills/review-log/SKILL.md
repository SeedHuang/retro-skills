# review-log：给审查过程建账

## 这个技能解决什么

**没有账本时，审查必然重复劳动。**

实测 2026-10-08（9 轮审查）：第 8 轮与第 9 轮 OCR 报**同一批 3 条**，我处置了两遍 ——因为「我这是第几轮」是**口头数的**，没有可查的表去回答「这条是不是已经处理过」。

**判据：能不能回答「那条问题我处理过没有」。** 答不上来，就是在裸奔。

## 什么时候建账

| 情况 | 建不建 |
|---|---|
| 要开始一轮审查（review-loop 的任何模式） | **建** |
| session 要断、且审查未做完 | **更新已有账**，别新建 |
| 只是改个错别字、调一次格式 | 不建（不值得，比审查本身还贵） |

**账本位置**：`.session/reviews/<YYYY-MM-DD-HHMM>-<kebab-case 名字>/`

- `.session/` **不进 git**（`.gitignore` 已含）——它是过程，不是成果
- 命名用 **kebab-case + 时间戳**（跨平台安全 + 目录里能排序）
- 目录名的中文标题写在文件**首行**，不写进路径

## 目录里两个文件，各管一件事

| 文件 | 装什么 | 何时更新 |
|---|---|---|
| **`progress.md`** | **范围 + 轮次账 + 每轮三段记述 + 本轮改动 + 本轮复盘 + 核销判定** | 每轮结束追加 |
| **`problems.md`** | **逐条问题 → 解法 → 状态** | 发现即记；**已修的立刻移出去** |

**为什么不塞进一个文件**：两者**生命周期不同**。`progress.md` 是**活的**（每轮追加，永不定格）；`problems.md` 是**漏斗**（修好的移走，最后只剩「不改」和「误报」）。

**为什么 problems.md 里必须留「不改」和「误报」**：测试记不住**取舍的理由**。下一轮遇到同一个取舍时，没有这几行就会重新纠结一遍。

**已修的问题不要留在 `problems.md`**：修好的 bug 已经变成测试断言或代码注释 —— 那才是它的长期形态。留着只会和代码说法漂移。

## 骨架

**逐字复制**，别自己改结构：

- `assets/review-progress-template.md` → `progress.md`
- `assets/review-problems-template.md` → `problems.md`

## 必须逐项填满的（缺一项 = 这一轮不算数）

| 小节 | 缺了会怎样 |
|---|---|
| **范围 + 起始 diff**（带取数命令） | 下一轮不知道从哪开始审 → 重审全量 |
| **轮次账表**（含 OCR `session id` + 每轮起止/耗时） | **无法回答「这条处理过没有」** —— 这就是 2026-10-08 那次重复劳动的直接原因；无耗时则审查成本不可见 |
| 每段**跑了 / 空转**（空转要写明理由） | 「空转」被当成「已跑且没问题」 |
| 段二**扫了哪些 md（列全）** | 漏审的文档没人知道 |
| **评论关联分析**（本轮有要修的评论 ≥1 条时；本轮无要修评论写「无」即合规） | 评论被孤立修，A 改签名 B 漏改调用点 → 中间态损坏；没有整体设计 = 修一半 |
| **本轮改了什么 + 为什么** | 下一轮分不清「这行是我改的还是原有的」 |
| **验证命令 + 结果** | 把「测试绿了」当「做对了」（实测多次） |
| **未验证 / 无法验证的项** | 「没测过」的东西下一轮被当成「已验证」 |
| **本轮核销判定** | 又退回「轮数够了」 |
| **本轮复盘**（沉淀「暴露了什么机制缺陷」；无新暴露也要写一行「本轮无新机制缺陷」） | **下一轮会踩同一个坑**——各轮小节只记「这轮改了什么」，跨轮累积的教训没地方沉淀，复盘缺失等于下轮从零开始 |
| **总耗时**（最终结论） | 审查总成本不可见，跨次审查无法对比成本趋势 |

## 轮次编号从哪来

**从 `progress.md` 的轮次账表里数**，不许口头数。

OCR 跑完立刻把 `session id` 记进去 —— 取数命令：

```powershell
ocr session list
```

**为什么要记 id**：它是唯一能回溯「当时报了哪些」的凭据。今天我只能靠时间戳去猜哪两次 OCR 报的是同一批。

## 什么时候删

**这次 review 的全部条目都处置完 → `.session/reviews/<那个目录>/` 整个删掉。**

### 删之前：先归档复盘文件（硬步骤，不许跳）

**⚠️ 本目录下的 `retro-*.md` 是这次审查唯一不会被 git 收走的产物——删目录 = 一起没。**

**做法**（顺序不可颠倒）：

1. 若本目录有 `retro-*.md`（独立复盘文件，格式见模板「本轮复盘」节）→ **先**把它们搬到 `docs/superpowers/retro/<YYYY-MM-DD>-<那一次>/`（命名 `retro-<轮次>-<主题>.md` 不变）
2. 在 `docs/superpowers/retro/<那一次>/README.md` 留一行墓碑：`~~<原 .session 路径>~~ → <N> 个复盘文件迁入（本目录）`
3. **读完复盘文件确认没有未落地的「可操作结论」**（模板要求：读完把可操作结论抄进待办）——有未落地的，说明这次审查还没真处置完，**不许删**
4. 然后才删 `.session/reviews/<那个目录>/`

**为什么不留在 `.session/`**：`docs-convention` 的「`.session/` 里不放成果」**真实理由是「会与 git 里的真版本漂移」**（手抄一份进 `.session/`，会和 git 里的真版本不一致）。复盘文件**不进 git**（`.session/` 本身 gitignore），**不存在漂移** —— 所以它不违反那条硬边界，但**受「审查完删整个目录」约束**，故必须在删之前搬走。

### 删之前还要确认（原有）

结论已经进了**测试断言**（修好的 bug）、**代码注释 / spec**（不改的理由）、**`docs/after/`**（还没做的待决项）。

**`.session/` 里不放成果** —— 代码、断言、结论都进 git 或 `docs/`。放进来就是垃圾堆，且会与 git 里的真版本漂移。（**复盘是唯一例外，且已按上面第 1 步搬走**）

## 与其它技能的分工

| 要做的事 | 走哪个 |
|---|---|
| 真正去审（找问题、修问题） | **`review-loop`** |
| **记录**这次审了什么（过程账） | **本技能** |
| 未完成事项 / 待决清单 / 跨 session 待办 | **`writing-after-docs`**（**只落 `docs/after/`** ——待决事不进 `.session/`，规则 `docs-convention`「待决事项只有一处」）。⚠️ 待办文件里不许有「已完成」档——做完即删 |
| 长期结论（定稿设计、验收标准） | `docs/superpowers/specs/` |

**「审查纪律」（什么时候停、不许问用户、不拿成本当理由）在全局规则 `how-i-must-reason.md` 里**，本技能不重定义。
