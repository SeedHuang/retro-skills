# 有效性台账模板（逐字使用）

> 本文件是 **`effectiveness.md` 结构的权威定义方**。`retro-verify/SKILL.md` 只指向这里，不复制；spec §14.8 只补判定口径。
> **必须逐字使用**。

## 落点

**每个目标一份** `effectiveness.md`，落**该目标在 KB 的归属目录**：

| 目标类型 | 落点 |
|---|---|
| 技能 | `<KB>/skills/<技能名>/effectiveness.md` |
| rule / automation 条目 | `<KB>/projects/<项目>/effectiveness.md` 或 `<KB>/universal/effectiveness.md` |

**不落** retro-skills 的技能目录（那里要保持发布纯净、不放个人数据）。台账**纳入体积治理**（超量归档）。

## 模板

```markdown
# 有效性台账：<目标名>

- 目标：<技能名 或 KB 条目 ID>
- 载体：<rule | skill | automation>
- 落点：<载体路径>
- 事前预期：<区间>（依据：基线 / 历史同类改动 / 覆盖面）

| 期 | 日期 | 机会A | 复发B | 新问题N | 认可P | 事前预期（区间） | 复发信号 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 改前 | YYYY-MM-DD | 6 | 4 | 1 | 0 | — | `<正则 / 命令>` | 基线 |
| 第1期 | YYYY-MM-DD | … | … | … | … | … | … | |
```

（台账不存在时由 `verify record` 建表头。）

## 字段口径

| 列 | 含义 | 取数方式 |
|---|---|---|
| **期** | 第几期 | `改前` = 基线；后接 `第1期`、`第2期`… |
| **机会 A** | 目标触发面内被记录到的相关场景数 | **自动化** = 该检查被执行次数；**rule / skill** = 触发面内相关场景数（从 `<session 目录>/userwords.md` / `<session 目录>/moments.md` / 对话数） |
| **复发 B** | 违反已发生次数 | 同上来源 |
| **新问题 N** | 该载体引入的新问题数 | 归因要标「不纯」——同期有其它改动时降级 |
| **认可 P** | 用户认可次数 | `<session 目录>/moments.md` 正面 / `<session 目录>/userwords.md` 情绪=正面（认可 = 情绪正面，不是立场） |
| **事前预期** | 改之前给的区间 | **必须改前给**，事后编等于没验 |
| **复发信号** | 怎么机器判定复发 | 写正则或命令，便于后续自动核 |

**数不出 → 该期标「无法评分」，不填假数。**

## 硬约束

1. **事前预期必须改前给**——事后补等于没验
2. **「没看到复发」≠「没有复发」**：只有 **A ≥ 5 且 B = 0** 才敢说「有效」
3. **置信门槛（A）**：0–1 不打分；2–4 只定性；5–9 量级可参考；**≥10 趋势可信**
4. **只纵向比**（同一目标前后），不横向比其它 skill
5. **算数走 CLI 不 import**：`lessons verify record|score|trend|expect <目标>`（避免跨技能「单装扑空」）
6. **无效 / 更差不得留在 landed 假装成功** → 回退方案先交用户确认，**先退载体 → 后改账目 `regressed`（附现场）**
