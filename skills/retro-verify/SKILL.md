# 有效性验证（retro-verify）

飞轮缺的一环：**落地之后，怎么知道改对了、改管用了**。没有它，飞轮是开环。

## 职责

对一个**已落地**的载体（skill / rule / 自动化），回答两件事：

1. **有没有效**：复发率 + 机会数 → 5 档；
2. **有没有达到事前预期**：实测 vs 预期对账。

无效 / 更差 → 出**回退方案**（**用户确认后**才退）。

**不做**：不采集事实（走 `retro-collect`）、不首次归置（走 `retro-institutionalize`）、不改载体本体（退回 `evolving-skills`）。

## 前置

- 目标**已 landed**（账本条目状态 `landed(→载体)`）；查不到或还没落地 → 拒绝。
- KB 未初始化 → 拒绝，转 `managing-lessons-store` 完成 bootstrap。

## 流程（六步）

1. **取目标**：`lessons show <ID>` 找到条目，确认已 landed，拿到载体与落点。
2. **取数**：`lessons verify score <目标>` → A / B / N / P + 复发率 / 新问题率 / 认可率。
   - **机会数 A 的取数口径**（否则评分悬空，不许打分）：**自动化** = 该检查被执行的次数；**rule/skill** = 该目标触发面内、被记录到的相关场景数（从 moments / 对话里数）。**数不出 → 标「无法评分」**。
3. **比上期**：`lessons verify trend <目标>` → 本期 vs 上期 → Δ 改善量 → **5 档**。
4. **对账预期**：`lessons verify expect <目标>` → 实测 vs 事前预期（台账里）。
5. **判**：
   - **复发了** → **分型**（没生效 / 判据不对 / 归类错）；每类**要拿得出证据**，"归类错"或拿不出证据 → **交用户**；
   - **有效** → 记一行台账。
6. **无效 / 更差** → 出**回退方案**：先出方案 + 理由 → **用户确认** → **先退载体 → 后改账目 `regressed`（附现场）** → 回炉。**绝不留在 landed 假装成功。**

## 判定标准（权威在 spec）

**详细口径以 `docs/superpowers/specs/2026-10-01-retro-self-improvement-design.md` §14 为准**，本技能不重定义。要点：

- **指标方向**：复发率 `↓ 好`、新问题率 `↓ 好`、认可率 `↑ 好`、机会数 **中性**（只当门槛）；
- **主判据 = 复发率**；新问题率 / 认可率是**警告灯**，方向冲突 → 结论**降级 + 加注**；**只纵向比**；
- **5 档**由 Δ 复发率定：≤−30% 明显变好 ｜ −30~−10% 略微变好 ｜ −10~+10% 看不出 ｜ +10~+30% 有劣化 ｜ ≥+30% 明显劣化；
- **置信门槛（A）**：0–1 不打分；2–4 只定性；5–9 量级可参考；**≥10 趋势可信**；
- **"没看到复发" ≠ "没有复发"**：**A ≥ 5 且 B = 0** 才敢说"有效"。

## 反例集

| 反例 | 为什么错 |
|---|---|
| A < 2 就打分 / 下结论 | 小样本，率是噪声 |
| 把"没记录到"当"没复发" | 漏记 → 假"有效" |
| 同期还有别的改动/环境变化却归功于它 | **归因不纯** → 应标不纯、降级为"看不出差别" |
| 数不出信号却硬编个数 | 假的精确；应标"无法评分" |
| 自动回退、不告诉用户 | 回退也是"改载体"，必须走用户确认 |
| 事后编预期 | 预期必须在**改之前**给，事后给等于没验 |

## 算数（工具）

- 命令住 **`lessons.mjs`**（KB 解析唯一处）：`node <managing-lessons-store>/scripts/lessons.mjs verify score|trend|check|expect <目标>`；
- **调它的 CLI 取数，不 import**（避跨技能"单装扑空"）。

## 台账

- 每个目标一份 `effectiveness.md`，落**该目标在 KB 的归属目录**（技能 → `<KB>/skills/<技能名>/`；rule / automation 条目 → `<KB>/projects/<项目>/` 或 `<KB>/universal/`）；
- 内容：分数 + 事前预期 + 复发信号（表结构见 spec §14.8）；
- **不落** retro-skills 的技能目录（那里要保持发布纯净、不放个人数据）。

## 何时跑

阶段收口 / 用户说"过一遍 <目标> 的有效性" / 巡检报"该看了"时。

## 常见错误

| 错误 | 纠正 |
|---|---|
| 目标还没 landed 就来验 | 先落地方案，再验 |
| 拿别的 skill 的复发率横向比 | **只纵向比**（同一目标前后） |
| 5 档按绝对分值套 | 5 档由 **Δ 变化量**定，不看绝对水平 |
| 复发就判死 | 先分型（没生效/判据不对/归类错），要证据 |
| 台账写进技能仓库 | 落 **KB** 的 `skills/<技能名>/`，不是 retro-skills 仓库 |
