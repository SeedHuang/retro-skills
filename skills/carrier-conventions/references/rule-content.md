# rule 正文里放什么、不放什么

## 四类该进（缺一不可）

| 类 | 形态 | 反例（缺这类时读者的实际困境） |
|---|---|---|
| ① 义务句 | 「必须 / 禁止 + 动作 + 对象」 | 「注意保持一致性」——不知道要做什么动作 |
| ② 判定动作 | 命令 + 退出码 / 计数 / 集合比较 / 空非空 / 带字面量枚举 | 「要仔细核对」——谁都无法复核 |
| ③ 边界与例外 | `除非 / 只许 / 不再 / 不得` 明写 | 例外藏在解释句里，执行时一定漏 |
| ④ 来源锚 | 一行 `> 来源：PRD §X / 用户裁定 YYYY-MM-DD` | 三个月后没人知道这条从哪来、能不能翻案 |

## 四类不该进

| 内容 | 去哪 | 判据 |
|---|---|---|
| 为什么 / 病根 / 实测记录 | references | 删掉它，「判定动作」一字不变 |
| 历史沿革（旧版怎么写的） | git | `git log` 可查即不进正文 |
| 反例清单 | 测试断言 | 有测试就进测试；无测试才在 references 压一行 |
| 操作步骤 / 模板 / 清单表 | 脚本或 references | 正文只留一句指针，指向真实存在的文件 |

## 判别法两条

1. **删掉这段，「判定动作」变不变？** 变 = 判据（提回正文压缩成一句）；不变 = 说明（删，git 里有）。
2. **已有脚本或技能持有它吗？** 已持有 → 移过去，并检查是否形成了第二份真相。

唯一例外：理由句里带着边界条件（`除非` / `只许` 藏在解释里）。处置 = 把边界提回判据行，再删解释句；不许整段删。

## 正文四层

| 层 | 内容 | 落在哪 |
|---|---|---|
| 判据层 | 义务 + 判定动作 | 必进上下文（rule 正文） |
| 边界层 | 例外 / 除非 / 只许 | 紧邻判据行，不隔节 |
| 溯源层 | 一行来源锚 | 判据之后、说明之前 |
| 说明层 | 为什么、实测、沿革 | references；正文只留一行指针 |

指针指向的文件必须真实存在（`Test-Path` 为 True）；跨仓指针带仓前缀（`（仓：retro-skills / evo-retro-skills-inspector）`）；references 不复制判据正文。

## 正反例

**正例**（义务 + 判定动作同在一行）

```
每条 rule 必须有一行 `> 来源`；检查命令：`Grep '^> 来源' rules/*.md` 命中数 = 文件数。
```

**反例**（只有评价，没有判定动作）

```
来源信息要写清楚，方便以后追溯。
```
