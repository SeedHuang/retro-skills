# spec 与 testcase 绑定

> 承接原 `spec-testcase-gate`（留档 `docs/bak/rules/spec-testcase-gate.md`）。范围：`docs/superpowers/specs/` 下的 spec，含 spike 类与目录形态。

## 五条判据（缺一不合格）

| # | 判据 | 怎么算合格 |
|---|---|---|
| 1 | 文件存在 | 与 spec 同目录；文件名 = spec 去掉 `.md` 后加 `-testcase.md`；目录形态用目录内 `testcase.md` |
| 2 | 编写者独立 | 由 `senior-sdet` 在全新上下文编写；编写者 ≠ spec 作者 ≠ 施工者；文件头写「编写者 / 独立性声明」 |
| 3 | 用例合格 | 每条用例五要素齐（覆盖 / 前置 / 步骤 / 预期 / 判据）；负例与边界条数 ≥ 正例；覆盖总表每行指回 spec 节号或 R 编号 |
| 4 | spec 外链 | spec 的测试节只写「测什么 / 为什么」，并写「测试用例文件：`<路径>`」；不内联用例 |
| 5 | 一起送审 | spec 与 testcase 作为一件交付物送议会；缺 testcase 不得送议会、不得进 plan |

## 无子代理环境

只能产出草稿并在文件头标「降级模式（角色卡内联）」，不得定稿；同一实例写、同一实例判，等于把自评偏差搬进验收。

## 正例 / 反例

- 正例：写 `2026-10-18-xxx-design.md` 时同批派 `senior-sdet` 产出 `2026-10-18-xxx-testcase.md`；spec 测试节写外链；议会开卷清单同时列两份。
- 反例：spec 写完直接进 plan，测试以后补。
- 反例：spec 作者自己顺手写用例，或在 spec 里内联用例表。
- 反例：议会只送 spec、不送 testcase。

## 适用范围

来源不豁免：子代理、脚本、模板、AI 生成的 spec 同样要过；存量 spec 被修订并进入 plan 时同样要补。

## 冲突裁决

与「先写 spec、测试以后补」「这次先快速交付」「用例由 spec 作者顺手写」冲突时，以本节为准；拿不准先停下说明，等确认再动。

## 例外

只有一类：2026-10-18 之前已定稿的存量 spec 不追溯。spike 类 spec、目录形态 spec 都不在例外内。

## 触发时机

- 写或修改 spec 时；
- 把 spec 送议会之前；
- 让 spec 进入 plan 之前；
- 评审或审计发现 spec 无 testcase 时，按本节打回。

## 验证

送审前逐条核五条判据：文件存在 → 独立性声明在位 → 五要素与负例比例 → spec 外链在位 → 开卷清单含两份。当前没有常驻脚本执行这四条；人工核对结果写进送审说明，脚本落地后再改为命令判据。
