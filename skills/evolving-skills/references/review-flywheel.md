# 技能自我进化的复盘回流（通用飞轮）

> 适用：任何技能在使用中被发现「本应覆盖但没覆盖」的问题时。multi-lens-review 与 prd-to-specs 均引用本卡；新增同类回流时优先引用，不复制。

## 触发

后续阶段（开发/测试/使用）发现**本技能本应覆盖但没覆盖**的问题。

## 三步（记要快，改要等）

1. **先记录不阻塞**：按复盘套件流程落错题集 KB——`retro-collect` / `retro-analyze`，条目进 `<KB>/skills/<本技能名>/ledger.md`（教训落点 = 本技能的手法条目 / 角色面板必问项 / 流程节 / 质量门 / 模板；**不写进本技能目录**，目录保持发布纯净）
2. **只告知，不追问**：顶多说一句「已记账（`<ID>`），落地留你在 lessons 处理」。
   **禁止追问「要不要现在就改」**——那会把用户当下正在进行的主线任务拉歪。改技能是大动作（读卡、六步协议、独立 agent），插进评审/开发中间，上下文一断，两头都做不好。
3. **「改」交给 lessons 发起**：由**用户在 lessons 发起落地分析**（一次一个技能）——读账本 + 历史复盘 + moments（锚点） + 用户画像 → 出方案 → 用户判断合理 → 才走 `evolving-skills`（六步协议 + 差异卡：失败场景先行、攒批、独立合并、体积守卫）。
   **绝不在使用当场改，也绝不在收口/巡检环节问「要不要改」。**

**边界**：本回流只做「记录 + 一句告知」；「要不要落地成 rule/skill」的判断与发起，**永远归用户在 lessons**——与 `using-retrospective` 的收集/落地边界一致。

飞轮：使用 → 发现 → 归因 → 记账 →（用户在 lessons 发起）→ 方法进化 → 更强的技能。
