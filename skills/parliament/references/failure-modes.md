# failure-modes —— 病根表与判据分配

### 9.1 「写了规则但 AI 没执行」13 病根（四层）

加载层：①没同步从未生效 ②写在 AI 读不到的地方 ③调度词不匹配。
理解层：④执行条件模糊 ⑤没说清要做什么（读完无产出要求 = 可跳过）⑥判据不可判定 ⑦冲突无裁决优先级。
执行层：⑧不在必经路上 ⑨成本太高被绕过 ⑩例外太宽吞掉规则 ⑪角色不清。
验证层：⑫执行了没留产物 ⑬假验 / 编证据 / 两份漂移。

**试金石**：任何指令写完问一句——「它被执行了，我怎么知道？」答不出产物/命令的，指令还没写完。

### 9.3 复盘回流

后续使用中发现「本应议会抓到却没抓到」的问题：先记账不阻塞（进本技能 KB 账本），只告知「已记账」；「改」由用户在 lessons 发起后走 evolving-skills。自由探索中反复出现的高价值问题（≥2 次）升格进固定清单。

**判据回流必须附对照表（防漏抄，实测漏抄 2 条被对答案环节抓到）**：把报告/教训条目抄进角色固定清单（ROLES 数据）时，必须同时产出「来源条目 ↔ 固定清单条目」逐条对照表（来源条目编号 → 落进哪席哪条，一行一条），逐条对账齐后才算回流完成；对照表随当次回流记录落盘，无对照表 = 回流未完成，不得宣告闭环。
