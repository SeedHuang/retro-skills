# doc-taxonomy —— 文档类型分诊判据表

本文档 = 议会评审按文档类型分诊的判据表。

| 类型 | 判据一句话 | 评审关注点（主责评委） | 完成判据（终局审计 B 节） |
|---|---|---|---|
| spec | 已定稿设计文档 | 逻辑闭环、无第二份真相、失败面画全（前端+后端+审计） | Backlog 三表齐、P2 全落态、P0/P1=0 |
| plan | 排期的执行步骤 | 步骤原子、依赖顺序、验收与 spec 对齐（测试+后端） | 勾选框全终态、每任务有验收命令 |
| rule | 条文化约束 | 13 病根表：在必经路上/判据可判定/执行留痕/冲突裁决/例外从严（AI+审计） | 触发时机+验证节存在、可证伪 |
| skill | 流程方法文档 | 读→产出闭环、路径纪律、<500 行、description 只写触发（AI+审计） | check 脚本 0 findings、资产三档合规 |
| agents | 子代理定义（.trae/agents/*.md 或本仓 agents/*.md） | description 具体度、tools 最小化、双清单在位、格式闭环（AI+审计） | frontmatter 合法、生成物与源一致 |
| 描述性文档 | README / guide | 任意章节可进入、术语有定义、与现状一致（读者代表） | 抽查计数/路径与实测一致 |
| 记录型文档 | 账本 / progress / handoff | 手抄数字/时间/✅ 与权威记录一致、处置闭环、引用真实（读者代表+审计） | 计数可复算、无悬空引用、每个 ✅ 有证据 |
| 探索稿 | docs/after | 「未决」标记在位、搬走条件写明（读者代表） | 阶段标记正确、待办可执行 |

## 各类型评委关注点展开

### spec —— 主责评委：前端、后端、审计

审 spec 最容易漏的是失败面只画了实现层、没画后端数据流与审计闸门——判据要求「失败面画全（前端+后端+审计）」，三席各自固定清单合起来才覆盖全。其次是第二份真相：同一信息在 spec 与别处两处维护，前端/后端两席都要查，但常常各自只查自己那一侧。关注点来源：`agents/reviewer-frontend.md`、`agents/reviewer-backend.md`、`agents/reviewer-audit.md` 该席固定清单。

### plan —— 主责评委：测试、后端

审 plan 最容易漏的是步骤不原子（一步做多件事、无法单独验收）和依赖顺序只写先后、不写为什么这个顺序。测试评委的验收可验证性判据与后端评委的依赖/契约判据正好管这两点。关注点来源：`agents/reviewer-qa.md`、`agents/reviewer-backend.md` 该席固定清单。

### rule —— 主责评委：AI、审计

审 rule 最容易漏的是「判据可判定」落空——写的是靠自觉的点，不是 grep/退出码/计数能判的点；AI 评委的机器可判定判据与审计的可证伪判据共同把关。其次是冲突裁决优先级缺失：规则之间打架时没写谁赢。关注点来源：`agents/reviewer-ai.md`、`agents/reviewer-audit.md` 该席固定清单。

### skill —— 主责评委：AI、审计

审 skill 最容易漏的是「读→产出闭环」：引用 reference 的指令只有「去读」、没有「读完必须产出什么」——AI 评委固定清单判据 1 逐条核这个。其次是路径纪律：跨技能引用写对方内部路径、脚本守卫用路径字符串比较。审计的资产三档合规与 check 脚本 0 findings 兜底。关注点来源：`agents/reviewer-ai.md`、`agents/reviewer-audit.md` 该席固定清单。

### agents —— 主责评委：AI、审计

审 agents 最容易漏的是 description 写了流程摘要（agent 会照摘要办事跳过正文）和 tools 没最小化——AI 评委固定清单判据 2/3 专管这两点；审计核 frontmatter 合法与「生成物与源一致」（手改生成物 = 漂移）。关注点来源：`agents/reviewer-ai.md`、`agents/reviewer-audit.md` 该席固定清单。

### 描述性文档 —— 主责评委：读者代表

审描述性文档最容易漏的是「任意章节可进入」——读者不是从头读起，而是中途打开某一节，术语无定义、编号悬空都会让中途读者迷路。读者代表固定清单判据 1-3 逐条核。关注点来源：`agents/reviewer-reader.md` 该席固定清单。

### 记录型文档 —— 主责评委：读者代表、审计

审记录型文档最容易漏的是手抄数字/时间/✅ 没核对权威记录——读者代表判据 5 核「每个 ✅ 背后有证据」，审计判据 4 核计数可复算。其次是处置闭环：记了问题但没记谁、何时、怎么处置。关注点来源：`agents/reviewer-reader.md`、`agents/reviewer-audit.md` 该席固定清单。

### 探索稿 —— 主责评委：读者代表

审探索稿最容易漏的是「未决」标记丢失或被当成定稿引用——读者代表固定清单判据 4（定稿结论与猜想一眼能区分）和判据 6（状态标注自洽）专管这个。其次是搬走条件没写明，做完的探索稿没人迁走。关注点来源：`agents/reviewer-reader.md` 该席固定清单。
