# submission-matrix —— 各类文档送审必带件判据

> 本文档 = 议会开评前的「送审材料」矩阵。**完成判据以 `references/doc-taxonomy.md` 为唯一权威**；本矩阵只负责「送审必带件」，不复制判据全文。
> 两档必须分开写：**明文硬门** = 规则或该文档自己的评审规则明确要求；**建议随附** = 从完成判据推导，缺了要写理由，但不等于违规。
> 路由键是**文档类型**；「技术评审」等口语别名只用于沟通，不作为必带件判据。

## 1 矩阵

| 文档类型 | 判据一句话 | 明文硬门 | 建议随附 | testcase | 机器证据（示例） | 主责评委 | 不审什么 |
|---|---|---|---|---|---|---|---|
| PRD | 需求定义：要做什么、为什么、验收与 spec 路线图 | 被审 PRD + 索引；一次只审一份（该 PRD 自己的评审规则） | 评审账本 / 已知雷区 / 上游裁定 | 否（PRD 不直接产 testcase；拆出的 spec 才要） | 两份文档路径 + SHA256；索引里的状态与通过判据 | 读者 + 审计（技术 PRD 加产品 / 后端 / 测试） | 已通过且依赖未变的 PRD；实现细节；代码 |
| spec | 已定稿设计：怎么做、失败面画全 | **spec + testcase 一件**（`spec-testcase-gate` 判据 1–5） | PRD 作为决策源 / 目标 rule 或结构锚点 / 已知雷区 | **是（硬门）** | testcase 五条判据核对（脚本未落地时人工 + 计数）；spec 外链；`^### TC-` 计数 | 前端 / 后端 / 审计；测试主审 testcase | 代码施工；P2/P3；已冻结的 PRD |
| plan | 排期的执行步骤 | 无明文 | plan + 对应 spec（验收锚点）+ 每任务验收命令 | 否（引用 spec 的 testcase） | 每任务验收命令；spec ↔ Task 映射 | 测试 + 后端 | spec 设计本身；代码实现 |
| rule | 条文化约束 | 无明文 | rule 文件 + rule-inspector 评分/标注 + 改前改后对照（若修订） | 否 | rule-inspector 命令输出；触发时机与验证节 | AI + 审计 | 其它 rule；运行时行为 |
| skill | 流程方法文档 | 无明文 | SKILL.md + scripts/references/assets + 技能守卫输出 | 否 | `npm run check` 0 findings；资产三档 | AI + 审计 | 业务代码；其它 skill |
| agents | 子代理定义 | 无明文 | agents 产物 + 生成器 `--check` 输出 | 否 | 生成物与源一致；frontmatter 合法 | AI + 审计 | skill / rule |
| 描述性文档 | README / guide | 无明文 | 文档 + 它引用的权威源 | 否 | 抽查计数 / 路径与实测一致 | 读者 | 记录型账本 |
| 记录型文档 | 账本 / progress / handoff | 无明文 | 账本 + 权威记录（用于对账） | 否 | 取数命令 + 输出；无悬空引用；每个 ✅ 有证据 | 读者 + 审计 | 设计文档 |
| 探索稿 | docs/after 的探索稿 | 无明文 | 探索稿 + 阶段标记 / 搬走条件 | 否 | 未决标记在位；搬走条件可执行 | 读者 | 定稿结论 |

## 2 口语别名（只用于沟通，不作路由键）

| 口语叫法 | 对应文档类型 | 送审件 |
|---|---|---|
| 需求评审 | PRD | PRD + 索引 |
| 技术设计评审 | spec | spec + testcase（一件） |
| 实施计划评审 | plan | plan + spec |
| 规则 / 技能 / 代理评审 | rule / skill / agents | 对应产物 + 机器证据 |
| 文档 / 记录评审 | 描述性 / 记录型 / 探索稿 | 原文档 + 权威源 |

**为什么单列这张表**：同一个「技术评审」可能指 spec、plan、rule、skill、agents；如果拿口语别名当必带件依据，就会把 spec 的 testcase 硬门错误地套到 plan，或把 rule 的评分证据漏掉。

## 3 不放进送审材料

| 不放进 | 为什么 |
|---|---|
| 尚未施工的代码 | 被审对象是文档；代码还没生成，评审无法核 |
| 未来里程碑（P2/P3 等） | 本轮不审；放进来会把「以后要做」当成「现在必须做」 |
| 已冻结且依赖未变的文档 | 议会规则明确不重审；重复开卷会污染范围 |
| 评审结论 / 个人笔记 / 猜测 | 送审说明是清单，不是结论；结论由评审产出 |
| 无法复算的口头数字 | 证据必须带命令 + 输出；口头数字不算证据 |

## 4 维护同步

- `references/doc-taxonomy.md` 改「类型 / 完成判据」时，同批改本矩阵对应行；两处不一致 = 送审清单漂移。
- 本矩阵不复制完成判据全文；写「完成判据以 `references/doc-taxonomy.md` 为准」即可。
- 新增文档类型：先在 `references/doc-taxonomy.md` 加类型与完成判据，再加本矩阵一行。
- 评审中发现的送审材料缺口，先记本技能账本，不在此处当场改判据。
