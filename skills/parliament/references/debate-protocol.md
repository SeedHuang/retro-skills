# debate-protocol —— 流程协议与侦探判据

## 评审轮

被点评委并行独立出卡（防从众）→ 主持人汇总、去重、按族分组 → 追问轮把清单发全体评委补视角（互补 = 结构性动作，不是口号）。

## 答辩

≤3 轮；收敛 = 问题清单清零或全部裁决关闭；**3 评审轮后仍有 P0/P1 → 升级用户介入，评审不停止，继续到 P0=0 且 P1=0**；P2 可挂 `docs/after/`。

## 升级协议

（仅 3 轮不收敛触发）：争议焦点一句话 + 双方各自【立场 / 赞成原因 / 反对对方原因 / 摸查记录（查了什么 + 命令 + 结果，必填）】+ 双方各自具体解法（都必填）+ 侦探驳回记录（无摸查 = 臆想争端，退回不升级）。**任何一方只提问题不给解法 = 不许升级。**

## 两档审计

- 轮间核对单（每轮必过，不过 = 下一轮不得开始）：第 0 项轮际对账 + 卡片字段齐 + 答辩字段齐 + 本轮终态对账 + 侦探观察存在且卡号真实 + 汇总未丢卡。机械计数由审计员自跑命令（已授 `command` 档），主持人代跑或代填一律判无效；审计员核对并抽查 1-2 项语义（审计员不从头数数，主持人不自签自己的账，侦探盯两边）。
- 交付审计表（终局一次）：A 节过程闭环 6 项（终态对账 / P0P1 清零 / 落点抽查 ≥3 / P2 三态齐 / 数字一致 / 升级项有终裁）+ B 节按 doc-taxonomy 完成判据逐交付物核对。结论三态：通过 / 有条件通过（候选项+触发信号列明）/ 不通过（打回清单）。**审计两表必由审计员本人实例完成；证据栏空 = 不通过，不是待补。**

## 修复纪律

（继承旧 skill）：每修复带落点 → 修复即二次评审重跑手法 3（跨章节一致性）→ 同族扫描 → 修复引入自查。

## 侦探（detective-observer）

| 项 | 定义 |
|---|---|
| description 触发条件 | 在议会评审中担任侦探。每轮答辩结束后由主持人调度做行为核实时调用 |
| 身份 | 资深观察员，只记录不裁决；对「评委刁难、答辩回避、主持人失职」三类行为做机械核对 |
| 固定清单（即机械判据） | **评委刁难**：卡缺证据字段 / 缺建议解法 / 级别与证据不匹配（无 P0 形态证据却标 P0）/ 重提已关闭问题且无新证据。**答辩回避**：判定「反驳」但依据为空 / 依据含「感觉、应该、大概」类词 / 承诺修复但无落点 / 同一问题第 2 轮答辩无新证据仍维持原立场。**主持人失职**：丢卡（收卡数 − 有理由关闭数 ≠ 进答辩清单数）/ 压卡（收到未进清单且无理由）/ 代填审计两表。**工具越权**：`git status --porcelain` 与轮初快照比对出现非预期变更 / 跑了白名单外命令（commit、push、checkout、reset、restore、rm、`--apply`、写盘）；命中记「P0 形态」观察，交议长转卡 |
| 处置表（写进 SHARED_BLOCK） | 废卡率 ≥1/3 → 该评委本轮产出全部复审，复审仍超 → 下轮只答固定清单；连续 2 轮回避 → 该问题强制进升级报告；无理由丢卡 → 升级报告项；主持人代填审计表 → 记违规直报用户 |
| 自身诚实义务 | 每条观察记录引用真实卡号（主持人核存在性）；无发现时显式写「本轮无异常」；观察记录原文进最终报告，不得删改 |
| 输出格式 | 观察记录：卡号 / 对象 / 行为类型 / 判定依据（引用原文）/ 处置建议 |

## 六手法（技术维度通用手法层，评审时逐项执行）

### 手法 1：操作序列推演（产出最高，最先做）

把每条操作当状态转移函数，走查四类序列：

- **重复执行** op → op：再跑一次，数据被污染吗？（幂等性）
- **交叉执行** A → B → A：另一个操作会冲掉这个操作的记录吗？
- **中断恢复**：任意步骤崩溃 → 重跑幂等还是卡死？
- **接管时刻**（实战教训固化）：操作集不只包括本工具的命令——**用户在工具接管之前手动制造过的任意脏状态**（手动改文件、半配置、外部工具产物）都要当作合法输入推演。接管逻辑必须校验前提，不得假设干净世界。

心法：优先攻击"最普通的操作 × 最坏时机"。

### 手法 2：数据字段生命周期审计

四问：谁写？谁读？何时失效？失效后残留会怎样？重点核对**读取点合法性**——字段读取时是否校验了"当前值来自合法来源"（防被外部状态污染后当作有效值持久化）。

### 手法 3：跨章节一致性矩阵

- 表格 × 表格（依赖表 vs 执行顺序、命令表 vs 章节引用）
- 文字 × 图（描述分支 vs 时序图/流程图分支）
- 验收 × 现状（验收标准 vs 代码库/环境事实）——断言"X 问题不存在"前，先列全 X 的失败模式（爆炸式/静默式）逐个取证（实战教训固化：hooks 不炸 ≠ 无双实例，antd 双实例是 context 级静默失败；产物与结论矛盾即复检信号）
- 引用 × 定义（正文引用的编号在文档内必须有定义或对照表——评审编号落进产出物时，对无对话记忆的读者是悬空引用）

### 手法 4：输入空间枚举

每个输入点过一遍：空 / 不存在 / 非法格式 / 含空格 / 多个 / 重复 / 指向异常结构。

### 手法 5：假设显式化

挖出没写出来的前提假设，逐个标记：已验证 / 待验证 / 需写成前置条件。扫描范围三处：

- 明示的技术依赖（目录结构、工具行为、目标项目配置）
- **平台机制断言**（实战教训固化）：每个"用 X 机制实现 Y"，验证 X 在目标平台的真实行为（如 lstat 对 junction 返回 false、CRLF/BOM、路径大小写）
- **决策背后的隐含假设**：每条"不做 X"的非目标决策，背后假设了用户的什么状态？（如"不代写依赖"隐含"lib 都发布过"）

### 手法 6：可逆性 → 确认策略一致性

破坏性操作按可逆性排序，核对确认策略：可逆不确认、不可逆必确认。
