# 判据全集（rule-optimizer）

> 本文件是 rule-optimizer skill 的判据全集：来源类型枚举、层级规范、三检验、评分维度定义（D1–D5）、健康分级、基线口径与取数命令。内容与 spec `2026-10-08-rule-optimizer-design.md` 对应章节**单源一致**，是 `scripts/score.mjs` 的实现依据（agent READ，不进上下文执行）。

## 1. 来源类型与约束力

### 1.1 来源类型（权限标记，管「谁定的」）

| 类型 | 现有规则 |
|---|---|
| `用户当场指令` | `global-ask-before-acting`、`plain-language-to-user`、`docs-convention`、`how-i-must-reason` |
| `评审第 N 轮` | `landing-sweep` |
| `实测/踩坑` | `powershell-file-encoding`、`import-guard`、`skill-assets-convention`、`ts-expect-error`、`vitest-queued-alternative` |
| `项目约定` | `poll-deferred-at-start`、`no-git-write`、`code-style`、`rules-single-source` |

> 注：来源类型是权限标记（这条规则谁定的、可审计），**不决定约束力**——约束力看措辞（§1.2）。

### 1.2 约束力（实际强度，客观判定）

**判定方法（可复算）**：grep 规则正文的措辞词，按**最高档**定级：

```
绝对禁止|严禁   → 绝对禁止级
禁止|不得|不要|不能|不许  → 禁止级（无绝对禁止时）
必须            → 必须级（无禁止类时）
（以上皆无）     → 提示级
```

取数命令（PowerShell）：
```powershell
Select-String -Path 'D:\Seed\my-rules\rules\*.md' -Pattern '绝对禁止|严禁|禁止|不得|不要|不能|不许|必须' | Group-Object Filename | Select-Object Name, Count
```

| 档位 | 判定 | 规则 |
|---|---|---|
| **绝对禁止级** | 正文含「绝对禁止」/「严禁」 | `no-git-write`、`import-guard`、`ts-expect-error` |
| **禁止级** | 正文含「禁止/不得/不要/不能/不许」 | `global-ask-before-acting`、`code-style`、`how-i-must-reason`、`rules-single-source`、`powershell-file-encoding`、`docs-convention`、`plain-language-to-user`、`skill-assets-convention`、`vitest-queued-alternative` |
| **必须级** | 正文含「必须」（无禁止类） | `landing-sweep`、`poll-deferred-at-start` |

**为什么 no-git-write 是绝对禁止级**（2026-10-09 修正）：正文含「**绝对禁止**的行为」+ 多处「禁止」——措辞是最高档；此前按来源类型误归「项目约定-低中」是错的。约束力只看措辞，不看来源。

## 2. 层级规范

（spec §3.2，判据：同一含义用同一标记）

| 层级 | 装什么 | 备注 |
|---|---|---|
| `#` | 规则名 = 一句话可执行判据 | 每条规则恰好一个 |
| `##` | 大节：核心约束 / 例外 / 豁免 / 反例 | **核心判据必须由 H2 或列表承载** |
| `###` | 小节：编号规则、分类、表格标题 | 不用 emoji 装饰 |
| `**加粗**` | **仅句内强调** | ⚠️ 不承担结构职责 |

**标记职责（2026-10-08 修正）**：`##` 管分节结构，`**加粗**` 管句内强调——两者**不冲突**。实测 14 条规则：`global-ask-before-acting` 的 `**先沟通清楚…**` 是总结句（`##` 分节照常存在），不是「加粗承载核心判据」。因此 D2 **不**把「首段裸加粗」当违规。

**依据**（B3）：这**不是官方要求**（官方只管 SKILL.md 不管 rules），依据是自定义规则 `rules-single-source`「一个用途一个地方」的同构逻辑 —— 内容不许两处说，标记也不许两处用。

## 3. 三检验（定义「可删」）

（spec §4.1，本 skill 的核心判据，替代「凭感觉精简」）

一条文字是「冗余措辞」、可删，**当且仅当删掉它以下三条全部不变**：

| # | 判据 | 检验方法 | 能否脚本化 |
|---|---|---|---|
| 1 | **判据本身不变** | 删后「什么时候该做什么」的核心句一字未变 | ❌ 需 AI 逐条判断 |
| 2 | **边界例子不变** | `✅正例`/`❌反例` 都还在，覆盖场景没少 | ❌ 需 AI 逐条判断 |
| 3 | **引用关系不变** | 指向其它规则的文件名（`no-git-write` 等跨规则钩子）没被删 | ✅ 可脚本查 |

**三条全过 → 可删。任一不过 → 属核心内容，agent 不得自行删除。**

## 4. 评分维度（硬性四维 + D4 参考）

（spec §6.1；硬性四维 D1/D2/D3/D5 各 0–20 分，**总分 80**；D4 是参考维度，**不计入总分**。用户裁决 2026-10-08：体积是「说清楚要多大」的自然结果，非质量硬指标，只参考）

| # | 维度 | 判定规则 | 分值 |
|---|---|---|---|
| D1 | **头部规范** | 来源行三字段齐全（**来源类型 / 日期 / 落地**，见 spec §3.1 / `assets/rule-template.md`）+ 来源类型在枚举内 + 日期格式合法 = 20；缺任一必填字段 −10；来源行错位在文末 −5 | 20 |
| D2 | **层级规范** | H1 唯一 + H3 无 emoji 装饰 = 20；每违一处 −5。**`**加粗**` 是句内强调，不参与扣分**（`#` 管分节、`**` 管强调，不冲突） | 20 |
| D3 | **来源精简** | 来源行 ≤ 2 渲染行（见 spec §3.1 / `assets/rule-template.md`）且无用户原话引用 = 20；每多 1 渲染行 −3；含原话引用 −5 | 20 |
| D5 | **引用完整** | 跨规则指针指向的文件都存在（脚本能查）= 20；每个失效指针 −5。**引用识别规则**：只认「rules 目录内规则名（带/不带 .md）」+「纯文件名 .md 引用」；排除带路径分隔符、文档路径前缀（docs/specs/plans/handoffs/.session/assets/references/scripts）、`xxx-` 占位、`SKILL`/`README`——防把命名示例当失效指针 | 20 |
| D4 | **体积健康**（参考） | H1 是判据 = 20（参考值）；目录式标题 = 0；超单条基线 ×1.5 → 提示需冗余审查。**不计入 total**，只输出参考 | — |

## 5. D4 体积维度与健康分级

### 5.1 D4 体积维度（B2 的落地：秤，不是栏杆；**参考维度，不计入总分**）

**明确不设总量上限。** 规则随场景增多而长大是正常的（用户裁决：说清楚一件事需要多大就该多大，体积不是质量硬指标）。D4 只查两件可判定的事：

| 检查项 | 得分逻辑 |
|---|---|
| **单条是否有可执行判据**（H1 是判据不是主题名） | 是 = 20（参考值）；是「笔记」「规范」「说明」等目录式标题 = 0 |
| **超预算时是否触发过废话审查** | 体积超基线 ×1.5 时，报告里必须有「本次新增部分的冗余审查」小节（脚本生成提示，作为 §5.2 第 6 步的人工检查点） |

### 5.2 健康分级

（spec §6.3；按 80 分制同比例换算：原 90/70 阈值 × 0.8）

| 总分 | 级别 | 含义 |
|---|---|---|
| 72–80 | 健康 | 达标 |
| 56–71 | 预警 | 有可清理项，不紧急 |
| < 56 | 超标 | **触发一次废话审查**（不是强制砍） |

⚠️ **分级只用于提示，不构成「必须优化到某分」的目标**。一条 60 分但每条判据都很硬的规则，优于一条 78 分但判据模糊的规则。

## 6. 基线口径与取数命令

### 6.1 基线口径

（spec §6.2）**基线**（2026-10-08 实测，总 673 行 / 22283 字符）：单条行数基线 = 全库中位数 ≈ 25 行；总量基线 = 673 行。**基线随每次优化后重取**（不是固定常量），记在脚本输出的 JSON 里，便于对比。

### 6.2 基线取数命令

（spec §7.1，供读者复算）

```powershell
Get-ChildItem -Path 'D:\Seed\my-rules\rules' -Filter *.md |
  ForEach-Object { '{0,-32} {1,5} lines {2,7} chars' -f $_.Name, (Get-Content -LiteralPath $_.FullName).Count, (Get-Content -LiteralPath $_.FullName -Raw).Length }
```

## 7. 实现决策（D4 脚本化边界）

D4 是参考维度（**不计入 total**）：脚本输出 `d4: { score, ref }`。`score` = H1 是否判据式（判据式 20 / 目录式 0）；`ref` = 是否超单条基线 ×1.5（≈37 行），为 true 时在 findings 生成「体积超基线，需冗余审查」提示（不计分）。「冗余审查是否做了」作为 §5.2 第 6 步的人工流程检查点（含在「人工过硬闸门」里）。

## 8. 诚实边界

（抄自 spec §4.3「公式的诚实边界」）

公式防的是「AI 执行层越权」。它**防不了**「规则本身是假的」——没有任何判据能证明「用户当场说过」，来源行是自称的章。这靠 `global-ask-before-acting` 的授权流程兜底，不靠评分。
