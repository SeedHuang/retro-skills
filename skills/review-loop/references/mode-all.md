# 第三段：文档断言 → 代码取证

> `all` 模式**必跑**；`md` 模式在「清单里同时有文档和代码改动」时也跑；`code` 模式**用不上**（纯代码没有「文档断言」可对账）。纯文档范围下本段空转跳过。

## 为什么需要这一段

前两段是**并排**的：OCR 看代码、multi-lens-review 看文档，两边各自成立但互不知情。漂移就发生在两段之间的缝里——

> 文档写「两个参数」，代码只读一个。**两段单独审都是全绿，代码实际跑不通文档说的用法。**

本段就是把段二说的每句话，拿到段一的代码事实里验一遍。

## 怎么跑

### 1 列出文档里的断言

只取**可验证的**那一类——凡是「X 有 Y 属性」「X 依赖 Z」「X 的产出是 W」这种有对应代码的句子。散文、理由、背景说明跳过（它们没有「对应代码」这回事）。

来源：
- 产物的模板文件里写的栏位/字段定义
- spec / SKILL.md 里的验收项
- 命令示例里的参数

### 2 逐条找代码对应物

| 断言形态 | 去找什么 |
|---|---|
| 「有X 这个参数/字段」 | 代码里的参数定义、解析逻辑 |
| 「产出是 W 形态」 | 代码里生成 W 的那个函数 |
| 「提取规则是 R」 | 下游实际执行 R 的解析代码 |
| 「有守卫/校验 G」 | 守卫测试的断言 |

### 3 验断言

- **找到对应物** → 比对：字段名一致吗？数量一致吗？必填还是可选？格式一致吗？
- **找不到对应物** → **这条更可疑**，不是「文档写错了」而是「文档承诺了代码没实现」。先当成问题记下来，不要因为「可能是文档过期」就放过。
- **判定要取证**，不能凭印象。取证命令写出来（grep 的关键词、读的文件位置）。

### 4 反向再扫一遍

正向是「文档说的有没有代码」。反向是「代码有的文档说不说」——**同一件事的两种漏法**：

```powershell
# 已有的守卫测试名（代码里写死的硬约束）
Select-String -Path <测试文件> -Pattern "test\('"
```

代码里已经写成断言的东西，文档里没有对应说法 = 文档缺一条。**这类漂移最容易漏，因为它是静默的**——测试照样绿，只是文档没跟上。

**实测省力办法（2026-10-08 第 6 轮）**：反向扫不用人肉对，先让**已有的守卫自己报**——凡是「文档 ↔ 代码」类的守卫，本质上就是反向扫描器：
- 行号引用守卫生效时，它会打出「**那一行附近没有它引用的代码**」——那就是一条「文档说 A、代码是 B」；
- 命令参数守卫生效时，它会打出「文档里出现 `--xxx`，但代码没有真正解析它」。

**先跑 `node --test`（或该仓的测试命令），把它的失败当成反向扫的起点**，比从零读两个文件对得快，也比人眼可靠。

**别把守卫条数写死在本文件里**——那个数会随守卫增减而漂移（本仓 `lessons.test.mjs` 的守卫从 5 条长到 9 条就是活例）。要现取：

```powershell
Select-String -Path <测试文件> -Pattern "^test\('守卫"
```

## 什么算问题

| 情况 | 判定 |
|---|---|
| 文档说 A，代码做B | **矛盾**（P0）——改哪边要看哪个是意图，但必须改一处，不许两处并存 |
| 文档说了，代码没实现 | **盲点**（P1）——承诺了没兑现 |
| 代码硬编码了，文档没说 | **盲点**（P1）——文档缺一条，行为可能对但读者不知道 |
| 措辞不准但行为对 | **优化**（P2）——记录，不阻塞 |
