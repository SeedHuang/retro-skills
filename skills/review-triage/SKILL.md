# review-triage：审查前分流，排除无风险文件

## 这个技能干什么

把一批改动分成**三档**：可直接提交 / 必须 review / 不提交。目的：只把「机器判不了的」送审，省 token。

**核心判据一句话：一个文件免审的充要条件是——它的对错判据「完全可机械执行」（错了机器自己报），且本次实跑结果全过。**

## 无风险闸门（免审的唯一入口）

对每个改动问一句：**「我怎么知道它错了？」**

- 答得出一条**可执行命令**（不是「我核对了」）→ 跑它 → 全过 → 潜在免审
- 答不出 / 答案是「我读了一遍」「看起来对」「语义等价」「摘抄自原文」→ **必审**

| 改动类型 | 判据命令（示例） | 免审条件 |
|---|---|---|
| 引用写法（跨技能路径/自引用前缀） | `npm run check` 的守卫段 | 0 findings |
| markdown 结构（围栏/表格列数） | `npm run check` 的 markdown 段 | 0 findings |
| 勾选/状态位 | `git diff` 字面核对 | diff 只含 `- [ ]`→`- [x]`（⚠️ **只验形态**：确认改动没夹带别的内容；「勾选所声称的工作真做了没有」不在本技能范围——那是执行者与验收方的责任，不是提交安全性问题） |
| 计数/数字 | 取数命令可复算 | 数字一致 |

## 必审特征（命中任一条 = 必审，不管跑得多绿）

| 特征 | 为什么机器判不了 |
|---|---|
| 新增代码 | 实跑绿只证明「检查自己跑得通」，不证明「判据判得对」（行数多只是提醒严重度 —— **任何新增代码都必审，不是「超 100 行才审」**） |
| 摘要 / 压缩 / 改写（长内容压成短句） | 压缩得准不准只有人能读 |
| 执行动作替换（命令 A → 命令 B） | 语义迁移要人确认 |
| 流程 / 纪律措辞（「什么时候必须做什么」） | 松一分就会被跳过 |
| 跨文件一致性断言（「三处对齐」） | 对齐靠人读，不靠机器 |
| 删除残留行 | 判据是「对比另存完整记录」——「完整」由谁判？给不出可执行命令 |
| 测试断言跟随模板 | 判据是「断言改的是被模板决定的字符串」——「被模板决定」是判断，不是命令 |

## 三档输出结构

```
✅ 可直接提交（无风险 + 证据）
  <文件>：<改动> —<判据命令> <实跑结果>

⚠️ 必须 review（判据：机器判不了）
  <文件>：<改动> —<为什么>

❌ 不提交（状态问题，不是风险问题）
  <文件>：<为什么>
```

## 硬约束（违反即不合格）

1. **「无风险」≠「低风险」**。无风险 = 判据完全机械、错了机器自己报；低风险 = 主观成分小。**低风险不许进免审档。** 两个词不许混用——汇报时只用「无风险」或「必须 review」。
2. **免审必须报「命令名 + 实跑结果」**。报不出 = 必审。「我核对了」「我跑过」「看起来对」「语义等价」「摘抄自原文」**都不是命令名**。
3. **免审清单必须逐条列给人看**，带证据，不许默默处理。
4. **互为依据的改动归同一笔，共进共退**：同一处计数/配置在两个文件各写一次 → 归同一笔，不许拆开单独提。**且同一笔里任一文件命中必审特征 → 整笔必审**——不能「数字那个免审、摘要那个必审」拆开处理（数字的成立依赖摘要的成立）。
5. **未跟踪 ≠ 免审**，也 ≠ 需要 review。按判据分，状态不是判据。
6. **必须 review 的清单不许为空时跳过理由**：每个必审文件都要写清「为什么机器判不了」。

## 常见错误

| 借口 | 现实 |
|---|---|
| 「内容摘抄自规则正文」 | 摘抄压缩是主观，压缩得准不准只有人能读 |
| 「语义等价」 | 等价是 agent 的结论，不是机器判据——尤其执行动作被替换时 |
| 「已实跑验证过」 | 实跑绿只证明检查自己跑得通，不证明判据对 |
| 「这是历史记录」 | 历史记录 ≠ 免审。记录「过期状态」的文档该进「不提交」档 |
| 「文件很小」 | 1 行改执行动作比 200 行加注释更需要人看 |

## 触发与边界

**固定触发**：用户说「帮我排除不用 review 的文件」「哪些可以直接提交」「审之前先分一下」，或提交/送审前主动分流。**不覆盖**：真正去审（走 `review-loop` 技能）。

**接缝（与 `review-loop`）**：**调用时点** = `review-loop` 分支前置之后、OCR 前置工程检测之前（先分流决定审什么，再跑闸门与 OCR）。本技能只做**分流**——实际提交 / 合并由用户决定（本技能不掌握提交动作）。
- 被判定「可直接提交」的文件**若已提交**：下次 review 取**默认范围「工作区未提交」**时不含它 → 不重复审。**⚠️ 但**若显式取「最近 N 次 commit」或某个 hash、且区间**覆盖**了该 commit，OCR 仍会审到它 —— 那算重复审。
- **若未提交**：它留在工作区 → 下次取默认范围时**必然重审**。这就是「不提交」的代价，分流时要写清。
