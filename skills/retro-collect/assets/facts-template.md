# 事实包模板（逐字使用）

> 本文件是**事实包结构的权威定义方**。`retro-collect/SKILL.md` 只指向这里，不复制。
> **必须逐字使用**——自创结构不用本模板，是 `retro-collect` 明确列出的常见错误。

## 落点

`<KB>/projects/<项目标识>/<日期>-<sid>-<摘要>/facts.md`

（**一 session 一目录**——与同目录 `userwords.md` / `moments.md` 并列，analyze 后加 `retro.md`。项目标识取自仓库目录名，入库前须清洗：去 `|`、换行、路径分隔符、控制字符；空白折为 `-`。）

**日期 / `sid` / 摘要的定法以 `SKILL.md`「第 0 步：定 session」为权威定义方**，此处不复制——防第二份。要点：日期取 **session 起始日期**（**禁用系统时间**）；`sid` = 首句逐字原文的 sha256 前 8 位；目录**永不改名**。

## 模板

```markdown
# 事实包：<session/阶段标识>

- 范围：<起止锚点>
- 生成：<日期>｜生成者：<agent/人>
- session：<sid>｜首句：<逐字原文>｜memory id：<可选，拿不到写 —>｜message 范围：<首>..<尾>

## 1 时间线锚点
| 时刻 | 事件 | 来源（文件 mtime / git log / 命令输出） |
|---|---|---|

> **⚠️ 填了「时刻」就必须同时声明抽样率**（2026-10-07 起，规则见 `docs/superpowers/specs/2026-10-07-moment-context-and-timeline-design.md` §3/§4.3）：时刻来自 `~\.trae-cn\memory\...session_memory_*.jsonl` 的 `message_summary_time`，**它的锚点数远少于原话条数**（实测 10-01 是 10 个锚点 vs 106 条原话 ≈ 9.4%）。**不声明的话，读者会把抽样当全覆盖。**声明写法：
>
> **时刻来源**：`<jsonl 路径>` 的 `message_summary_time`｜**覆盖率**：本 session N 个锚点、用户原话 M 条 → **抽样 x%**；**不代表每条原话都有时刻**｜**取数时点**：<日期>（锚点数会随时间补齐，重跑须重取）。
>
> **锚点全缺时**（memory 无该 session 文件）：只写日期 + 一行「本 session 无时刻锚点，**原因**：<实测结论>」。**不编造时刻，也不留空。**
>
> **间隔与总跨度要显式算出来**（如 `15:06:56 → 16:07:08 间隔 1h00m12s`、`总跨度 1h46m58s`）——**这是「哪一步卡最久」唯一能回答的地方**。

## 2 计数
| 项 | 值 | 来源 |
|---|---|---|
| 本次 session 情绪点数 | N | 同目录 `moments.md`（本 session） |
| 其中未结案 | M | 同目录 `moments.md` |

## 3 异常事件
| # | 现象 | 证据 |
|---|---|---|

## 4 情绪点
| # | moment ID | 极性 | 时间 | 触发原话（引用） | 状态 | 来源 |
|---|---|---|---|---|---|---|

> 「触发原话」取同目录 `moments.md` 里该条目的**触发句**——证据栏的**最后一行引用**（`- 证据（原话）：` 单句形态，或 `- 证据（对话原文，紧邻上文→触发句）：` 多行形态，两种栏标题并存，见下）。
> **抄内容时必须去掉标签前缀**：多行形态下行首的 `[触发] ` / `[上文] ` 是**机器标记不是原话**，本列要的是**逐字原话**（与 §5 证据清单、与 `userwords.md` 的原话列口径一致）。
> **⚠️ 两种栏标题并存**（2026-10-07 起）：不传 `--evidence-up` 的记录是单句旧形态，传了的是多行新形态。**按「末行定位 + 去标签」取，不要按固定行号或标题字面量。**

## 5 证据清单

## 6 未取得的数据

## 7 声明
本文件不含判断、不含方案、不含优先级。分析见同目录 `retro.md`。
```

## 节号形态（供下游引用）

事实包各节的编号是 `## 1 时间线锚点` / `## 2 计数` / `## 3 异常事件` / `## 4 情绪点` 这类**数字节号**；下游引用某一行时写作 `§<节号>-<行号>`（如 `§3-1` = 「3 异常事件」表中的第 1 行，`§4-2` = 「4 情绪点」第 2 行）。

**`retro-collect` 是该形态的权威定义方**；`retro-analyze` 只引用不重定义。

## 七节缺一即不合格

| 节 | 缺了会怎样 |
|---|---|
| 1 时间线锚点 | 没有过程，无法判断节奏 |
| 2 计数 | 没有分母，结论无法定权重 |
| 3 异常事件 | 复盘对象缺失 |
| 4 情绪点 | 画像与规则管线失去输入 |
| 5 证据清单 | 结论无法回溯 |
| 6 未取得的数据 | **空着等于伪装完整**——拿不到的必须诚实列出并说明为什么 |
| 7 声明 | 边界不清，后面会被读成结论 |

## 硬约束（与 SKILL.md 同步，不在此重复论证）

1. **只写事实**：不写判断、不写方案、不写优先级
2. **每条事实必须带来源**，且来源只能是：本次实跑的命令输出 / 文件直读（路径 + 行号或 hash）/ 对话原文（仅用于情绪点）
3. **原文一律放进引用块或代码块**——这样「只写事实」的检查只需扫非引用块，不需豁免条款
