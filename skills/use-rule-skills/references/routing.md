# 入口路由：意图判定

> 口径来源：spec §2。入口第一步必做——先判意图，再走对应路径。

| 调用形态 | 判定 |
|---|---|
| 显式「新建 / 我要建 rule」 | 新建 |
| 带路径 /「帮我优化这个 rule」 | 优化（路径指向 `rules/<name>.md`） |
| 从既有规则拆出独立部分（「把 X 拆出来 / 拆分这个 rule」） | **拆分**（源规则在 `rules/<name>.md`，拆出部分按新建处理） |
| 裸调用（什么都没说） | **默认新建** |

- 判定为**新建** → 走新建路径（见 `flows.md` §四 新建路径流程）。
- 判定为**优化** → 源规则在 `rules/<name>.md`，走优化路径（见 `flows.md` §五 优化路径流程）。
- 判定为**拆分** → 源规则在 `rules/<name>.md`，走拆分路径（见 `flows.md` §六 拆分路径流程）——拆出部分按新建处理（从需求四要素重新起草，受 rule-writer「禁止搬运」硬闸门约束），落地同时写新 rule + 改旧 rule。
