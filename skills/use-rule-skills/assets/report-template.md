## 三、查看（按输入形态，用 open-view 脚本打开）

**通道**：调用 `scripts/open-view.mjs` 脚本打开（`preview` 开草稿 / `diff` 开对比）——脚本内部固定用 `trae-cn` 命令，已实测；**不要**现场拼命令、**不要**用任何链接协议（`computer://` 等实测不可用）。命令由脚本发出，报告文本附路径文字作备份。

**出报告时**：按形态用脚本打开一次（打开好窗口给你直接看）；同时报告里给「可点击按钮」——用户点按钮 = 你收到选择后**再跑一次脚本**打开对应窗口：

| 形态 | 打开什么 | 脚本命令 |
|---|---|---|
| **新建**（纯新 rule，无改前） | 只开草稿 | `node scripts/open-view.mjs preview "<草稿路径>"` |
| **优化**（修原 rule） | 只开 diff（源 vs 草稿） | `node scripts/open-view.mjs diff "<源路径>" "<草稿路径>"` |
| **拆分**（从源拆出） | 只开 diff（源 vs 草稿）——diff 窗口并排已含草稿全文，不用再单独开草稿 | 同优化 |

**可点击按钮（AskUserQuestion）**：报告末尾给「查看草稿」「查看 diff」两个按钮，各自触发脚本：
- 查看草稿 → `node scripts/open-view.mjs preview "<草稿路径>"`
- 查看 diff → `node scripts/open-view.mjs diff "<源路径>" "<草稿路径>"`

**循环规则**：用户每次点完按钮、agent 执行完脚本后，**立即再弹一组按钮**（查看草稿 / 查看 diff / 采纳落地），直到用户选「采纳落地」结束——用户可在草稿 / diff / 落地之间来回。

**按钮是快捷入口，不是唯一出口**：用户随时可跳过按钮直接对话（选项卡片自带「其他」自由输入）；「采纳落地」只结束流程，不结束对话——落地后仍可继续讨论。

- 新建：草稿已开 → 路径：`<草稿绝对路径>`
- 优化/拆分：diff 已开（源 vs 草稿并排）→ 源：`<源路径>`；草稿：`<草稿路径>`

**设计要点**（出报告时对照执行）：

- **涨/掉都列**，不藏负变化（某项下降要明示）。

- **数字必须实测**（inspector 跑出来的真数，不是估算）；不附取数命令（报告是摘要，不是操作手册）。
