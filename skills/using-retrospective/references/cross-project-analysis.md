# 跨项目分析（L4-1，独立子代理）

> 触发：手动（用户说「跨项目分析一下 / 看看跨项目模式」）或里程碑收口建议且信号满足。
> 信号：`lessons stats` 显示 **项目 ≥ 2 且 条目 ≥ 20**。不满足 → 拒绝并告知差距，不硬跑。

## 为什么用独立子代理

主上下文带着当次任务的立场；跨项目模式要从全部账本里"往外看"。独立子代理只拿数据与指令，不带当次会话的偏见——与 multi-lens 飞轮、evolving-skills 步 4 同一套手法。

## 步骤

1. **前置校验**：KB `resolve` 通过；`lessons stats` 显示 项目 ≥ 2 且 条目 ≥ 20。不满足 → 停，报差距。
2. **汇总输入**：三区账本路径清单——`projects\<项目>\ledger.md` 全部、`skills\<技能>\ledger.md` 全部、`universal\ledger.md`（及 universal 下既有分析报告，供对比上一轮）。
3. **Task 起独立子代理**，指令模板见下；产出跨项目模式报告。
4. **落盘**：报告写 `<KB>\universal\<日期>-cross-project-analysis.md`（日期 = 分析当天）。
5. **汇报与裁决**：向用户报告要点 + 候选教训清单；用户点头 → 走正常复盘流程（retro-analyze → institutionalize / evolving-skills）把候选教训入账。

## 子代理指令模板

```
你是跨项目复盘分析员。读取以下账本（每行一条教训，列含 问题/根因/维度/修复/状态）：
<账本路径清单>

任务：
1. 找跨项目重复出现的模式——同构问题或同构根因出现在 ≥ 2 个不同归属；
2. 找共性根因——不同条目指向同一深层原因；
3. 指出维度薄弱面——哪个维度条目最少、open 积压最多；
4. 产出「建议立为通用教训的候选清单」：每条 = 模式描述 + 证据条目 ID 列表 + 建议归属（universal）。

约束：
- 只基于账本内容，不引入外部假设；
- 每个结论必须附证据条目 ID；
- 输出 Markdown 报告；报告不是 ledger 条目，不写账。
```

## 边界

- 报告落 `universal\<日期>-cross-project-analysis.md`，**不进 ledger 统一表**（分析产物 ≠ 教训条目）；
- 分析过程**不改账本**（KB 写纪律照旧：写前查 `.migrating` 锁，本次只新增报告这一个文件）；
- 报告中的候选教训**未经用户裁决前不自动入账**。
