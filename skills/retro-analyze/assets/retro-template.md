# 复盘模板 + 账本条目格式（逐字使用）

> 本文件是**复盘文件与账本条目结构的权威定义方**。`retro-analyze/SKILL.md` 只指向这里，不复制。
> **必须逐字使用**——自创结构不用本模板，是本技能明列的常见错误。

## 落点

1. 复盘文件：同 session 目录内的 `retro.md`（= `<KB>/projects/<项目标识>/<日期>-<sid>-<摘要>/retro.md`）
2. 账本条目：**追加行**到**项目根**的 `ledger.md`（`<KB>/projects/<项目标识>/ledger.md`，**不在** session 目录内；状态**先写 `open`**，落地成功后由 `retro-institutionalize` 改为 `landed`）

**写入顺序固定「先条目 → 后落地 → 再改状态」**（防中断后重跑重复落规则）。

## 复盘文件模板

```markdown
# 复盘：<session/阶段标识>

- 事实包：<路径>

## 1 问题清单
| # | 事实包条号 | 问题 | 维度 | 影响范围 | 可逆性 | 隐蔽度 | 根因 | 方案 | 优先级 |
|---|---|---|---|---|---|---|---|---|---|

## 2 归置结果
| 条目 ID | 教训 | 走 Step 几 | 落点（载体 + 路径）|
|---|---|---|---|

## 3 附录：规则裁决

## 4 未决与待验证
```

**每个问题在表格下方跟一段人话说明**（见 SKILL.md「说人话」硬规则），说明里补 ⚠️ 可选字段：**可复现性**（稳定/偶发/不可，未知可空）。

## 账本条目行格式

```markdown
| ID | 日期 | 归属 | 来源 | 问题 | 根因 | 维度 | 修复 | 载体 | 状态 |
|---|---|---|---|---|---|---|---|---|---|
| L-NNN | <日期> | <标识> | 复盘 | <问题> | <根因> | <维度> | <方案> | 未定 | open |
```

- **条目 ID**：全库统一 `L-NNN`（三位连续）。取数 = grep 全库 ledger 表行 `| L-0` 与 `L-RS-` 取最大 N + 1
- **状态流转**：`open` →（落地成功）→ `landed(→<载体>)`；落地失败回改 `open`；作废改 `closed(理由)`
- **条目去重**：追加前先在目标 `ledger.md` 查是否有同一条教训——**有则复用该 ID，不重复追加**（状态保持或置 `open`）
- **转义规则**：自由文本栏位内 `|` 写作 `\|`，换行写作 `<br>`。不转义会破整份表

## 列口径

| 栏 | 含义 | 取值 |
|---|---|---|
| **维度** | 改进面 | 健壮度 / 产品体验 / 协作体验 / 性能 / 安全（五选一） |
| **影响范围** | 后果波及多广 | 单点 / 本项目 / 跨项目 / 全局 |
| **可逆性** | 能否回退 | 可逆 / 不可逆 |
| **隐蔽度** | 失败是否可见 | 显式 / 静默（**静默更危险**——会潜伏） |
| 根因 | 为什么会这样 | 区别于现象：现象是「重复落规则」，根因是「写规则与写记录的顺序未定义」 |
| 事实量 vs 判断量 | — | 事实量（复发次数 / 耗时 / token / 讨论轮数）= **可测**；判断量（严重度 / 影响范围 / 可逆性 / 隐蔽度）= **判断** |

**「是否普遍」列已删除**——由「影响范围」取代（同一信息的第二份表述）。

## 硬约束（四条，缺一即不合格）

1. **第 2 列「事实包条号」必填**。写不出条号 → 这不是基于事实的问题，删掉它，或先回 `retro-collect` 补事实
2. **「优先级」必须带判据**，不得只给「P1」。判据口径：直接后果 / 时间代价 / token 代价（注明估算）/ 触发频率。示例：`P1 — 后果不可逆 + 触发频率高（本次 3 次）`
3. **问题必答清单缺一不可**：① 谁受影响、什么场景触发（人话一句）② 后果 + 量化 ③ 根因（**标注：事实 or 推断**）④ 怎么修（可执行一句）⑤ 怎么验证修好了
4. **每个问题下必须跟一段人话说明**——复盘是写给用户看的
